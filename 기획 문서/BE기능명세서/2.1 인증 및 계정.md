## 2.1 인증 및 계정

### BE-AUTH-001 · 인증 상태 확인

서비스 접속 시 사용자의 로그인 상태를 확인한다.

도메인 | Auth
관련 요구사항 | REQ-001, REQ-002
관련 화면 | 로그인 화면, 메인 화면 진입

입력 | `accessToken` 또는 `sessionId`
처리 | 토큰 또는 세션을 검증하고, 유효하면 사용자 기본 정보를 반환한다.
출력 | `isAuthenticated`, `userProfile` 또는 `null`

DB 영향 | `AuthSession`, `User` 조회
상태 변화 | 비로그인 유지 또는 로그인 유지
권한 | 선택적 인증
오류 | 만료된 토큰, 유효하지 않은 세션
우선순위 | 상

비고 | 로그인 화면 UI 표시는 FE 책임이다.

### BE-AUTH-002 · Google ID 토큰 검증

프론트엔드 Google SDK가 받은 ID 토큰이 유효한 Google 로그인 결과인지 검증한다.

도메인 | Auth
관련 요구사항 | REQ-002
관련 화면 | Google로 계속하기 버튼

입력 | `googleIdToken`
처리 | Google 공개 키 또는 검증 라이브러리로 토큰 서명, 만료 시간, audience, issuer를 검증한다.
출력 | `verifiedGooglePayload`

DB 영향 | 없음
상태 변화 | 비로그인 → Google 토큰 검증 중
권한 | 비로그인 허용
오류 | 만료된 ID 토큰, 잘못된 audience, 서명 검증 실패, `INVALID_GOOGLE_ID_TOKEN`
우선순위 | 상

비고 | FE는 Google SDK로 ID 토큰을 얻으며 OAuth URL·콜백은 사용하지 않는다.

### BE-AUTH-003 · Google 사용자 정보 추출

검증된 Google ID 토큰에서 FlowKit 사용자 생성·로그인에 필요한 식별 정보를 추출한다.

도메인 | Auth
관련 요구사항 | REQ-002
관련 화면 | Google 로그인 완료

입력 | `verifiedGooglePayload`
처리 | `sub`, `email`, `name`, `picture`를 추출하고 필수값 누락 여부를 확인한다.
출력 | `googleUserId`, `email`, `name`, `profileImage`

DB 영향 | 없음
상태 변화 | Google 토큰 검증 완료 → 사용자 정보 확인
권한 | Google 토큰 검증 완료 필요
오류 | 필수 claim 누락, 이메일 없음
우선순위 | 상

비고 | MVP 포함

### BE-AUTH-004 · 사용자 조회 또는 신규 생성

검증된 Google 사용자 정보를 기준으로 기존 사용자를 찾거나 새 사용자를 생성한다.

도메인 | Auth, User
관련 요구사항 | REQ-002
관련 화면 | Google 로그인 완료

입력 | `googleUserId`, `email`, `name`, `profileImage`
처리 | Google 사용자 ID 또는 이메일로 사용자를 조회하고, 없으면 새 사용자를 생성한다.
출력 | `userId`, `isNewUser`, `userProfile`

DB 영향 | `User` 조회 또는 생성
상태 변화 | 미가입 → 가입 완료 가능
권한 | Google 토큰 검증 완료 필요
오류 | 이메일 중복, 사용자 생성 실패
우선순위 | 상

비고 | MVP 포함

### BE-AUTH-005 · 서비스 인증 토큰 발급

로그인 성공 후 서비스에서 사용할 access token과 refresh token을 발급한다.

도메인 | Auth
관련 요구사항 | REQ-002
관련 화면 | 메인 화면 진입

입력 | `userId`, `deviceInfo`
처리 | 사용자 상태를 확인하고 토큰을 발급한 뒤 세션을 저장한다.
출력 | `accessToken`, `refreshToken`, `expiresAt`

DB 영향 | `AuthSession` 생성
상태 변화 | 비로그인 → 로그인
권한 | 인증된 `userId` 필요
오류 | 비활성 사용자, 토큰 발급 실패
우선순위 | 상

### BE-AUTH-006 · 인증 토큰 재발급

access token 만료 시 refresh token으로 새 인증 토큰을 발급한다.

도메인 | Auth
관련 요구사항 | REQ-002
관련 화면 | 메인 화면 유지

입력 | `refreshToken`
처리 | refresh token과 세션 상태를 검증한 뒤 새 access token·refresh token을 발급하고, 기존 refresh token은 폐기한다.
출력 | `accessToken`, `refreshToken`, `expiresAt`

DB 영향 | `AuthSession` 조회·수정, refresh token 교체
상태 변화 | 로그인 유지, refresh token 회전
권한 | 유효한 refresh token 필요
오류 | refresh token 만료, 세션 없음, 이미 사용된 refresh token, 토큰 탈취 의심
우선순위 | 중

비고 | refresh token 회전 적용

### BE-AUTH-007 · 현재 로그인 사용자 조회

로그인된 사용자의 최소 프로필 정보를 조회한다.

도메인 | Auth, User
관련 요구사항 | REQ-002, REQ-058
관련 화면 | 메인 화면, 프로필 영역

입력 | `accessToken` 또는 `userId`
처리 | 인증된 사용자를 기준으로 메인 UI에 필요한 사용자 정보를 조회한다.
출력 | `userId`, `name`, `email`, `profileImage`, `plan`

DB 영향 | `User` 조회
상태 변화 | 없음
권한 | 로그인 필요
오류 | 사용자 없음, 권한 없음
우선순위 | 상

비고 | 사용자 설정 화면의 상세 정보 조회와 구분한다.

### BE-AUTH-008 · 계정 기본 정보 수정

사용자의 이름, 이메일, 메모 등 기본 계정 정보를 수정한다.

도메인 | User
관련 요구사항 | REQ-059
관련 화면 | 사용자 정보 모달

입력 | `userId`, `name`, `email`, `memo`
처리 | 본인 소유 계정인지 확인하고 입력값을 검증한 뒤 정보를 수정한다.
출력 | `updatedUserProfile`

DB 영향 | `User` 수정
상태 변화 | 사용자 정보 변경
권한 | 로그인 필요, 본인만 가능
오류 | 잘못된 이메일 형식, 중복 이메일, 권한 없음
우선순위 | 중

비고 | 상세 설정 흐름은 2.10 사용자 설정과 연결한다.

### BE-AUTH-009 · 로그아웃 처리

사용자가 현재 인증 세션을 종료할 수 있게 한다.

도메인 | Auth
관련 요구사항 | REQ-003
관련 화면 | 프로필 메뉴 로그아웃

입력 | `accessToken` 또는 `sessionId`
처리 | 현재 세션을 만료 처리하고 refresh token을 무효화한다.
출력 | `logoutSuccess`

DB 영향 | `AuthSession` 수정
상태 변화 | 로그인 → 비로그인
권한 | 로그인 필요
오류 | 이미 만료된 세션, 세션 없음
우선순위 | 중

### BE-AUTH-010 · 인증 실패 응답 반환

인증 실패 상황을 프론트엔드에서 처리할 수 있도록 표준 오류 형식으로 반환한다.

도메인 | Auth, Error
관련 요구사항 | REQ-001, REQ-002, REQ-003, REQ-064
관련 화면 | 로그인 화면, 오류 배너

입력 | `requestContext`, `errorType`
처리 | 인증 오류 유형을 분류하고 표준 `errorCode`와 메시지를 생성한다.
출력 | `errorCode`, `message`, `detail`

DB 영향 | 없음
상태 변화 | 없음
권한 | 상황별
오류 | `UNAUTHORIZED`, `TOKEN_EXPIRED`, `SESSION_NOT_FOUND`, `INVALID_GOOGLE_ID_TOKEN`
우선순위 | 중

비고 | 공통 오류 모듈과 연동한다.
