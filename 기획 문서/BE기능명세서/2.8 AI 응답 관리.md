## 2.8 AI 응답 관리

### BE-AIRESP-001 · AI 응답 생성 입력 구성 및 요청

사용자가 메시지를 전송하면 userPrompt와, Context를 적용하지 않았으면 activeMessageFlow를, Context를 적용했으면 activeMessageFlow 대신 appliedContextSnapshot을 함께 써서 AI 응답 생성을 요청한다.

**도메인**
AIResponse, MessageBlock, ContextApply

**관련 요구사항**
REQ-013, REQ-046

**관련 화면**
메시지 전송 버튼, AI 응답 표시 영역

**입력**
userId, chatId, branchId, userPrompt, userMessageBlockId, appliedContextSnapshot

**처리**
채팅·브랜치 접근 권한과 사용자 메시지 블록을 검증한 뒤, BE-MSG-007로 activeMessageFlow를 조회한다. BE-CTXAPPLY-002에서 확정된 appliedContextSnapshot이 있으면 activeMessageFlow 대신 그것과 userPrompt를, 없으면 activeMessageFlow와 userPrompt를 그대로 AI 모델링 파트에 전달한다.

**출력**
aiResponseJobId, aiInputSnapshot(activeMessageFlow, appliedContextSnapshot, userPrompt), status

**DB 영향**
AIResponseJob 생성, MessageBlock 조회, MessageBlockVersion 조회

**상태 변화**
없음 → AI 응답 생성 요청 중

**권한**
로그인 필요, 채팅 소유자

**오류**
사용자 메시지 없음, 브랜치 없음, 메시지 흐름 조회 실패, Context snapshot 없음, 권한 없음, AI 요청 실패

**우선순위**
상

**비고**
Context 검증·snapshot 확정은 2.7. 사용자 메시지 저장은 BE-MSG-001. 답변 생성은 AI 모델링 파트 책임. 답변을 스트리밍으로 흘려보내는 경로(BE-AIRESP-007)는 이 요청 안에서 모델을 부르지 않고, 요청 처리와 답변 생성을 분리한다.

### BE-AIRESP-002 · AI 응답 결과 저장 연결

AI 모델링 파트가 생성한 답변을 assistant 메시지 블록으로 저장하도록 연결한다.

**도메인**
AIResponse, MessageBlock, Version

**관련 요구사항**
REQ-013

**관련 화면**
AI 응답 표시 영역

**입력**
userId, chatId, branchId, aiResponseJobId, aiGeneratedContent, modelInfo 선택값

**처리**
AI 응답 본문을 검증한 뒤 BE-MSG-001의 메시지 블록 생성 로직을 사용해 role=assistant인 MessageBlock과 최초 MessageBlockVersion을 생성한다. AIResponseJob 상태를 completed로 변경한다.

**출력**
aiMessageBlockId, versionId, content, createdAt, status

**DB 영향**
MessageBlock 생성, MessageBlockVersion 생성, AIResponseJob 수정

**상태 변화**
AI 응답 생성 요청 중 → AI 응답 저장 완료

**권한**
로그인 필요, 채팅 소유자

**오류**
응답 본문 없음, 메시지 블록 생성 실패, 버전 저장 실패, 작업 없음, 권한 없음

**우선순위**
상

**비고**
메시지 저장 구조는 2.4 메시지 블록 관리 정책을 따른다. 이 절차는 답변 전체가 한 번에 도착하는 경로를 기준으로 한다. 스트리밍 경로(BE-AIRESP-007)는 답변 블록을 생성 시작과 동시에(본문이 비어 있는 채로) 만들고, 조각이 도착할 때마다 그 블록의 본문을 채워간다.

### BE-AIRESP-003 · AI 답변 재생성 및 버전 추가

기존 AI 답변을 다시 생성하고, 같은 assistant 메시지 블록의 새 버전으로 추가한다.

**도메인**
AIResponse, MessageBlock, Version

**관련 요구사항**
REQ-049

**관련 화면**
답변 다시 시도 버튼

**입력**
userId, chatId, branchId, aiMessageBlockId

**처리**
대상 블록이 해당 브랜치의 role=assistant 블록인지 확인한다. 기존 AI 응답 생성 입력 스냅샷 또는 해당 답변 직전의 활성 메시지 흐름을 기준으로 AI 모델링 파트에 재생성을 요청하고, 생성된 답변을 새 MessageBlockVersion으로 저장한 뒤 currentVersionId로 설정한다.

**출력**
aiMessageBlockId, newVersionId, content, versionNo

**DB 영향**
AIResponseJob 생성, MessageBlockVersion 생성, MessageBlock 수정

**상태 변화**
기존 AI 답변 버전 → 새 AI 답변 버전 활성화

**권한**
로그인 필요, 채팅 소유자

**오류**
AI 답변 블록 없음, assistant 블록 아님, AI 요청 실패, 응답 없음, 버전 저장 실패, 권한 없음

**우선순위**
중

**비고**
새 MessageBlock을 만들지 않고 기존 AI 답변 블록의 버전으로 추가. 버전 목록 조회·활성 버전 변경은 BE-MSG-005/006 사용

### BE-AIRESP-007 · 답변 생성 실행과 스트리밍 중계

답변 생성을 요청을 처리하는 스레드가 아니라 별도로 돌리고, 화면이 붙어 글자 조각을 받아갈 수 있는 통로를 연다.

**도메인**
AIResponse, MessageBlock, Version

**관련 요구사항**
REQ-069

**관련 화면**
AI 응답 표시 영역

**입력**
userId, chatId, branchId, aiResponseJobId, aiInputSnapshot

**처리**
질문 블록과 본문이 비어 있는 답변 블록을 만들고 AIResponseJob 상태를 generating으로 두어, 요청에는 즉시 응답한다. 별도로 시작된 작업이 AI-ANSWER-005로 답변을 스트리밍 생성하며, 글자 조각이 도착할 때마다 통로에 붙은 화면들에 중계한다. 일정 시간 또는 일정 글자마다 지금까지의 본문을 답변 블록에 저장해, 화면이 새로고침해도 그 시점까지의 내용을 잃지 않게 한다. 생성이 끝나면 최종 본문을 확정하고 AIResponseJob 상태를 completed로, 실패하면 failed로 바꾼다. 도중에 합류한 화면에는 지금까지 쌓인 본문을 먼저 보내고 그 뒤부터 이어서 중계하며, 이미 끝난 작업에 합류하면 완료 상태만 알려준다.

**출력**
aiResponseJobId, status(즉시 응답), 이후 통로로: 글자 조각, 검색 근거 조각, 완료/오류 조각

**DB 영향**
MessageBlock 생성, MessageBlockVersion 생성·수정, AIResponseJob 생성·수정

**상태 변화**
없음 → 생성 중 → 완료 또는 실패

**권한**
로그인 필요, 채팅 소유자

**오류**
사용자 메시지 없음, 브랜치 없음, Context snapshot 없음, 권한 없음, AI 요청 실패, 응답 시간 초과

**우선순위**
상

**비고**
서버가 재시작되면 그 사이 generating으로 남은 작업은 메모리 중계가 사라져 다시는 끝나지 않는다. 서버 시작 시 이런 작업을 모두 failed로 정리한다. 재생성(BE-AIRESP-003)과 실패 재시도도 같은 절차를 쓴다.

### BE-AIRESP-008 · 답변 생성 중단

사용자가 생성 중인 답변을 멈추면, 그때까지 만들어진 본문을 남기고 생성을 그친다.

**도메인**
AIResponse, MessageBlock, Version

**관련 요구사항**
REQ-070

**관련 화면**
중단 버튼

**입력**
userId, chatId, branchId, aiResponseJobId

**처리**
작업이 이 사용자·채팅·브랜치 소유인지 확인한다. 아직 생성 중이면 중단을 요청하고, 진행 중이던 작업이 그 요청을 확인하는 대로 지금까지 만들어진 본문을 답변 블록에 확정하며 AIResponseJob 상태를 cancelled로, 답변 블록에도 중단됨 표시를 남긴다. 이미 끝난 작업에 중단을 요청하면 오류 없이 지금 상태를 그대로 돌려준다.

**출력**
aiMessageBlockId, content, status(cancelled)

**DB 영향**
AIResponseJob 수정, MessageBlockVersion 수정, MessageBlock 수정

**상태 변화**
생성 중 → 중단됨

**권한**
로그인 필요, 채팅 소유자

**오류**
작업 없음, 권한 없음

**우선순위**
중

**비고**
중단된 답변은 지우지 않지만, 다음 질문의 Context나 정제 대상, 브랜치 분기점으로는 쓸 수 없다(REQ-070). 서버 판단이 최종 기준이며, 화면의 버튼 숨김은 보조 수단이다.

### BE-AIRESP-009 · 진행 중인 답변에 다시 붙기

새로고침하거나 브랜치를 다시 열었을 때, 아직 생성 중인 답변이 있으면 화면이 그 작업의 통로를 다시 찾을 수 있게 한다.

**도메인**
AIResponse, MessageBlock

**관련 요구사항**
REQ-069

**관련 화면**
AI 응답 표시 영역

**입력**
userId, chatId, branchId

**처리**
채팅·브랜치의 메시지 블록 목록을 돌려줄 때, 아직 생성 중인 답변 블록에는 그 작업의 aiResponseJobId를 함께 실어 보낸다. 완료·중단·실패한 블록에는 실어 보내지 않는다. 화면은 이 id로 BE-AIRESP-007의 통로에 다시 붙는다.

**출력**
메시지 블록 목록(생성 중인 블록에는 aiResponseJobId 포함)

**DB 영향**
AIResponseJob 조회

**상태 변화**
없음

**권한**
로그인 필요, 채팅 소유자

**오류**
없음

**우선순위**
상

**비고**
새 엔드포인트가 아니라 기존 채팅·브랜치 조회 응답에 값을 더하는 방식이다.
