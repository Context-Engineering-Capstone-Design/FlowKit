## 2.6 블록별 정제

### BE-REFINE-001 · 블록별 정제 요청 생성 및 대상 스냅샷 구성

사용자가 선택한 메시지 블록과 편집 지시를 기반으로 정제 작업을 생성하고, 실행 시점의 각 블록 활성 버전을 정제 기준으로 고정한다.

도메인 | BlockRefine, MessageBlock
관련 요구사항 | REQ-028, REQ-029
관련 화면 | 블록별로 정제하기 버튼

입력 | userId, chatId, branchId, selectedBlockIds, instructionText
처리 | 선택 블록 유효성 및 편집 지시를 검증한 뒤 BlockRefineJob을 생성하고, 각 blockId의 currentVersionId와 content를 BlockRefineTarget으로 저장한다.
출력 | refineJobId, refineTargets(blockId, baseVersionId, baseContent, role, orderIndex), status

DB 영향 | BlockRefineJob 생성, BlockRefineTarget 생성, MessageBlock 조회, MessageBlockVersion 조회
상태 변화 | 없음 → 정제 요청 생성, 정제 기준 버전 확정
권한 | 로그인 필요, 채팅 소유자
오류 | 선택 블록 없음, 지시문 없음, 블록 없음, 버전 없음, 권한 없음, 요청 생성 실패
우선순위 | 상

비고 | 하나의 블록별 정제 실행 API 내부에서 처리

### BE-REFINE-002 · AI 정제 요청 전달

정제 대상 블록과 편집 지시를 AI 모델링 파트에 전달해 블록별 정제 결과 생성을 요청한다.

도메인 | BlockRefine, AI
관련 요구사항 | REQ-028
관련 화면 | 블록별로 정제하기 버튼

입력 | refineJobId, refineTargets, instructionText
처리 | 각 대상 블록의 기준 content와 instructionText를 AI 모델링 파트에 전달하고, 블록별 정제 결과를 수신한다.
출력 | aiRefineResults(blockId, refinedContent)

DB 영향 | BlockRefineJob 조회
상태 변화 | 정제 요청 중 → 정제 결과 수신
권한 | 로그인 필요, 채팅 소유자
오류 | AI 요청 실패, 응답 지연, 정제 결과 누락, blockId 불일치
우선순위 | 상

비고 | BE-REFINE-001과 동일 API flow

### BE-REFINE-003 · 블록별 정제 결과 저장

AI 모델링 파트가 생성한 정제 결과를 각 원본 blockId와 연결해 저장한다.

도메인 | BlockRefine
관련 요구사항 | REQ-028, REQ-032
관련 화면 | 정제 결과 패널, 인라인 정제 결과

입력 | refineJobId, aiRefineResults
처리 | 각 결과가 정제 대상 blockId와 대응되는지 확인하고, refinedContent와 status=pending을 저장한다.
출력 | refineResults(resultId, blockId, baseVersionId, refinedContent, status)

DB 영향 | BlockRefineResult 생성, BlockRefineJob 수정
상태 변화 | 정제 요청 중 → 정제 결과 대기
권한 | 로그인 필요, 채팅 소유자
오류 | 결과 없음, blockId 불일치, 저장 실패
우선순위 | 상

비고 | BlockRefineResult 상태: pending, approved, rejected

### BE-REFINE-004 · 정제 결과 목록 조회

정제 완료 후 FE가 원본과 정제 결과를 비교·표시할 수 있도록 결과 목록을 조회한다.

도메인 | BlockRefine
관련 요구사항 | REQ-029, REQ-030, REQ-031, REQ-032
관련 화면 | 우측 정제 결과 패널, 인라인 정제본 표시, 원본/정제본 토글

입력 | userId, chatId, branchId, refineJobId
처리 | 정제 작업 접근 권한을 확인하고, 각 결과의 기준 버전 content와 refinedContent, status를 함께 반환한다.
출력 | refineResults(resultId, blockId, baseVersionId, baseContent, refinedContent, status, orderIndex)

DB 영향 | BlockRefineResult 조회, MessageBlockVersion 조회
상태 변화 | 없음
권한 | 로그인 필요, 채팅 소유자
오류 | 정제 작업 없음, 결과 없음, 권한 없음
우선순위 | 상

비고 | 인라인 표시, 토글, 비교 UI 렌더링은 FE 책임

### BE-REFINE-005 · 정제 결과 승인 및 버전 반영

pending 상태의 정제 결과를 승인하면 해당 정제본을 메시지 블록의 새 버전으로 저장하고 활성화한다.

도메인 | BlockRefine, MessageBlock, Version
관련 요구사항 | REQ-033, REQ-036, REQ-039, REQ-040, REQ-041, REQ-042
관련 화면 | 인라인 승인 버튼, 우측 패널 승인 버튼

입력 | userId, chatId, branchId, resultId
처리 | pending 상태인 resultId를 검증한 뒤 refinedContent를 새 MessageBlockVersion으로 저장하고 MessageBlock.currentVersionId를 새 versionId로 변경한다. BlockRefineResult.status를 approved로 변경한다.
출력 | blockId, resultId, newVersionId, currentVersionId, content, status

DB 영향 | MessageBlockVersion 생성, MessageBlock 수정, BlockRefineResult 수정
상태 변화 | pending → approved, 기존 활성 버전 → 정제 버전 활성화
권한 | 로그인 필요, 채팅 소유자
오류 | 정제 결과 없음, pending 아님, 이미 거절됨, 블록 없음, 버전 저장 실패, 권한 없음
우선순위 | 상

비고 | 승인 후 되돌리기는 BE-MSG-005/006 사용. 버전 이력 삭제하지 않음

### BE-REFINE-006 · 정제 결과 거절

pending 상태의 정제 결과를 원본 블록에 반영하지 않도록 거절한다.

도메인 | BlockRefine
관련 요구사항 | REQ-035, REQ-036
관련 화면 | 인라인 거절 버튼, 우측 패널 거절 버튼

입력 | userId, chatId, branchId, resultId
처리 | pending 상태인 resultId를 검증하고 BlockRefineResult.status를 rejected로 변경한다. MessageBlock.currentVersionId는 변경하지 않는다.
출력 | resultId, blockId, status

DB 영향 | BlockRefineResult 수정
상태 변화 | pending → rejected
권한 | 로그인 필요, 채팅 소유자
오류 | 정제 결과 없음, pending 아님, 이미 승인됨, 권한 없음
우선순위 | 상

비고 | MessageBlockVersion 생성하지 않음

### BE-REFINE-007 · 정제 결과 일괄 승인

pending 상태의 정제 결과를 한 번에 승인하고 각 대상 메시지 블록에 새 버전으로 반영한다.

도메인 | BlockRefine, MessageBlock, Version
관련 요구사항 | REQ-037
관련 화면 | 전체 승인 버튼

입력 | userId, chatId, branchId, refineJobId
처리 | refineJobId의 pending 결과를 순회하며 BE-REFINE-005와 동일하게 새 MessageBlockVersion을 생성하고 currentVersionId를 변경한다.
출력 | approvedResults(resultId, blockId, newVersionId), failedResults

DB 영향 | MessageBlockVersion 생성, MessageBlock 수정, BlockRefineResult 수정
상태 변화 | 여러 결과 pending → approved
권한 | 로그인 필요, 채팅 소유자
오류 | 일부 결과 승인 실패, 정제 작업 없음, 권한 없음
우선순위 | 중

비고 | MVP에서 개별 승인만 우선하면 후순위 가능

출력 | rejectedResults(resultId, blockId), failedResults

DB 영향 | BlockRefineResult 수정
상태 변화 | 여러 결과 pending → rejected
권한 | 로그인 필요, 채팅 소유자
오류 | 정제 작업 없음, 일부 결과 거절 실패, 권한 없음
우선순위 | 중

비고 | MVP에서 개별 거절만 우선하면 후순위 가능

### BE-REFINE-010 · 미승인 정제 결과 정리

승인되지 않은 정제 결과가 원본 메시지 블록에 영향을 주지 않도록 미승인 결과를 정리한다.

도메인 | BlockRefine
관련 요구사항 | REQ-043
관련 화면 | 패널 닫기, 새 정제 실행

입력 | userId, chatId, branchId, refineJobId
처리 | pending 또는 rejected 상태의 정제 결과를 보관 또는 만료 처리한다. MessageBlock.currentVersionId는 변경하지 않는다.
출력 | cleanupResult(refineJobId, cleanedCount)

DB 영향 | BlockRefineResult 수정 가능
상태 변화 | pending/rejected 결과 → 보관/만료
권한 | 로그인 필요, 채팅 소유자
오류 | 정제 작업 없음, 권한 없음, 정리 실패
우선순위 | 중

비고 | 미승인 결과는 활성 메시지 흐름에 반영되지 않음

### BE-REFINE-011 · 블록별 정제 접근 권한 검증

사용자가 특정 정제 작업과 정제 결과에 접근하거나 상태를 변경할 수 있는지 공통으로 검증한다.

도메인 | BlockRefineAuth
관련 요구사항 | REQ-028, REQ-033, REQ-035, REQ-036
관련 화면 | 블록별 정제 관련 전체 기능

입력 | userId, chatId, branchId, refineJobId 또는 resultId
처리 | refineJob 또는 result가 해당 Chat, Branch에 속하는지 확인하고 Chat ownerId와 요청 userId를 비교한다.
출력 | hasAccess 또는 권한 오류

DB 영향 | Chat 조회, Branch 조회, BlockRefineJob 조회, BlockRefineResult 조회
상태 변화 | 없음
권한 | 로그인 필요, 채팅 소유자
오류 | REFINE_JOB_NOT_FOUND, REFINE_RESULT_NOT_FOUND, ACCESS_DENIED
우선순위 | 상

비고 | 공통 서비스 함수로 구현 권장
