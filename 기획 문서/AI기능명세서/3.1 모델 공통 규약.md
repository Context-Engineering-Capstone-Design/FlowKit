## 3.1 모델 공통 규약

**FE/BE/AI 책임 기준:** AI 모델링 파트는 백엔드가 파이썬 패키지로 가져다 쓰는 라이브러리다. 별도 서버로 뜨지 않는다. DB를 직접 보지 않고, 백엔드가 넘긴 데이터 구조만 받아 모델 호출 결과를 돌려준다. 권한 검증·저장·상태 관리는 모두 백엔드 책임이다.

### AI-CORE-001 · 사용 가능 모델 목록 정의

사용자가 고를 수 있는 모델과 각 모델이 지원하는 기능을 한곳에서 정의한다.

ModelRegistry

**관련 요구사항**
REQ-056, NFR-017

**관련 BE 기능**
BE-INPUT-005

**관련 화면**
모델 선택 버튼, 모델 드롭다운

**입력**
없음

**처리**
모델별로 `modelId`, `displayName`, `provider`, 웹 검색 지원 여부, 첨부 입력 지원 여부, 기본 모델 여부를 정의한 목록을 반환한다. 목록은 코드 안 상수로 관리한다.

**출력**
`models(modelId, displayName, provider, supportsWebSearch, supportsAttachment, isDefault)`

**DB 영향**
없음

**상태 변화**
없음

**권한**
없음

**오류**
없음

**우선순위**
중

**비고**
백엔드는 이 목록을 그대로 BE-INPUT-005 응답으로 내보낸다. 드롭다운 표시는 FE 책임이다.

### AI-CORE-002 · 모델 선택값 확정

요청에 실려 온 모델 선택값이 쓸 수 있는 값인지 확인하고, 실제로 호출할 모델을 정한다.

**도메인**
ModelRegistry

**관련 요구사항**
REQ-056

**관련 BE 기능**
BE-INPUT-006

**관련 화면**
모델 선택 버튼, 메시지 전송 버튼

**입력**
`selectedModelId` 선택값

**처리**
값이 없으면 기본 모델을 쓴다. 값이 있으면 AI-CORE-001 목록에 있는지 확인하고, 없는 값이면 오류를 낸다. 지원하지 않는 모델로 조용히 기본 모델을 쓰지 않는다.

**출력**
`resolvedModel(modelId, displayName, provider, supportsWebSearch, supportsAttachment)`

**DB 영향**
없음

**상태 변화**
모델 선택값 확정

**권한**
없음

**오류**
지원하지 않는 모델

**우선순위**
중

**비고**
사용자별 사용 권한 판단은 백엔드 몫이다. 여기서는 목록에 있는 모델인지만 본다.

### AI-CORE-003 · 모델 클라이언트 생성

정해진 모델과 요청 옵션에 맞는 모델 클라이언트를 만든다.

**도메인**
LLMClient

**관련 요구사항**
REQ-055, REQ-056, REQ-060

**관련 BE 기능**
BE-AIRESP-001, BE-REFINE-002, BE-CHAT-004

**관련 화면**
없음

**입력**
`apiKey`, `modelId`, `webSearchEnabled` 선택값

**처리**
API 키와 모델명과 요청 옵션 조합마다 클라이언트를 만들어 재사용한다. 같은 모델이라도 키가 다르거나 웹 검색을 켠 정도가 다르면 서로 다른 클라이언트로 다룬다. 응답 시간 제한을 함께 건다.

**출력**
모델 클라이언트

**DB 영향**
없음

**상태 변화**
없음

**권한**
없음

**오류**
API 키 없음, 클라이언트 생성 실패

**우선순위**
상

**비고**
사용자마다 다른 키를 쓰므로 키를 모듈 전체가 공유하는 값으로 두면 안 된다. 체인은 이 함수가 만든 클라이언트를 쓰되, 인자로 다른 모델을 직접 넣을 수도 있다. 테스트는 가짜 모델을 넣어 API 키 없이 돌린다.

### AI-CORE-004 · API 키 확인

모델을 부르기 전에 이번 요청에 쓸 API 키가 있는지 확인한다.

**도메인**
LLMClient

**관련 요구사항**
REQ-060, REQ-062

**관련 BE 기능**
BE-USERSET-006, BE-AIRESP-001, BE-REFINE-002, BE-CHAT-004

**관련 화면**
오류 배너, API 키 관리 모달

**입력**
백엔드가 요청마다 넘긴 `apiKey`

**처리**
요청과 함께 넘어온 키를 쓴다. 키가 없거나 비어 있으면 모델을 부르지 않고 키 없음 오류를 낸다. 키를 모듈 안에 남겨 두거나 다음 요청에 재사용하지 않는다.

**출력**
확인된 API 키 또는 키 없음 오류

**DB 영향**
없음

**상태 변화**
없음

**권한**
없음

**오류**
API 키 없음

**우선순위**
상

**비고**
키를 꺼내 복호화해 넘기는 것은 BE-USERSET-003과 006의 몫이다. 이 오류를 REQ-062의 안내 배너로 바꿔 보여주는 것은 백엔드와 FE 책임이다. 키 값 자체는 로그와 응답 어디에도 남기지 않는다. 사용자 키를 요구하지 않는 모델이라면 백엔드가 서비스 공용 키를 넘길 수 있고, AI 파트는 그 키가 누구 것인지 구분하지 않는다.

### AI-CORE-005 · 요청 시간 제한과 실패 전달

모델 호출이 길어지거나 실패했을 때 백엔드가 판단할 수 있는 형태로 알린다.

**도메인**
LLMClient

**관련 요구사항**
NFR 운영 항목

**관련 BE 기능**
BE-AIRESP-001, BE-REFINE-002

**관련 화면**
오류 안내, 답변 다시 시도 버튼

**입력**
모델 호출 요청

**처리**
모든 모델 호출에 응답 시간 제한을 건다. 제한을 넘거나 모델이 오류를 내면 예외로 올려보내고, 여기서 임의로 다시 시도하지 않는다.

**출력**
예외

**DB 영향**
없음

**상태 변화**
없음

**권한**
없음

**오류**
응답 시간 초과, 모델 호출 실패, 응답 없음

**우선순위**
상

**비고**
재시도 여부와 사용자 안내는 백엔드가 정한다. 답변 생성 실패 시 사용자 질문을 남겨 두는 처리도 백엔드 책임이다.

---



### AI-CORE-006 · API 키 연결 확인

사용자가 등록한 키로 실제 모델을 부를 수 있는지 최소 요청으로 확인한다.

**도메인**
LLMClient

**관련 요구사항**
REQ-061

**관련 BE 기능**
BE-USERSET-005

**관련 화면**
API 키 관리 모달 연결 확인 버튼

**입력**
`apiKey`, `modelId` 선택값

**처리**
받은 키로 비용이 거의 들지 않는 최소 요청을 보내 성공 여부만 확인한다. 실패하면 키가 잘못된 것인지 연결이 안 되는 것인지 구분할 수 있게 사유를 함께 돌려준다. 대화 내용이나 사용자 데이터를 이 요청에 넣지 않는다.

**출력**
`connectionResult(success, reason 선택값)`

**DB 영향**
없음

**상태 변화**
없음

**권한**
없음

**오류**
API 키 없음, 잘못된 키, 연결 실패, 응답 시간 초과

**우선순위**
중

**비고**
확인 결과를 저장하고 화면에 알리는 것은 BE-USERSET-005 책임이다. 이 함수는 예외를 밖으로 던지지 않고 실패도 결과값으로 돌려준다. 연결 확인은 실패가 정상적인 결과이기 때문이다.
