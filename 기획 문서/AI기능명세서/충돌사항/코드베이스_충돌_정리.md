# AI 기능명세서와 현재 코드베이스의 충돌 정리

이 문서는 임시 문서다. 아래 항목을 모두 해결하면 파일과 `충돌사항/` 폴더째로 지운다. 그래서 다른 문서에서 이 문서를 링크로 걸지 않는다.

**비교 대상은 AI 기능명세서와 코드다.** 요구사항정의서는 여기서 다루지 않는다. 충돌은 모두 기능명세서를 기준으로 삼아 코드를 고쳐 해결한다. 명세를 코드에 맞춰 고치는 항목은 없다.

기준 코드는 `modeling/`과 `backend/app/services/`다.

먼저 적어둘 것은, 이미 만들어진 부분은 대체로 명세와 잘 맞는다는 점이다. 블록별 정제(AI-REFINE-001~004), 채팅 제목 생성(AI-TITLE-001~003), 답변 입력 구성과 Context 반영(AI-ANSWER-001~003)은 명세대로 동작한다. API 키 확인(AI-CORE-004)과 시간 제한·실패 전달(AI-CORE-005)도 명세와 일치한다.

아래는 아직 없거나 어긋나는 항목이다.

---

## 1. 답변 재생성이 명세와 정반대로 동작한다

**충돌 대상:** AI-ANSWER-004

**명세**

AI-ANSWER-004는 백엔드가 넘긴 원래 입력 스냅샷을 그대로 써서 다시 생성하고, "재생성이라는 이유로 Context를 빼거나 대화 흐름을 새로 계산하지 않는다"고 정한다.

**현재 동작**

`backend/app/services/ai_response_service.py`의 `send_message`는 적용 Context가 있으면 이전 대화 흐름을 비우고(78행) Context만 근거로 답을 만든다(87행). 그런데 같은 파일의 `regenerate`는 적용 Context 자리에 빈 목록을 넘기고, 대신 앞선 대화 흐름 전체를 새로 계산해 넘긴다(145행).

명세가 하지 말라고 한 두 가지를 정확히 하고 있다. Context를 빼고, 흐름을 새로 계산한다.

**무엇이 문제인가**

Context를 골라 물어본 답변을 다시 만들면, 고른 Context는 빠지고 고르지 않은 대화가 근거로 들어온다. 사용자는 같은 질문의 두 답변을 버전으로 비교한다고 생각하지만 실제로는 조건이 다른 두 답을 비교하게 되고, 무엇 때문에 답이 달라졌는지 알 수 없다.

**해결 방향(코드)**

`context_service.save_log`가 적용 Context 사용 이력을 이미 저장하고 있다. `regenerate`에서 그 이력을 읽어 원래 입력 조건을 복원해 넘긴다. 이력이 없는 답변만 지금처럼 대화 흐름을 기준으로 처리한다.

**우선순위:** 상. 기능이 없는 것이 아니라 이미 잘못 동작하고 있는 유일한 항목이다.

## 2. 모델 목록과 선택값 확정 단계가 없다

**충돌 대상:** AI-CORE-001, AI-CORE-002, AI-ANSWER-003, AI-ANSWER-004, AI-REFINE-002

**명세**

AI-CORE-001은 모델별 `modelId`, `displayName`, `provider`, 웹 검색·첨부 지원 여부, 기본 모델 여부를 담은 목록을 코드 안 상수로 두라고 정한다. AI-CORE-002는 넘어온 선택값이 그 목록에 있는지 확인하고, 없는 값이면 조용히 기본 모델로 넘어가지 말고 오류를 내라고 정한다. AI-ANSWER-003, AI-ANSWER-004, AI-REFINE-002는 모두 `selectedModelId`를 입력으로 받는다.

**현재 동작**

`modeling/config.py`에는 모델명 상수가 하나뿐이고(7행) 목록이 없다. `modeling/llm.py`의 `get_chat_model`은 모델명을 인자로 받지만(36행) 그 값이 쓸 수 있는 값인지 판단하지 않는다. `modeling/types.py`의 `AnswerRequest`에는 모델 선택값을 담을 자리가 없고(37~46행), 백엔드의 `send_message`, `regenerate`, `_call_refiner` 어디에도 모델 인자가 없다.

**무엇이 문제인가**

명세가 정한 세 함수가 모두 받도록 되어 있는 입력을 받을 수 없다. 지금 구조에서는 백엔드가 모델 선택값을 알아내도 모델링까지 전달할 통로가 없다.

**해결 방향(코드)**

모델 목록을 상수로 정의하고, 선택값을 검증해 실제 모델을 정하는 단계를 만든다. `AnswerRequest`와 정제 호출에 모델 선택값을 받는 자리를 만들고, 전송·재생성·정제 흐름에서 그 값을 이어 넘긴다.

**우선순위:** 중. 4번과 5번이 같은 전달 통로를 함께 쓴다.

---

## 3. 모델 클라이언트를 모델명만으로 재사용한다

**충돌 대상:** AI-CORE-003

**명세**

AI-CORE-003은 "모델명과 요청 옵션 조합마다 클라이언트를 만들어 재사용"하고, "같은 모델이라도 웹 검색을 켠 클라이언트와 끈 클라이언트는 서로 다른 것으로 다룬다"고 정한다.

**현재 동작**

`modeling/llm.py`의 `get_chat_model`은 모델명 하나만을 기준으로 만들어 둔 클라이언트를 재사용한다(35~36행). 요청 옵션은 기준에 들어가지 않는다.

**무엇이 문제인가**

지금은 옵션 자체가 없어 겉으로 드러나지 않는다. 그러나 2번과 4번을 넣는 순간, 먼저 만들어진 클라이언트가 옵션이 다른 요청에도 그대로 쓰인다. 검색을 켰는데 검색이 안 되거나 껐는데 검색이 도는 상태가 되고, 원인을 찾기 어렵다.

**해결 방향(코드)**

재사용 기준에 요청 옵션을 함께 넣는다. `configure`가 기억을 비우는 처리는 그대로 유지한다.

**우선순위:** 중. 2번·4번과 반드시 함께 처리한다. 따로 두면 나중에 원인 불명의 문제로 나타난다.

## 4. 웹 검색을 수행하는 코드가 없다

**충돌 대상:** AI-SEARCH-001, AI-SEARCH-002

**명세**

AI-SEARCH-001은 검색을 켠 요청에 모델 내장 Google 검색 도구를 붙이고, 고른 모델이 검색을 지원하지 않으면 오류를 내라고 정한다. AI-SEARCH-002는 응답에 검색 근거가 있으면 제목과 주소를 뽑아 함께 돌려주라고 정한다.

**현재 동작**

`modeling/` 전체에 검색 관련 코드가 없다. `AnswerRequest`에 검색 사용 여부를 담을 자리도 없다.

**무엇이 문제인가**

명세가 정한 두 기능이 통째로 비어 있다. 화면에서는 토글이 켜지므로, 사용자는 검색이 된 줄 알고 답을 받게 된다.

**해결 방향(코드)**

`AnswerRequest`에 검색 사용 여부를 받는 자리를 만들고, 켜진 요청에만 내장 검색 도구를 붙인 클라이언트를 쓴다. 응답에서 근거 정보를 뽑아 답변과 함께 돌려준다. 별도 검색 서비스나 API 키 발급은 필요 없다.

**우선순위:** 하

---

## 5. 첨부 파일을 모델에 넘길 방법이 없다

**충돌 대상:** AI-ATTACH-001, AI-ATTACH-002, AI-ATTACH-003

**명세**

AI-ATTACH-001은 이미지를 텍스트로 바꾸지 말고 질문 메시지에 함께 실어 넘기라고 정한다. AI-ATTACH-002는 PDF와 텍스트 계열 파일의 글자를 뽑아 파일명과 함께 질문 앞에 붙이고, 글자를 뽑을 수 없으면 조용히 넘기지 말고 오류로 알리라고 정한다.

**현재 동작**

`modeling/types.py`의 대화 데이터는 모두 글자만 담는다. `ChatTurn.content`(33행)와 `AnswerRequest.user_prompt`(44행)가 문자열이고, 첨부를 담을 자리가 없다. 백엔드의 `_generate`도 글자만 조립해 넘긴다.

**무엇이 문제인가**

첨부를 받을 입구 자체가 없다. 4번과 마찬가지로 화면에는 첨부가 붙은 것으로 보이므로 사용자가 잘못됐다는 것을 알아채기 어렵다.

**해결 방향(코드)**

`AnswerRequest`에 첨부 목록을 받는 자리를 만든다. 이미지는 모델에 그대로 실어 보내고, PDF와 텍스트 계열 파일은 글자를 뽑아 질문 앞에 붙인다. 첨부가 없으면 기존 흐름이 그대로 유지되어야 한다(AI-ATTACH-003).

**우선순위:** 하

## 확인이 필요한 항목

아래는 충돌로 단정하지 않았다. 실제 키로 확인한 뒤 결론을 낸다.

### 다시 만든 답변이 이전 답변과 같을 수 있다

**관련:** AI-ANSWER-004

`modeling/config.py`에 적힌 대로 현재 모델은 샘플링 값을 고정으로 쓰며 값을 지정할 수 없다. 위 1번을 고쳐 재생성 입력을 원래 조건 그대로 맞추면, 같은 입력에 같은 답이 나올 가능성이 생긴다.

AI-ANSWER-004는 입력 조건을 똑같이 맞추라고 정하지만, 그렇게 해서 나온 답이 매번 동일하다면 재생성 기능 자체가 의미를 잃는다. 같은 입력으로 여러 번 불러 답이 실제로 달라지는지 먼저 확인한다. 달라지지 않으면 명세에 다양성 확보 방법을 추가할지 사용자와 상의한다.
