# FE 기능명세서와 프로토타입의 충돌 정리

이 문서는 임시 문서다. 아래 항목을 모두 해결하면 파일과 `충돌사항/` 폴더째로 지운다. 그래서 다른 문서에서 이 문서를 링크로 걸지 않는다.

비교 대상은 `기획 문서/FlowKit_0520.html`과 `기획 문서/요구사항정의서/`다. 프로토타입은 5월 작성본이고, 요구사항은 그 뒤에 확정됐다. FE 기능명세서는 요구사항을 기준으로 작성했으므로, 아래 항목은 모두 프로토타입 쪽이 낡은 경우다.

세 항목 모두 블록별 정제(2.6)에 몰려 있고, 원인이 하나로 이어진다. 프로토타입은 승인·거절을 **껐다 켰다 하는 표시**로 다뤘고, 확정된 요구사항은 **한 번 정하면 되돌리지 않는 상태 전이**로 다룬다.

---

## 1. 승인한 정제 결과를 다시 눌러 취소할 수 있다

**충돌 대상:** REQ-033, REQ-036, FE-REFINE-005, BE-REFINE-005

**현재 동작**

프로토타입의 `approveBlockRefine`은 이미 승인된 항목을 다시 누르면 상태를 `pending`으로 되돌리고 `_revertBlockNow`로 블록 내용을 원본으로 복구한다. 버전 이력에서도 마지막 항목을 빼낸다.

**무엇이 문제인가**

REQ-033은 "승인 후에는 정제 승인 취소 UI를 제공하지 않는다", REQ-036은 "승인 버튼 재클릭으로 승인을 취소할 수 없다"고 명시한다. 되돌리기는 메시지 블록 버전 이동(REQ-020, REQ-021)으로만 하도록 정해져 있다.

더 중요한 건 데이터 쪽이다. 승인은 정제본을 블록의 새 버전으로 저장하고 활성 버전을 바꾸는 동작이다(BE-REFINE-005). 프로토타입처럼 화면에서 버전을 빼내는 방식은 서버에 이미 저장된 버전과 어긋난다. BE 명세의 상태 전이에도 `approved → pending` 경로가 없다.

**해결 방향**

승인 버튼은 대기 상태에서만 누를 수 있게 한다. 승인이 끝나면 인라인 툴바를 제거하고 패널 항목도 목록에서 없앤다. 되돌리려는 사용자는 블록 버전 이동으로 안내한다. FE 기능명세서는 이미 이 기준으로 작성했다.

**우선순위:** 상. 저장된 버전과 화면이 어긋나는 문제라 구현 단계에서 그대로 옮기면 안 된다.

## 2. 거절한 정제 결과도 다시 눌러 취소할 수 있다

**충돌 대상:** REQ-035, FE-REFINE-006, BE-REFINE-006

**현재 동작**

프로토타입의 `rejectBlockRefine`은 이미 거절된 항목을 다시 누르면 상태를 `pending`으로 되돌린다.

**무엇이 문제인가**

REQ-035는 "pending 상태의 정제 결과만 거절 가능"하다고 정한다. BE-REFINE-006의 상태 변화도 `pending → rejected` 한 방향뿐이고 되돌아오는 경로가 없다. 화면에서만 대기 상태로 되돌리면, 서버는 거절로 알고 있는 항목을 사용자는 다시 승인할 수 있다고 보게 된다.

**해결 방향**

거절 버튼도 대기 상태에서만 누를 수 있게 한다. 거절한 항목은 '거절됨' 표시로 남기고 더 이상 상태를 바꾸지 않는다. 다시 정제하고 싶으면 새로 정제를 실행한다.

**우선순위:** 상. 1번과 같은 원인이라 함께 처리한다.

---

## 3. 전체 승인·전체 거절이 이미 거절한 항목까지 건드린다

**충돌 대상:** REQ-037, REQ-038, FE-REFINE-007, FE-REFINE-008, BE-REFINE-007, BE-REFINE-008

**현재 동작**

프로토타입의 `approveAllBlockRefines`는 승인되지 않은 항목 전부를 대상으로 삼는다. 즉 사용자가 방금 거절한 항목까지 승인해 버린다. `rejectAllBlockRefines`도 상태를 가리지 않고 전부 거절로 바꾼다.

또 전체 승인·전체 거절 버튼의 노출 조건이 "승인되지 않은 항목이 있는가"로 되어 있어, 거절만 남은 상태에서도 버튼이 계속 보인다.

**무엇이 문제인가**

REQ-037과 REQ-038은 둘 다 "pending 상태의 모든 정제 결과"만 대상으로 한다고 정한다. REQ-038은 "전체 거절 버튼은 pending 항목이 없을 경우 숨겨져야 한다"까지 명시한다.

사용자가 일부러 거절한 항목이 전체 승인 한 번에 되살아나 블록에 적용되는 것은, 거절·대기 항목이 원본에 영향을 주면 안 된다는 NFR-010에도 어긋난다.

**해결 방향**

전체 승인·전체 거절 모두 대기 상태 항목만 대상으로 한다. 버튼 노출 조건도 "대기 항목이 1개 이상인가"로 바꾼다. 서버가 일부 실패를 돌려주면 성공한 항목만 반영하고 나머지는 목록에 남긴다.

**우선순위:** 중. 1·2번을 고치면 상태 구분이 명확해지므로 함께 정리한다.

## 참고: 충돌이 아닌 항목

아래는 확인했으나 충돌이 아니었다. 다시 검토하지 않기 위해 남긴다.

- **Context 패널 레이아웃** — NFR-018은 패널 섹션을 배경색·테두리 박스 없이 나누라고 정한다. 프로토타입의 섹션 요소에는 배경과 테두리가 없어 이미 이 기준을 만족한다.
- **로그인 화면 안내 문구** — 프로토타입에 "계정 정보는 이 기기에만 저장됩니다"라는 문구가 있으나, 이는 프로토타입이 브라우저 저장소만 쓰는 목업이기 때문이다. 실제 인증은 서버에 저장되므로 FE 기능명세서에는 이 문구를 넣지 않았다. 프로토타입 자체를 고칠 필요는 없다.
- **마이크 버튼** — 프로토타입 입력창에 남아 있으나 REQ-057에 따라 MVP 구현 범위가 아니다. FE-INPUT-007에 제외 항목으로 명시했다.
