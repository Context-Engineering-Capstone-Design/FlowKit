## 2.13 다중 창 실시간 동기화

### FE-REALTIME-001 · 실시간 채널 연결 유지

로그인해 있는 동안 다른 창의 변화를 받는 실시간 연결을 계속 열어 둔다.

**화면**
없음 (화면에 표시되지 않는 내부 연결)

**관련 요구사항**
REQ-073, REQ-074

**관련 BE 기능**
BE-REALTIME-001

**트리거**
로그인, 로그아웃, 연결 끊김

**화면 동작**
로그인하면 실시간 채널에 연결한다. 연결이 끊기면 1초, 2초, 4초... 최대 30초 간격으로 다시 연결을 시도한다. 다시 연결되면 그동안 놓쳤을 변화를 보정하기 위해 대화 목록을 한 번 강제로 다시 불러온다. 로그아웃하면 연결을 닫는다.

**표시 데이터**
없음

**입력 검증**
없음

**오류 처리**
연결이 끊겨도 오류로 알리지 않고 조용히 재연결을 시도한다. 재연결 전까지는 기존 폴링(FE-CHAT-003)이 안전망 역할을 한다.

**우선순위**
중

**비고**
인증 정보를 실어야 해서 EventSource가 아니라 fetch로 직접 스트림을 읽는다(FE-AIRESP-005와 같은 방식). 여러 대화 패널이 있어도 이 연결은 계정당 하나만 유지한다.

---

### FE-REALTIME-002 · 사이드바 대화 목록 자동 갱신

다른 창에서 대화를 만들거나 지우거나 제목을 바꾸면, 사이드바 목록이 자동으로 그 변화를 보여준다.

**화면**
사이드바 최근 대화 목록

**관련 요구사항**
REQ-073

**관련 BE 기능**
BE-REALTIME-002

**트리거**
대화 목록 변화 신호 수신

**화면 동작**
신호를 받으면 지금 보이는 검색어·조건 그대로 대화 목록을 다시 불러온다. 자기 자신이 방금 만든 변화의 신호를 받아도 다시 불러오기 자체는 안전하다(같은 결과를 그대로 다시 그린다).

**표시 데이터**
갱신된 대화 목록

**입력 검증**
없음

**오류 처리**
다시 불러오기에 실패해도 화면 흐름을 막지 않는다 — 다음 신호나 안전망 폴링에서 다시 시도된다.

**우선순위**
중

**비고**
기존 생성 중 배지 폴링(FE-CHAT-003)의 간격을 2.5초에서 60초로 늘렸다. 이 실시간 신호가 주 경로이고, 폴링은 연결이 끊겼을 때만 의미가 있는 안전망이다.

---

### FE-REALTIME-003 · 열려 있는 대화 자동 갱신과 실시간 답변 확인

지금 열려 있는 대화와 같은 대화에서 다른 창이 메시지를 보내거나 답변을 받으면, 그 내용이 이 창에도 자동으로 나타난다.

**화면**
중앙 채팅 영역

**관련 요구사항**
REQ-074

**관련 BE 기능**
BE-REALTIME-003

**트리거**
답변 생성 시작·완료 신호 수신(지금 열려 있는 대화·브랜치와 같을 때만)

**화면 동작**
신호를 받으면 스크롤 위치·선택 상태는 그대로 두고 지금 대화의 메시지 블록만 조용히 다시 불러온다. 신호에 작업 id가 실려 있고 그 답변 블록이 아직 생성 중이면, 이미 그 블록에 붙어 있는 스트림이 없을 때만 FE-AIRESP-005의 통로에 새로 붙는다 — 이 창 자신이 보낸 요청이면 이미 붙어 있으므로 중복 연결하지 않는다. 다른 대화의 신호는 무시한다.

**표시 데이터**
새로 생긴 질문·답변 블록, 실시간으로 이어지는 답변 글자

**입력 검증**
없음

**오류 처리**
다시 불러오기에 실패하면 조용히 넘어간다 — 다음 신호나 안전망 폴링에서 보정된다.

**우선순위**
중

**비고**
다른 대화의 답변 활동 신호는 FE-REALTIME-002의 목록 갱신만으로 사이드바 배지에 반영되므로 따로 처리하지 않는다.
