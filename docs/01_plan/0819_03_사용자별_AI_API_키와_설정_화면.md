## 목표

서버 공용 Gemini API 키 의존을 제거하고, 로그인 사용자가 자신의 키를 안전하게 등록·삭제·확인한 뒤 답변·정제·제목 생성에 사용하게 한다. 프로필 팝업과 사용자 정보 수정 화면도 함께 완성한다.

## 현재 상태와 문제

- `modeling`은 호출마다 `api_key`를 받을 수 있다.
- 백엔드는 시작 시 `GOOGLE_API_KEY`를 전역 예비 키로 등록하고, 실제 요청에는 사용자 키를 전달하지 않는다.
- 사용자 기본 정보 조회·수정 API는 있으나 API 키 저장 구조와 설정 API가 없다.
- 사이드바에는 사용자 정보와 로그아웃만 있고 프로필 팝업·수정 모달·API 키 모달이 없다.
- 실제 Gemini 키 연결 확인은 가짜 모델 테스트만 되어 있다.

## 확정 구현 방식

### API 키 보관

- 키 원문은 암호화한 값만 DB에 저장한다.
- 암호화에는 `cryptography`의 Fernet을 사용한다.
- 암호화 키는 `API_KEY_ENCRYPTION_KEY` 환경 변수로 받는다.
- 운영·개발 모두 안전한 기본값을 두지 않는다. 값이 없으면 키 저장·AI 호출 API를 시작 전에 실패시킨다.
- 화면 표시용으로 Provider와 마지막 4자만 별도 저장한다.
- 현재 Provider 값은 `google`만 허용한다. 확장 가능한 문자열 필드로 저장하되 임의 Provider는 거절한다.
- 사용자와 Provider 조합은 하나만 존재하게 한다.

### AI 호출 키 선택

- 현재 Gemini 모델은 사용자 키가 필요한 모델로 본다.
- 백엔드는 매 요청에서 현재 사용자의 키를 조회·복호화해 모델링 함수 인자로 전달한다.
- 키 원문을 전역 변수, 캐시 키 외의 장기 메모리, 입력 스냅샷, 로그에 남기지 않는다.
- 모델링 클라이언트 캐시는 기존처럼 키·모델·검색 설정 조합을 사용한다. 최대 크기 제한은 유지한다.
- 서버 시작 시 `configure_llm(settings.google_api_key)`를 호출하는 흐름은 제거한다.
- `modeling.configure`는 다른 호출부가 없는 것을 확인한 뒤 제거한다. 바로 제거하기 어렵다면 호환 함수로만 남기고 백엔드에서는 사용하지 않는다.

### 연결 확인

- 저장된 키를 복호화해 `modeling.check_connection`에 전달한다.
- 성공 여부, 확인 시각, 안전하게 줄인 안내 문구만 저장한다.
- Provider 원문 오류 응답은 화면이나 DB에 그대로 남기지 않는다.
- 연결 확인 실패는 키 저장 자체를 취소하지 않는다. 사용자가 키를 고쳐 저장할 수 있게 실패 상태를 보관한다.

## 데이터 구조

### `UserApiKey`

| 필드 | 형식 | 규칙 |
| --- | --- | --- |
| `id` | UUID | 기본 키 |
| `user_id` | UUID | `users.id`, 사용자 삭제 시 함께 삭제 |
| `provider` | 문자열 | 현재 `google`만 허용 |
| `encrypted_api_key` | Text | 암호화된 키 원문 |
| `last4` | 문자열 4자 | 화면 표시 전용 |
| `connection_status` | enum | `unchecked`, `connected`, `failed` |
| `connection_message` | 문자열 또는 null | 민감정보를 제거한 안내 문구 |
| `last_checked_at` | 시각 또는 null | 마지막 연결 확인 시각 |
| `created_at`, `updated_at` | 시각 | 공통 이력 |

제약:

- `user_id + provider` 고유 제약
- `encrypted_api_key`와 암호화 키는 API 응답에서 제외
- 키를 다시 저장하면 연결 상태를 `unchecked`로 초기화

## API 계약

### 사용자 설정 조회

`GET /api/settings`

응답:

```json
{
  "userProfile": {
    "userId": "uuid",
    "name": "사용자",
    "email": "user@example.com",
    "memo": null,
    "profileImage": null
  },
  "apiKeyStatus": {
    "hasApiKey": true,
    "provider": "google",
    "last4": "1234",
    "connectedStatus": "unchecked",
    "checkedAt": null,
    "message": null
  }
}
```

API 키 원문과 암호문은 반환하지 않는다.

### API 키 저장·갱신

`PUT /api/settings/api-keys/google`

요청:

```json
{ "apiKey": "사용자 입력 키" }
```

처리:

- 앞뒤 공백 제거
- 빈 값, 최대 길이, 허용 문자 기본 검증
- 암호화 후 사용자·Provider 기준으로 생성 또는 갱신
- 연결 상태를 `unchecked`로 변경

### API 키 삭제

`DELETE /api/settings/api-keys/google`

- 현재 사용자의 키만 삭제한다.
- 없는 키를 삭제하면 `API_KEY_NOT_FOUND`를 반환한다.
- 삭제 직후 키 등록 상태를 `false`로 반환한다.

### API 키 연결 확인

`POST /api/settings/api-keys/google/check`

- 현재 사용자의 저장된 키만 사용한다.
- 성공과 실패 모두 연결 결과 응답을 반환한다.
- 키 없음은 `API_KEY_NOT_REGISTERED` 오류로 구분한다.

### 사용자 정보 수정

기존 `PATCH /api/auth/me`를 재사용한다. 새 사용자 설정 API를 중복으로 만들지 않는다.

## 화면 동작

### 프로필 팝업

- 사이드바 하단 프로필을 누르면 연다.
- 아바타, 이름, 이메일을 표시한다.
- `사용자 정보`, `API 키 관리`, `피드백 남기기`, `로그아웃` 메뉴를 둔다.
- 이번 마일스톤에서 피드백 메뉴는 후속 마일스톤 안내 상태로 두지 않는다. 버튼 자체는 마일스톤 5에서 함께 추가한다.
- 바깥 클릭과 Escape로 닫는다.

### 사용자 정보 모달

- 이름·이메일·메모를 현재 값으로 채운다.
- 저장 중 중복 제출을 막는다.
- 이메일 형식·중복 등 오류는 모달 안에 표시한다.
- 성공하면 `authStore.user`와 사이드바 표시를 동시에 갱신하고 토스트는 마일스톤 5의 공통 기능 전까지 모달 내 완료 상태로 표시한다.

### API 키 모달

- 열 때마다 키 입력은 빈 값·가림 상태로 시작한다.
- 저장된 키가 있으면 `•••• 1234`와 연결 상태만 표시한다.
- 사용자가 새로 입력한 값만 보기·숨기기 할 수 있다.
- 저장 성공 후 입력 원문을 즉시 비운다.
- 삭제, 연결 확인, 처리 중, 성공, 실패 상태를 서로 구분한다.
- 키 미등록 오류에서 열면 안내 문구를 모달 안에 먼저 표시한다.

## 오류 코드

- `API_KEY_NOT_REGISTERED`: 저장된 사용자 키 없음
- `API_KEY_NOT_FOUND`: 삭제·조회 대상 키 없음
- `API_KEY_INVALID_FORMAT`: 기본 형식 검증 실패
- `API_KEY_ENCRYPTION_FAILED`: 암호화 실패
- `API_KEY_DECRYPTION_FAILED`: 복호화 실패
- `AI_PROVIDER_CONNECTION_FAILED`: Provider 연결 실패
- `PROVIDER_NOT_CONFIGURED`: 지원하지 않는 Provider

내부 복호화 오류와 Provider 원문 오류는 로그에만 안전하게 기록하고 사용자 응답에는 정리된 문구만 넣는다.
