# 0820_02 기본 채팅 경험 보완과 모델 공급자 교체

- 상태: 진행 중 — A·B·C 완료, D 남음
- 기준 커밋: `01fb80a`
- 앞선 조사: `docs/01_plan/0820_01_기능명세_추가_대조_조사.md`

## 배경

지금까지는 기능명세서를 기준으로 구현해 왔다. 그 결과 Context 편집·정제·브랜치 같은 FlowKit 고유 기능은 촘촘하게 만들어졌지만, 일반 챗봇이라면 당연히 있는 기본기가 비어 있다. 명세서에 "표를 그린다", "대화 이름을 바꾼다" 같은 항목이 없었기 때문이다.

코드로 확인한 대표적인 빈 곳은 다음과 같다.

- 답변에 표가 나오면 글자로 깨져 보인다. 마크다운 확장 기능이 꺼져 있다.
- 대화 이름을 바꿀 수 없다. 서버 기능과 화면 호출 함수는 있는데 부르는 버튼이 없다.
- 웹 검색을 켜도 무엇을 근거로 답했는지 화면에 나오지 않는다.
- 파일을 붙여 보내면 대화 기록에 그 파일이 남지 않는다.
- 고를 수 있는 모델이 하나뿐이다.

이 문서는 그 기본기를 채우는 작업과, 모델 공급자를 Gemini에서 GPT로 바꾸는 작업을 함께 다룬다.

## 목표

1. 일반 챗봇 수준의 기본 채팅 경험을 갖춘다.
2. 답변에 쓰는 모델을 GPT 계열(Sol · Terra · Luna)로 바꾸고, 세 모델 모두 같은 추론 단계를 고를 수 있게 한다.

## 마일스톤 C · 모델 공급자 교체 (Gemini → GPT)

**완료** — 커밋 `2470f0a`.

### C1. 모델 목록 교체

- [x] 고를 수 있는 모델을 아래 세 가지로 바꾼다
- [ ] 실제 키로 한 번씩 호출해 보고 값이 맞는지 확인한다 — **미검증**. 이 환경에는 OpenAI API 키가 없어 실제 호출로 모델 식별자·웹 검색·첨부 지원 여부를 확인하지 못했다. 사용자가 제공한 식별자를 그대로 등록했다.

| 화면 표시 이름 | API 모델 식별자 | 용도 | 기본 모델 |
| --- | --- | --- | --- |
| Sol | `gpt-5.6-sol` | 고품질·복잡한 작업 | |
| Terra | `gpt-5.6-terra` | 일반 채팅 기본 | ✅ |
| Luna | `gpt-5.6-luna` | 저비용·고속 | |

세 모델 모두 웹 검색과 파일 첨부(`input_file`)를 지원한다. `gpt-5.6`은 현재 Sol의 별칭이므로 모델 식별자로는 쓰지 않고, 위 표의 개별 이름을 그대로 쓴다.

Gemini는 모델 목록에서 완전히 뺀다.

### C2. 모델 클라이언트 교체

- [x] Gemini 연결 패키지를 GPT 연결 패키지로 바꾼다 — `langchain-google-genai` → `langchain-openai>=1.6,<2`
- [x] 답변 생성 호출을 Responses API 기준으로 만든다 — `ChatOpenAI(..., output_version="responses/v1")`
- [x] 백엔드와 모델링의 설치 목록을 함께 고친다
- [x] 예비 키를 읽는 환경변수 이름을 바꾼다 — `GOOGLE_API_KEY` → `OPENAI_API_KEY`. 백엔드는 이 환경변수를 쓰지 않아(사용자별 키만 사용) 별도 `.env.example` 항목은 없었다.

추론 단계는 사용자가 아직 고를 수 없으므로 `config.py`의 `DEFAULT_REASONING_EFFORT`("medium")로 고정해 모든 호출에 `reasoning={"effort": ...}`를 싣는다. 마일스톤 D에서 사용자 선택값으로 대체한다.

### C3. API 키 저장소 교체

- [x] 허용 공급자 값을 바꾼다 — `SUPPORTED_PROVIDER`: `"google"` → `"openai"`
- [x] 이미 저장된 Google 키는 지우지 않고 사용 중단 상태로 숨긴다 — 값만 바꿔서 `google` provider 레코드는 조회·삭제·연결확인 경로 모두에서 자연히 제외된다(DB에는 그대로 남는다)
- [x] API 키 관리 화면의 안내 문구와 발급 안내를 바꾼다 — "Google AI API 키" → "OpenAI API 키"

기존 Google 키 정리는 이번 마일스톤 범위가 아니다. 이후 별도 마이그레이션 작업에서 다룬다.

### C4. 웹 검색 도구 교체

- [x] GPT의 `web_search` 도구를 붙이는 방식으로 바꾼다
- [x] 검색을 지원하지 않는 모델을 막는 검사는 그대로 둔다

Gemini 내장 검색 도구 대신 OpenAI `web_search` 도구를 붙인다. 도구를 붙여 검색 결과를 답에 반영하게 한다는 명세 취지(AI-SEARCH-001)는 그대로 유지되고, 구현에 쓰는 도구만 바뀌었다. 명세 문서의 "Google 검색 도구" 표현도 "웹 검색 도구"로 고쳤다.

### C5. 검색 근거 추출 교체

- [x] GPT 응답의 자동 인라인 인용(`url_citation` annotation)에서 근거 자료를 꺼내는 방식으로 바꾼다
- [x] 같은 주소가 여러 번 인용되면 중복을 없앤다
- [x] 근거가 없어도 답변을 실패로 보지 않는 규칙은 그대로 둔다

Gemini의 grounding 구조 대신 GPT 응답 본문 블록의 `annotations` 를 읽는다. 근거를 뽑아 함께 돌려준다는 명세 취지(AI-SEARCH-002)는 유지되고, 읽는 응답 구조만 바뀌었다. 이 명세는 원래도 응답 구조를 특정하지 않고 provider 중립적으로 쓰여 있어 문서 수정은 필요 없었다.

### C6. 첨부 전달 방식 확인

- [x] 이미지 첨부가 그대로 전달되는지 확인한다 — 기존 `{"type": "image_url", "image_url": {"url": "data:..."}}` 형식을 langchain-openai 가 Responses API 의 `input_image` 로 자동 변환한다(라이브러리 소스로 확인). 코드 변경 없이 그대로 재사용
- [x] 문서 첨부의 글자 추출 방식은 그대로 둔다 — 변경 없음

### C7. 연결 확인 교체

- [x] API 키 연결 확인 요청을 GPT 기준으로 바꾼다
- [x] 실패 사유를 한 줄로 줄여 돌려주는 규칙은 그대로 둔다

**검증 결과**: 백엔드 자동 테스트 169개(기존 164 + 5), modeling 자동 테스트 42개, 프론트엔드 자동 테스트 43개, `tsc -b` 타입체크 모두 통과. langchain-openai 1.6.0 소스 코드를 직접 읽어 Responses API 호출 방식·웹 검색 도구·인용 구조·이미지 입력 변환을 확인했다.

**남은 제한 사항**:
- 실제 OpenAI API 키로 Sol·Terra·Luna 세 모델을 호출한 적은 없다. 모델 식별자(`gpt-5.6-sol/terra/luna`)와 웹 검색·첨부 지원 여부는 사용자가 제공한 값을 그대로 반영했을 뿐, 이 환경에서 직접 검증하지 못했다.
- 화면(API 키 모달·모델 선택기·검색 근거 표시)을 실제 브라우저에서 GPT 응답으로 띄워보지는 않았다. 자동 테스트와 코드 검토로만 확인했다.

## 마일스톤 D · 추론 단계 선택

이번에는 사용자가 단계를 고르고 그 값이 서버까지 전달·저장되는 데까지 만든다. 고른 단계를 실제 모델 호출에 반영하는 것은 다음 단계다.

### D1. 단계 정의

- [ ] `low` · `medium` · `high` · `xhigh` · `max` 다섯 단계를 정의한다
- [ ] 세 모델 모두 같은 다섯 단계를 지원한다
- [ ] 기본값은 `medium`으로 정한다

다섯 단계 이름은 GPT API가 실제로 받는 값과 동일하게 맞춘다. 화면에 보여줄 한글 이름은 이 다섯 값에 대응해 화면 작업 시 정한다.

### D2. 화면에서 고르기

- [ ] 입력창 도구 줄에 추론 단계 선택 버튼을 넣는다
- [ ] 고른 단계를 대화 안에서 유지한다

### D3. 값 전달과 저장

- [ ] 메시지 전송 요청에 추론 단계를 담는다
- [ ] 답변 생성 입력 구조에 추론 단계를 더한다
- [ ] 재생성할 때 처음과 같은 단계로 다시 만들도록 입력 스냅샷에 포함한다

재생성은 처음과 같은 조건이어야 두 답변을 버전으로 비교할 수 있다. 추론 단계도 그 조건에 들어간다.

### D4. 이번 범위 밖

- 고른 단계에 따라 실제 모델 호출 값을 바꾸는 처리

**마일스톤 D 완료 기준**: 화면에서 단계를 고르면 그 값이 서버 요청에 실려 가고, 답변 재생성 시 같은 단계가 복원된다. 모델 호출 결과는 아직 단계에 따라 달라지지 않는다.

## 기획 문서와 맞지 않는 부분

기획 문서를 현재 요구사항에 맞게 수정한다. 마일스톤 C를 실행하며 실제로 대조해 보니, AI-CORE-001~006과 AI-SEARCH-002는 애초에 특정 공급자를 명시하지 않고 `apiKey`·`modelId`·`provider` 같은 일반화된 표현으로 쓰여 있어 고칠 필요가 없었다. 실제로 고친 것은 AI-SEARCH-001의 "Google 검색 도구"라는 표현 하나뿐이다 → "웹 검색 도구"로 수정(이번 커밋에 포함).

| 명세 항목 | 상태 |
| --- | --- |
| AI-SEARCH-001 | 수정 완료. "Google 검색 도구" → "웹 검색 도구" |
| AI-SEARCH-002 · AI-CORE-001~006 | 수정 불필요. 이미 공급자 중립적으로 쓰여 있었다 |
| 3.5 전체(추론 단계 신설), BE-INPUT-005·006, BE-AIRESP-001, FE-INPUT 계열 | 아직 미수정. 마일스톤 D(추론 단계 선택)가 실제로 구현된 뒤에 반영한다 |

## 확정된 값

- **모델**: Sol(`gpt-5.6-sol`) · Terra(`gpt-5.6-terra`, 기본) · Luna(`gpt-5.6-luna`)
- **Gemini**: 모델 목록에서 제거
- **기존 Google API 키**: 삭제하지 않고 사용 중단 상태로 숨김. 정리는 별도 마이그레이션에서
- **추론 단계**: `low` · `medium` · `high` · `xhigh` · `max` 다섯 단계, 기본값 `medium`
- **웹 검색**: OpenAI `web_search` 도구 + 인라인 인용 + `sources`

## 남은 확인 사항

- 실제 API 키로 세 모델을 호출해, 위 식별자와 웹 검색·첨부 지원 여부가 문서 그대로인지 마지막으로 확인한다(C1 작업 항목).
- 추론 단계 다섯 값의 화면 표시용 한글 이름은 화면 작업(D2) 시점에 정한다.

## 작업 순서

```text
A (표시 품질)  →  B (기본 조작)  →  C (모델 교체)  →  D (추론 단계)
```

A·B·C·D 모두 착수에 필요한 확인이 끝났다. 순서대로 진행한다.

## 검증 방법

- 마일스톤마다 자동 테스트를 추가하고, 백엔드와 프론트 전체 테스트를 통과시킨다. 기준 상태는 백엔드 164개, 프론트 31개 통과다.
- 화면 동작은 실제 브라우저에서 직접 확인한다. 표 렌더링, 이름 변경, 붙여넣기 업로드, 근거 표시는 자동 테스트만으로는 확인이 어렵다.
- 모델 교체는 실제 API 키로 세 모델을 각각 호출해 확인한다. 검색을 켠 경우와 끈 경우, 이미지 첨부와 문서 첨부를 각각 시험한다.
- 마일스톤 단위로 커밋하고, 완료 후 이 문서에 결과를 반영한 뒤 `docs/02_result/`로 옮긴다.
