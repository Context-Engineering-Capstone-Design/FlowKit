# 0819_01 AI 파트 기능명세 구현

## 목표

AI 기능명세서(3.1~3.5)에 적혀 있으나 코드에 없는 기능을 모두 만든다. 작업 범위는 `modeling/` 패키지다. 백엔드와 프론트엔드는 다른 세션이 맡으므로 여기서는 고치지 않는다.

## 배경

사용자가 API 키를 직접 등록해 쓰는 구조로 가기로 결정했다. 이 결정에 따라 AI 기능명세서의 API 키 항목을 먼저 고치고, 그 위에서 나머지를 구현한다.

네 문서를 확인한 결과 요구사항정의서, BE 기능명세서, FE 기능명세서는 이미 사용자별 키 구조로 적혀 있었다. AI 기능명세서만 서버 공용 키를 전제로 하고 있어 이 문서만 고치면 된다.

BE와 FE 명세 모두 "시스템 공용 키를 쓰는 모델이면 검증을 생략한다"는 단서를 달고 있다. 그래서 AI 파트는 키가 누구 것인지 알 필요가 없고, 요청마다 키를 받기만 하면 두 경우를 모두 만족한다.

## 범위

### 1. 명세 수정 (AI 기능명세서 3.1)

| 항목 | 바꾸는 내용 |
| --- | --- |
| AI-CORE-003 | 클라이언트 재사용 기준에 API 키를 추가한다 |
| AI-CORE-004 | 서버 공용 키 전제를 요청별 사용자 키로 바꾼다 |
| AI-CORE-006 | 새로 추가한다. API 키 연결 확인(REQ-061, BE-USERSET-005) |

답변·정제·제목 생성 항목에는 `apiKey` 입력을 추가한다.

### 2. 구현

| 명세 | 만들 것 |
| --- | --- |
| AI-CORE-001 | 모델 목록 상수와 조회 함수 |
| AI-CORE-002 | 모델 선택값 검증과 확정 |
| AI-CORE-003 | 키·모델·옵션 조합으로 클라이언트 생성 |
| AI-CORE-004 | 요청별 키 확인 |
| AI-CORE-006 | 연결 확인 함수 |
| AI-SEARCH-001 | 모델 내장 Google 검색 도구 연결 |
| AI-SEARCH-002 | 검색 근거 목록 반환 |
| AI-ATTACH-001 | 이미지를 모델에 그대로 전달 |
| AI-ATTACH-002 | PDF·텍스트 파일에서 글자 추출 후 질문에 첨부 |
| AI-ATTACH-003 | 첨부 없는 요청은 기존 흐름 유지 |
| AI-ANSWER-003, 004 | 키·모델·검색 옵션·첨부를 입력으로 받도록 확장 |
| AI-REFINE-002 | 키·모델 선택값을 입력으로 받도록 확장 |
| AI-TITLE-001 | 키를 입력으로 받도록 확장 |

### 3. 확인한 라이브러리 사용법

설치된 `langchain-google-genai` 4.3.3 기준으로 직접 확인했다.

- 검색 도구 연결: `model.bind_tools([{"google_search": {}}])`
- 검색 근거 위치: 응답 메시지의 `response_metadata["grounding_metadata"]`, 그 안의 `grounding_chunks` 각 항목이 `web.title`과 `web.uri`를 가진다
- 이미지 입력: `{"type": "image_url", "image_url": {"url": "data:<mime>;base64,<데이터>"}}`

## 범위 밖

- 백엔드와 프론트엔드 수정. 사용자 키 저장소(`UserApiKey`), 첨부 저장소(`Attachment`), API 키 관리 화면은 각 파트가 맡는다.
- 답변 재생성 시 적용 Context 복원. 고칠 자리가 `backend/app/services/ai_response_service.py`라 백엔드 몫이다.
- 비기능 요구사항(NFR) 소실 건. 사용자 확인 대기 중이라 명세의 인용을 건드리지 않는다.

## 완료 기준

- 명세에 적힌 AI 항목이 모두 함수로 존재하고, 명세가 정한 입력과 출력을 지킨다.
- 첨부와 검색 옵션이 없는 기존 호출 방식이 그대로 동작한다.
- 기존 테스트가 모두 통과하고, 새 기능마다 테스트가 있다.

## 검증 방법

`modeling/tests/`에서 가짜 모델로 확인한다. 실제 API를 부르지 않으므로 키 없이 돌아간다.

- 모델 목록 조회, 없는 모델 선택 시 오류
- 키 없이 호출하면 오류, 키를 넘기면 통과
- 검색을 켠 요청과 끈 요청이 서로 다른 클라이언트를 쓰는지
- 검색 근거를 응답에서 뽑아내는지
- 이미지 첨부가 텍스트로 바뀌지 않고 그대로 실리는지
- 텍스트 파일에서 글자를 뽑아 질문 앞에 붙이는지
- 첨부가 없으면 기존과 같은 메시지가 만들어지는지

## 남는 제한

- **실제 모델 동작은 확인하지 못한다.** 테스트는 가짜 모델을 쓴다. 웹 검색과 이미지 인식이 실제로 되는지는 진짜 키로 따로 확인해야 한다.
- **모델 목록에 넣을 모델이 하나뿐이다.** 현재 확인된 모델은 `gemini-3.6-flash` 하나다. 목록 구조는 여러 개를 담을 수 있게 만들지만, 실제로 무엇을 더 넣을지는 사용자가 정해야 한다.
- **의존성이 하나 늘어난다.** PDF에서 글자를 뽑으려면 `pypdf`가 필요하다. 백엔드 가상환경에도 다시 설치해야 한다.
- **기존 `configure` 함수를 남긴다.** 백엔드가 서버 시작 시 이 함수를 부르고 있어, 지금 없애면 서버가 뜨지 않는다. 요청에 키가 없을 때만 쓰는 예비 값으로 남기고, 백엔드가 사용자 키를 넘기기 시작하면 그때 뺀다.
