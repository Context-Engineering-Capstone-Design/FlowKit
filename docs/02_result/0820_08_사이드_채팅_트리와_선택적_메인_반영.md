# 0820_08 사이드 채팅 트리와 선택적 메인 반영

- 상태: 계획
- 기준: 2026-08-20 논의
- 관련 기능: 채팅 탭, 브랜치, Context 관리

## 목표

부모 메인 채팅의 공통 컨텍스트를 활용하면서도, 별도 흐름으로 탐색할 수 있는 사이드 채팅을 제공한다. 사이드 채팅의 결과는 메인 채팅에 자동 반영하지 않고 사용자가 필요한 경우에만 반영한다.

## 확정된 구조

### 대화 세션과 탭

- 메인 채팅과 사이드 채팅은 모두 별도 탭으로 유지한다.
- 탭 구조에서는 메인·사이드 채팅이 동등한 대화 세션이다.
- 역할만 다르다. 메인 채팅은 공통 컨텍스트의 부모이고, 사이드 채팅은 부모 컨텍스트를 자동 참고하는 자식 대화다.
- 새 사이드 채팅을 열어도 기존 탭은 화면 위치를 바꾸지 않고 그대로 남긴다.
- 메인 채팅뿐 아니라 사이드 채팅도 자식 사이드 채팅을 만들 수 있다. 새 자식도 별도 탭으로 유지한다.
- 사용자가 삭제하기 전까지 사이드 채팅은 일반 채팅처럼 보존한다.

### 트리 관리

- 좌측 사이드 채팅 관리 패널에서 사이드 채팅의 생성 관계를 Git 브랜치 그래프처럼 보여준다.
- 그래프의 노드를 선택하면 해당 대화 세션 탭을 열거나 활성화한다.
- 각 사이드 채팅이 생성된 부모 대화 흐름의 시점에는 저장·불러오기 버튼을 제공한다. 사용자는 부모 대화를 따라가며 그 시점에서 연결된 사이드 채팅을 찾을 수 있다.
- 사이드 채팅에서 만든 자식은 그래프에서 해당 사이드 채팅 아래에 연결한다.

### 컨텍스트와 대화 흐름

- 새 사이드 채팅은 부모 메인 채팅 전체를 자동으로 참고한다.
- 사이드 채팅 생성 시에는 부모의 최신 대화 흐름 전체를 시작 맥락으로 사용하고, 그 생성 시점을 부모 대화 안에 기록한다.
- 부모 메인 채팅에 새 메시지가 추가되면, 자식 사이드 채팅도 새 내용을 자동 참고한다.
- 사이드 채팅은 공통 컨텍스트와 별도로 자신만의 대화 흐름을 가진다.
- 사이드 채팅에서 자식 사이드 채팅을 만들더라도, 자식은 루트 메인 채팅의 공통 컨텍스트만 자동 참고한다. 부모 사이드 채팅의 메시지·답변은 자동 참고하지 않는다.
- 따라서 사이드 채팅끼리는 부모·자식 관계여도 서로의 메시지나 답변을 자동 참고하지 않는다.
- 과거 사이드 답변이 생성된 당시의 컨텍스트 스냅샷은 저장하지 않는다.

### 메인 채팅 반영

- 사이드 채팅은 기본적으로 메인 채팅을 변경하지 않는다.
- 사용자는 사이드 채팅의 결과를 선택해 다음 작업을 실행할 수 있다.
  - 답변 일부 또는 전체를 Context로 추가
  - 질문·답변을 메인 채팅 메시지로 가져오기
  - 새 브랜치 생성
- 사이드 채팅에서 새 브랜치를 만들면, 해당 브랜치는 사이드 채팅과 같은 부모 아래의 형제 브랜치로 생성한다. 기존 부모와 자식 관계를 공유한다.

## 범위

### 마일스톤 A · 세션 관계와 저장 구조

- [ ] A1. 일반 채팅·사이드 채팅을 공통 대화 세션으로 표현하고, 사이드 채팅에 직접 부모와 루트 메인 채팅 관계를 저장한다.
- [ ] A2. 부모·자식·형제 관계를 조회할 수 있는 API와 서비스 로직을 만든다.
- [ ] A3. 메인·사이드 채팅 어디에서든 자식 사이드 채팅을 생성하고, 이름 변경·삭제·조회할 수 있게 한다.
- [ ] A4. 부모 메인 채팅에 새 메시지가 추가될 때, 자식 사이드 채팅이 최신 부모 흐름을 답변 입력에 포함하도록 조립한다.

### 마일스톤 B · 탭과 트리 화면

- [ ] B1. 메인·사이드 채팅을 같은 방식으로 여닫고 전환할 수 있는 탭 상태를 만든다.
- [ ] B2. 메인·사이드 채팅의 우측 패널에서 새 자식 사이드 채팅을 열고, 기존 사이드 채팅 탭으로 전환할 수 있게 한다.
- [ ] B3. 좌측 관리 패널에 부모·자식 관계를 보이는 그래프와 노드 선택 동작을 만든다.
- [ ] B4. 부모 대화의 사이드 채팅 생성 시점에 저장·불러오기 버튼을 표시하고, 그 지점에서 연결된 사이드 채팅을 열고 관리한다.

### 마일스톤 C · 선택적 메인 반영

- [ ] C1. 사이드 답변 일부 또는 전체를 기존 Context 추가 흐름으로 넘긴다.
- [ ] C2. 사이드 채팅의 질문·답변을 메인 채팅 메시지로 가져오는 흐름을 만든다.
- [ ] C3. 사이드 채팅 기준으로 새 브랜치를 만들되, 부모 아래의 형제 브랜치로 연결한다.
- [ ] C4. 반영 전에는 메인 채팅의 메시지·Context·브랜치를 바꾸지 않는지 보장한다.

### 마일스톤 D · 검증

- [ ] D1. 메인·사이드 채팅에서의 자식 생성, 생성·삭제, 형제 브랜치 생성, 최신 루트 메인 메시지 자동 참고를 백엔드 테스트로 검증한다.
- [ ] D2. 탭 전환, 부모 대화 안의 생성 시점 접근 UI, 트리 노드 선택, 삭제 후 화면 상태를 프론트엔드 테스트로 검증한다.
- [ ] D3. Context 추가·메시지 가져오기·브랜치 생성이 사용자의 명시적 실행 뒤에만 일어나는지 검증한다.
- [ ] D4. 브라우저에서 메인 채팅 1개와 여러 사이드 채팅의 생성·탭 전환·부모 메시지 추가·선택 반영 흐름을 확인한다.

## 구현 범위 밖

- 사이드 채팅끼리의 자동 Context 공유
- 모든 대화 세션 사이의 Context 공유
- 답변 생성 당시 컨텍스트 스냅샷 저장·재현
- 사이드 채팅의 자동 삭제 또는 Temporary Chat 방식

## 완료 기준

- 사용자가 메인 또는 사이드 채팅에서 여러 단계의 사이드 채팅을 만들고 탭으로 전환할 수 있다.
- 사용자는 부모 대화 흐름의 생성 시점 또는 좌측 브랜치 트리 그래프에서 원하는 사이드 채팅을 찾고 열 수 있다.
- 부모 메인 채팅의 최신 메시지가 모든 자식 사이드 채팅의 답변 입력에 자동 반영된다.
- 사이드 채팅끼리는 서로의 흐름을 입력에 포함하지 않는다.
- Context 추가·메시지 가져오기·새 브랜치 생성은 사용자가 선택했을 때만 메인 작업에 반영된다.

## 검증 방법

- `cd backend && .venv/bin/pytest`
- `cd frontend && npx vitest run`
- `cd frontend && npx tsc --noEmit && npm run lint && npm run build`
- 브라우저에서 탭·트리·부모 메시지 자동 참고·세 가지 반영 작업을 확인한다.
