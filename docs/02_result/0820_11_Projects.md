## 제한 사항

- Library 자료는 현재 제목·본문·선택 URL 형태의 텍스트 자료다. 파일 업로드형 Library는 별도 구현이 필요하다.

## 목표

여러 대화와 Library 자료를 하나의 작업 공간으로 묶고, 프로젝트 전용 지침을 해당 작업의 모든 대화에 자동 적용한다.

## 구조

```text
Project
  ├─ 프로젝트 지침
  ├─ 프로젝트 전용 메모리
  ├─ Library 자료
  └─ 메인 대화
       └─ 브랜치 / 사이드 채팅 트리
```

- 대화는 하나의 Project에만 속한다.
- Project 밖의 대화는 나중에 하나의 Project로 이동할 수 있다.
- Project 내부의 메인 대화·브랜치·사이드 채팅은 모두 해당 Project에 속한다.
- Temporary Chat도 Project 안에서 만들면 실행 중 프로젝트 지침을 적용한다.

## 지침 우선순위

```text
일반 사용자 지침
  < 프로젝트 지침
  < 개별 대화의 Context
  < 현재 사용자 요청
```

- 프로젝트 지침은 해당 Project의 모든 대화에 자동 적용한다.
- 현재 사용자의 명시적 요청은 프로젝트 지침보다 우선한다.

## 프로젝트 전용 메모리

- 프로젝트 전용 메모리는 해당 Project에서만 쓰는 작업 사실을 저장한다.
- 예: 확정된 기획 결정, 프로젝트 용어, 반복해서 참고할 제약 조건이다.
- 메모리는 제목·분류·태그 없이 본문 형태로만 저장한다.
- 사용자는 Project 설정의 `메모리` 탭에서만 메모리를 추가·수정·삭제한다.
- 각 대화 화면에는 프로젝트 전용 메모리의 추가·수정 UI를 제공하지 않는다.
- AI는 메모리를 자동 저장하거나 후보를 제안하지 않는다.
- 등록된 모든 메모리는 해당 Project의 모든 소속 대화에 자동 적용한다.
- Project 밖 대화와 다른 Project에는 해당 메모리를 전달하지 않는다.
- Project를 삭제하면 프로젝트 전용 메모리도 함께 삭제한다.

## 과거 채팅 참고와 Library

- 과거 채팅 참고는 필요할 때만 검색한다.
- 검색 범위는 기본적으로 본인의 모든 대화다. Project 안팎으로 자동 제한하지 않는다.
- Library 자료는 Project에 연결한다.
- 연결된 Library 자료는 필요할 때 해당 대화의 후보 Context로 쓸 수 있다.
- 후보 자료 전체를 매번 AI 입력에 자동으로 넣지 않는다. 실제 답변에는 선택된 자료만 전달한다.

## 삭제 규칙

- Project를 삭제하면 Project 내부의 모든 대화와 연결된 Library 자료를 함께 삭제한다.
- 메인 대화, 브랜치, 일반 사이드 채팅, Temporary Chat의 실행 중 자료를 모두 삭제 범위로 처리한다.
- 삭제 뒤에는 해당 대화와 자료를 검색·과거 채팅 참고·Library에서 다시 찾을 수 없다.

## 완료 기준

- 사용자가 Project를 만들고 대화·Library 자료를 연결할 수 있다.
- 모든 소속 대화에 Project 지침이 자동 적용된다.
- 모든 소속 대화에 등록된 Project 전용 메모리가 자동 적용된다.
- Project 전용 메모리는 Project 설정의 메모리 탭에서만 본문 형태로 관리한다.
- 대화는 하나의 Project에만 속하고, Project 밖 대화는 나중에 이동할 수 있다.
- 과거 채팅 참고는 필요할 때 본인의 전체 대화 범위에서만 검색된다.
- Project 삭제 시 내부 대화와 연결 자료가 함께 삭제된다.
