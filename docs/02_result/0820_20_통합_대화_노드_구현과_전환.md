# 0820_20 통합 대화 노드 구현과 전환

## 목표

`통합 대화 노드 전환 명세`를 실제 서비스에 적용한다. 새 대화 흐름은 모두 Chat 노드로 만들고, 기존 Branch는 한 릴리스 동안 내부 호환 식별자로만 유지한다.

## 범위

1. Chat에 출발 노드·출발 메시지·스냅샷 정보를 추가하고, 기존 Child Branch를 Chat 노드로 일괄 전환한다.
2. 새 분기 API는 현재 노드의 부모 아래에 `분기 N` 노드를 만들고, 출발 메시지까지의 흐름을 복제해 고정한다.
3. 기존 `branchId` 주소는 읽기 호환으로 유지한다. 신규 화면은 대화 노드만 사용한다.
4. 노드 삭제는 하위 노드까지 함께 지우며, 전환 검증·백업 안내·기획 문서를 갱신한다.

## 완료 기준

- [x] 분기 노드가 지정한 부모 위치와 고정된 출발 흐름을 가진다.
- [x] 기존 Child Branch가 메시지·작업 참조를 보존한 Chat 노드가 된다.
- [x] 좌측 트리와 AI 응답 하단 분기 버튼이 통합 노드 API를 사용한다.
- [x] 기존 Branch 조회는 한 릴리스 동안 새 노드 내용을 읽을 수 있다.
- [x] 백엔드·프론트 테스트와 빌드를 통과한다.

## 검증 방법

- 서비스 단위 테스트로 분기 위치, 스냅샷 독립성, 하위 노드 삭제, 기존 Branch 전환을 확인한다.
- API 테스트로 새 노드 생성과 기존 `branchId` 조회 호환을 확인한다.
- 프론트 테스트와 production build로 트리·분기 동작 연결을 확인한다.

## 구현 결과

**기준 커밋:** `e03adc7`

- `POST /api/chats/{chatId}/nodes`가 AI 응답 지점에서 `분기 N` 노드를 만들고, 현재 노드의 부모 아래에 둔다.
- 출발 메시지의 활성 버전을 새 노드 전용 Main 흐름으로 복제한다. 이후 원본 노드의 추가·수정은 AI 입력에 섞이지 않는다.
- Alembic `a82020nodes`가 기존 Child Branch를 새 Chat 노드로 전환한다. 기존 Branch 행과 `branch_id` 참조는 새 노드의 내부 Main 흐름으로 보존한다.
- 기존 `branchId` 상세 조회는 한 릴리스 동안 이동된 노드를 읽는다.
- 좌측 `대화 구조`는 Branch 목록을 제거하고 Chat 노드 트리만 표시한다.

## QA 후속 수정 (2026-08-21)

`0820_19` QA 진행 중 사용자가 실제 브라우저(제 QA 세션과 별개)에서 첫 메시지 전송 시 `AI_JOB_NOT_FOUND`가 반복되는 문제를 보고해 원인을 찾아 고쳤다.

- 기준 커밋: `48b8340` (`fix(chat): 전송 버튼 더블클릭 시 채팅이 두 번 생성되던 레이스를 고친다`)
- **증상**: 새 채팅에서 첫 메시지를 보내면 `.../ai-response-jobs/{jobId}/stream` 요청이 404 `AI_JOB_NOT_FOUND`로 실패했다. "다시 시도"를 눌러도 같은 job id로 재요청해 같은 오류가 반복됐다.
- **원인**: DB로 직접 확인해보니, 거의 동시(61ms 간격)에 서로 다른 두 채팅·브랜치가 만들어져 있었다. `chatStore.sendMessage`는 채팅이 없을 때 새로 만드는데, 이 생성 과정이 끝나기 전까지 `isSending`이 `true`로 설정되지 않아 전송 버튼이 비활성화되지 않았다. 그 틈에 전송이 한 번 더 겹치면(더블클릭 등) `createChat()`이 두 번 호출돼 채팅이 두 개 생기고, 실제 메시지·job은 나중에 만들어진 채팅에 저장되는데 화면 상태(store의 `chatId`/`branchId`)는 먼저 만들어진 채팅을 가리켜, 그 상태로 스트림을 열면 `job.chat_id`가 안 맞아 못 찾는다.
- **수정**: `sendMessage` 맨 앞에서 `isSending`이 이미 `true`면 즉시 반환하고, 새 채팅 생성 전에 `isSending`을 먼저 `true`로 설정한다. 이후 조기 반환 경로에도 `isSending: false`를 맞춰줬다.
- **재검증**: Chrome에서 전송 버튼을 더블클릭해도 채팅이 하나만 생성되고 스트림이 정상적으로 붙는 것을 확인했다(`POST /api/chats`가 한 번만 호출됨). `npx vitest run`(142 passed), `npx tsc --noEmit`, `npm run build` 재통과.
