## 재현한 문제

- A 학습 대화의 재생성·재시도·중단 응답이 늦으면, B 대화 또는 다른 노드의 같은 블록 ID·오류·전송 상태를 바꿀 수 있었다.
- A로 다시 들어온 뒤 이미 완료된 최신 답변도 늦은 빈 `generating` 초기 응답으로 되돌아가고 스트림이 다시 연결될 수 있었다.
- A 작업이 진행 중일 때 재진입하면 진행 상태가 사라질 수 있었고, 재시도 버튼을 중복 실행할 여지가 있었다.

## 구현

- 전송·재생성·재시도·중단을 `chatId + branchId`별 작업 순서와 진행 상태로 관리했다.
- 늦은 성공·실패·정리 단계는 시작한 대화·노드가 현재일 때만 화면 상태를 바꾼다.
- 재진입 조회 중 백그라운드 작업이 끝나면 최신 서버 상태를 한 번 더 읽는다.
- 스트림 연결을 대화·노드·블록·작업 ID 기준으로 분리했다. 이전 작업의 완료 이벤트와 중단 응답은 새 작업을 덮지 않는다.
- 같은 버전이 이미 완료·실패·중단 상태이면 늦은 `generating` 초기 응답과 재연결을 건너뛴다.
- 답변 재시도 중에는 실패 질문의 재시도 버튼을 비활성화했다.

## 제한 사항

- 운영 대화의 실제 전송·재생성·재시도·중단은 데이터 변경을 피하기 위해 실행하지 않았다.
