## 목표

AI 담당자의 독립적인 모델링 작업을 허용하면서도, 실제 백엔드 실행 환경에서 모델링 의존성이 누락되지 않도록 개발·실행 환경의 경계를 명확히 한다. 프론트엔드의 구현 규칙도 함께 보강한다.

## 결정 사항

### 1. AI 가상환경 분리

| 환경 | 용도 | 설치 의존성 |
| --- | --- | --- |
| `backend/.venv` | 실제 서버 실행 | 백엔드와 모델링 의존성 전체 |
| `modeling/.venv` | 모델링 단독 개발·테스트 | 모델링 의존성 |

- `modeling/`은 별도 서버가 아니라 백엔드가 직접 import하는 Python 패키지다.
- AI 담당자는 DB·백엔드 없이 `modeling/.venv`에서 프롬프트와 체인을 단독 실행·테스트할 수 있다.
- 실제 서버 실행 시에는 `backend/.venv`에 `modeling/requirements.txt`까지 설치해야 한다.
- 모델링 의존성 버전을 변경하면 백엔드 환경에도 다시 설치해야 한다. 두 환경의 동일 패키지 버전이 달라 단독 테스트만 통과하고 서버가 실패하는 상황을 방지하기 위한 규칙이다.

### 2. 프론트엔드 규약 보강

- Vite·React·TypeScript·Tailwind 기반 프론트엔드 생성 완료 상태를 진행표에 반영했다.
- import 경로는 `@/` 별칭으로 통일했다.
- UI 색상은 직접 지정하지 않고 `src/index.css`의 토큰을 사용하도록 정했다.
- React 19, Vite 8, TypeScript 6, Tailwind 4의 실제 설치 버전은 `frontend/package.json`과 `package-lock.json`을 기준으로 관리한다.

### 3. 토큰 재발급 보호 규칙

- refresh token은 재발급 시 교체되고 기존 토큰은 폐기된다.
- 동시에 만료된 요청이 각각 재발급을 시도하면 폐기된 토큰을 다시 보내 전체 세션이 종료될 수 있다.
- `frontend/src/api/client.ts`의 단일 재발급 처리 구조를 인증 코드 변경 시 유지하도록 명시했다.

## 완료 기준

- 모델링 단독 개발 환경과 백엔드 실행 환경의 목적이 구분돼 있다.
- 서버 실행에 필요한 모델링 의존성 설치 절차가 명시돼 있다.
- 프론트엔드 별칭·색상·패키지 버전·토큰 재발급 규칙이 문서화돼 있다.
