## 목표

사용자가 채팅을 생성·조회·검색하고, 특정 메시지 지점에서 대화 흐름을 보존한 채 새 브랜치를 만들 수 있도록 한다.

## 구현 항목

### 1. 채팅 관리 (BE-CHAT-001~008)

- 새 채팅 생성 시 Main 브랜치를 동일 트랜잭션으로 생성하고 초기 화면 상태를 반환한다.
- 최근 활동 순 채팅 목록, 제목 검색, 커서 기반 페이지네이션을 구현했다.
- AI 생성 제목을 저장할 때 빈값, 길이 초과, 제어문자를 검증한다.
- 채팅 상세 조회 시 기본적으로 Main 브랜치를 열고, 지정된 브랜치도 조회할 수 있다.
- 채팅이 없을 때는 `404`, 다른 사용자의 채팅일 때는 `403`을 반환하도록 접근 권한 검증을 공통화했다.

### 2. 브랜치 관리 (BE-BRANCH-001~006)

- 브랜치 목록 및 브랜치 전환 API를 구현했다.
- 메시지를 복사하지 않는 참조형 브랜치를 구현했다. 조회 시 조상 브랜치를 분기점까지 거슬러 올라가 대화 흐름을 구성하므로 원본 대화가 보존된다.
- 브랜치 생성 시 분기점과 선택 Context 블록이 기준 브랜치에서 실제로 보이는지 검증한다.
- 출발 Context 참조를 저장하고, 원본 메시지로 이동하기 위한 `scrollTargetIndex`를 계산해 반환한다.

### 3. 페이지네이션 안정성

- 채팅 목록 정렬용 활동 시각을 애플리케이션에서 채우도록 변경했다.
- SQLite의 초 단위 기본 시각으로 여러 채팅이 같은 시각을 갖는 경우, 커서 페이지네이션이 중복 항목을 반복 반환할 수 있는 문제를 방지했다.

## 테스트 범위

추가된 테스트는 다음 동작을 다룬다.

- 인증된 채팅 생성과 초기 Main 브랜치 상태
- 사용자별 채팅 목록 분리, 제목 검색, 커서 페이지네이션
- 제목 입력값 검증과 채팅 접근 권한
- 참조형 브랜치 생성, 분기점까지의 상속 흐름, 원본 대화 보존
- 중첩 브랜치 및 출발 Context 정보

이 커밋의 Git 기록에는 테스트 실행 결과가 포함되지 않는다. 따라서 당시 테스트 성공 여부는 이 문서에서 주장하지 않는다.

## 완료 기준

- 사용자가 자신의 채팅을 생성·조회·검색할 수 있다.
- 선택한 분기점과 Context를 기반으로 브랜치를 만들 수 있다.
- 브랜치 생성이 원본 메시지를 복제하거나 변경하지 않는다.
- 목록 페이지네이션이 중복 없이 다음 페이지로 진행된다.
