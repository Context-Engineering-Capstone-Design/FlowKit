## 목표

프론트엔드에서 Google Identity Services 로그인 버튼을 제공하고, 받은 ID 토큰을 기존 백엔드 인증 API로 전달한다. 팀원이 필요한 OAuth 설정을 재현할 수 있도록 안내 문서를 추가한다.

## 구현 내용

### 1. Google 공식 로그인 버튼

- Google Identity Services 스크립트를 동적으로 불러온다.
- 스크립트 로딩 Promise를 재사용해 중복 로드를 방지한다.
- Google이 제공하는 공식 버튼을 한국어·검은색·알약형 스타일로 렌더링한다.
- 로그인 성공 시 전달받은 ID 토큰을 인증 상태 저장소의 `loginWithGoogle()`에 넘긴다.
- 스크립트 로드 실패 시 로그인 화면에 오류를 표시한다.

### 2. 인증 흐름 연결

1. 사용자가 Google 로그인 버튼을 누른다.
2. Google이 브라우저에 ID 토큰을 반환한다.
3. 프론트엔드가 토큰을 백엔드 인증 API에 전달한다.
4. 백엔드가 Google 공개 키로 토큰을 검증한다(BE-AUTH-002).
5. 검증에 성공하면 FlowKit 토큰과 사용자 정보를 받아 작업 화면으로 진입한다.

### 3. 설정값과 미설정 안내

- `frontend/.env.example`에 `VITE_GOOGLE_CLIENT_ID`를 추가했다.
- 프론트엔드와 백엔드는 동일한 Google OAuth 클라이언트 ID를 각각 `VITE_GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_ID`에 설정해야 한다.
- 클라이언트 ID가 없으면 버튼 대신 필요한 환경 변수와 설정 위치를 안내한다.
- Vite와 백엔드 모두 시작 시 환경 변수를 읽으므로, 값 변경 뒤 서버 재시작이 필요하다.

### 4. 팀 설정 가이드

- Google Cloud 프로젝트 생성, OAuth 동의 화면 설정, 테스트 사용자 등록, 웹 OAuth 클라이언트 ID 발급 절차를 문서화했다.
- 로컬 개발 원본으로 `http://localhost:5173`, `http://127.0.0.1:5173` 등록 방법을 안내한다.
- 허용되지 않은 origin, 테스트 사용자 누락, 토큰 오류 등 대표 오류의 원인과 조치 방법을 정리했다.
- 배포 시 승인된 JavaScript 원본 추가와 OAuth 동의 화면 게시 필요성을 명시했다.

## 검증 범위

- 커밋 변경 내역과 소스 구조를 기준으로 Google ID 토큰 전달 경로와 미설정 처리 흐름을 확인했다.
- Git 기록에는 OAuth 클라이언트 ID 발급, 브라우저 로그인 성공, 백엔드 토큰 검증의 실행 결과가 남아 있지 않다.
- 실제 로그인은 Google Cloud Console 설정, 테스트 사용자 등록, 프론트·백엔드 환경 변수 일치 후 별도 확인이 필요하다.

## 완료 기준

- 클라이언트 ID가 설정되면 공식 Google 버튼으로 ID 토큰을 받아 기존 인증 API에 전달할 수 있다.
- 클라이언트 ID가 없거나 스크립트를 불러오지 못하면 사용자가 원인을 알 수 있다.
- 팀원이 OAuth 클라이언트 ID를 발급하고 로컬 개발 환경에 적용할 수 있다.
