## 목표

대화를 수정·정제·재생성 가능한 메시지 블록과 버전 이력으로 관리하고, 참조형 브랜치에서도 원본 대화의 불변성을 보장한다.

## 구현 항목

### 1. 블록 생성과 순서

- 사용자 질문과 AI 답변을 `MessageBlock`으로 저장한다.
- 블록 생성 시 최초 `MessageBlockVersion`을 함께 만들고 활성 버전 포인터를 연결한다.
- 브랜치에 상속된 블록까지 고려해 다음 `order_index`를 계산한다. 상속 블록과 새 블록의 순번이 겹쳐 화면 순서가 뒤엉키는 문제를 방지한다.
- 빈 내용과 길이 초과 내용을 검증한다.

### 2. 수정과 불변 버전 이력

- 블록 수정은 기존 본문을 덮어쓰지 않고 새 버전을 추가한다.
- 정제 승인과 AI 답변 재생성도 같은 새 버전 추가 경로를 공유하도록 설계했다.
- 활성 버전만 `current_version_id`로 교체하며, 이전 버전은 삭제하지 않는다.
- 되돌리기는 기존 버전을 다시 활성화하는 방식으로 처리한다.

### 3. 선택·조회·활성 버전 API

- 선택한 블록을 실행 요청 시점에 검증하고 유효·무효 ID를 나눠 반환한다.
- 블록별 버전 이력을 조회할 수 있다.
- 특정 버전을 활성 버전으로 변경할 수 있다.
- AI 입력용 활성 메시지 흐름을 서버의 현재 활성 버전 기준으로 구성한다.

### 4. 참조형 브랜치 보호

- 하위 브랜치에서 상속받은 블록은 읽기와 버전 이력 조회만 허용한다.
- 상속 블록의 수정·활성 버전 변경은 막는다. 상속 블록은 조상 브랜치가 소유하므로 변경하면 원본 대화까지 바뀌기 때문이다.
- 하위 브랜치에서 분기점 이후 원본 블록은 보이지 않는 것으로 처리한다.

## 완료 기준

- 메시지 블록의 생성·수정·버전 조회·활성 버전 변경이 가능하다.
- 수정·정제·재생성에서 기존 버전 이력이 삭제되지 않는다.
- 참조형 브랜치에서 원본 메시지를 변경할 수 없다.
- AI 입력이 현재 활성 버전의 대화 흐름을 사용한다.
