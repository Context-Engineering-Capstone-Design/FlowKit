## 목표

생성된 `modeling` 패키지를 백엔드 개발환경에 일관되게 설치하고, 모델링 코드·의존성·백엔드 연동 상태를 팀이 혼동하지 않도록 규약과 진행표를 갱신한다.

## 반영 내용

### 1. 편집 가능 설치

- 백엔드 환경에서는 `pip install -e ../modeling`으로 `modeling` 패키지를 설치하도록 정했다.
- 편집 가능 설치이므로 모델링 소스 코드를 수정하면 재설치 없이 백엔드에 반영된다.
- 경로를 임의로 추가하지 않아도 `import modeling`을 사용할 수 있다.

### 2. 의존성 동기화

- `modeling/pyproject.toml`을 패키지 의존성의 기준으로 삼는다.
- `modeling/requirements.txt`는 모델링 단독 작업용 사본으로 함께 관리한다.
- 의존성 목록을 변경하면 백엔드 가상환경에도 다시 설치해야 한다. 모델링 단독 환경과 백엔드 실행 환경의 패키지 버전이 달라지는 문제를 방지하기 위한 규칙이다.
- LangChain 1.x와 LangGraph 1.x 범위로 버전 상한을 명시했다.

### 3. 실행·테스트 절차

- 모델링만 작업하는 경우 `pip install -e .` 후 `pytest tests/ -q`로 테스트한다.
- 모델링 단위 테스트는 실제 API 호출을 하지 않으므로 Gemini API 키 없이 실행할 수 있다.
- 실제 서버 실행 시에는 백엔드 가상환경에 편집 가능 설치가 필요하다.

### 4. 진행 상태 명확화

- 모델링 패키지와 정제·제목·답변 체인 생성은 완료로 표시했다.
- 이 시점에는 체인이 백엔드 기능에 아직 연결되지 않았음을 명시했다.
- 모델은 Gemini 2.5 Flash를 기준으로 정제와 제목 생성에 사용하도록 기록했다.

## 완료 기준

- 백엔드 환경에서 `modeling`을 편집 가능 패키지로 설치하는 방법이 명시돼 있다.
- 모델링 의존성 변경 시 필요한 동기화 절차가 명시돼 있다.
- 모델링 패키지 생성 완료와 백엔드 미연동 상태가 구분돼 있다.
