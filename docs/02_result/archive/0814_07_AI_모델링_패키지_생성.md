## 목표

백엔드가 직접 호출할 수 있고, DB·백엔드 없이도 단독 개발·테스트할 수 있는 AI 모델링 패키지를 만든다.

## 구현 항목

### 1. 설치 가능한 모델링 패키지

- `modeling/`을 Python 패키지로 구성하고 `pyproject.toml`을 추가했다.
- 백엔드 가상환경에서 `pip install -e ../modeling`으로 설치해 직접 import하도록 구성했다.
- DB 모델에 의존하지 않고 `types.py`의 데이터 구조만 주고받도록 분리했다.

### 2. AI 체인

| 기능 | 함수 | 관련 명세 |
| --- | --- | --- |
| 블록별 정제 | `refine_blocks()` | BE-REFINE-002 |
| 채팅 제목 생성 | `generate_title()` | BE-CHAT-004 |
| 답변 생성 | `generate_answer()` | BE-AIRESP-001 |

- 프롬프트 문안을 `prompts/`로 분리해 체인 코드를 바꾸지 않고 문안을 수정할 수 있게 했다.
- Gemini 기반 LLM 클라이언트를 추가하고, API 키가 없을 때 명시적 오류를 반환하도록 구성했다.
- LangChain 계열 의존성에 버전 상한을 두어 팀원별 메이저 버전 차이로 인한 실행 불일치를 줄였다.

### 3. 블록별 정제 정합성

- 여러 메시지 블록을 하나의 AI 응답으로 묶지 않고, 블록별 입력과 결과를 일대일로 유지했다.
- 결과의 `block_id`가 원본 블록과 어긋나 다른 블록에 정제 결과가 반영되는 위험을 방지한다.
- 호출은 배치 처리하되, 각 입력과 출력의 순서를 엄격히 대응시킨다.

### 4. 제목·답변 입력 처리

- 제목 생성 결과에서 따옴표, 줄바꿈, 끝 마침표를 정리하고 최대 길이로 제한한다.
- 답변 생성 시 대화 흐름을 역할 순서대로 구성한다.
- 적용된 Context가 있으면 시스템 메시지에 포함해 우선 참고하도록 구성한다.

## 테스트 범위

테스트는 실제 Gemini API를 호출하지 않고 가짜 모델을 사용한다.

- 정제 결과와 원본 블록 ID의 대응
- 공백·빈 입력 처리
- 제목 정리와 길이 제한
- 대화 역할 순서와 적용 Context의 프롬프트 반영
- 답변 출력 공백 정리

Git 기록에는 테스트 실행 결과가 포함되지 않으므로, 당시 테스트 성공 여부는 이 문서에서 주장하지 않는다. 실제 답변 품질은 API 키를 이용한 별도 검증이 필요하다.

## 완료 기준

- 백엔드가 모델링 패키지를 직접 import할 수 있다.
- 정제·제목·답변 생성 체인이 독립 데이터 구조를 통해 동작한다.
- 실제 API 키 없이 프롬프트 조립과 결과 매핑을 테스트할 수 있다.
