## 목표

팀원이 서로 다른 로컬 환경에서 개발하더라도 의존성, 실행 방식, API 규약 차이로 통합이 깨지지 않도록 공통 개발환경을 정한다.

## 결정 사항

### 1. 애플리케이션 구조

- 프론트엔드는 `frontend/`에서 별도 프로세스로 실행하고, 백엔드와 HTTP로 통신한다.
- 백엔드와 `modeling/`은 별도 서버로 분리하지 않는다. 백엔드가 모델링 패키지를 직접 import한다.
- 따라서 Python 가상환경은 `backend/.venv` 하나를 백엔드와 모델링이 공유한다.

### 2. 기술과 버전 기준

| 영역 | 기준 |
| --- | --- |
| 프론트엔드 | React + TypeScript + Vite + Tailwind CSS |
| 상태 관리 | Zustand |
| HTTP 클라이언트 | axios |
| AI 모델링 | LangChain + LangGraph + Gemini |
| Node.js | 26.x |
| npm | 11.x |
| Python | 3.14.x |
| PostgreSQL | 16.x |

패키지 매니저는 npm으로 통일하며, 프론트엔드 의존성은 `package-lock.json` 기준으로 관리한다.

### 3. 코드와 API 규약

- 프론트엔드는 `api/`, `components/`, `store/`, `types/` 구조를 따른다.
- API 응답 필드는 camelCase로 사용한다.
- 백엔드는 `models/`, `schemas/`, `services/`, `routers/`, `core/` 구조를 따른다.
- 비즈니스 로직은 `services/`에 두고, 라우터는 요청·응답 연결에 집중한다.
- 오류 응답은 `app/exceptions.py`의 공통 형식을 사용한다.
- 비밀값은 `.env`에만 저장하며, 새 환경변수는 `.env.example`에도 빈 값으로 추가한다.

### 4. 실행·온보딩 절차

- PostgreSQL을 Homebrew 또는 Docker Compose로 실행한다.
- 백엔드 가상환경에 `backend/requirements.txt`와 `modeling/requirements.txt`를 함께 설치한다.
- Alembic 마이그레이션 적용 후 FastAPI를 실행한다.
- 프론트엔드는 npm 설치 후 Vite 개발 서버로 실행한다.
- 필수 환경변수는 DB 접속 정보, JWT 비밀값, Google OAuth 클라이언트 ID, Gemini API 키, 프론트엔드 API 주소다.
