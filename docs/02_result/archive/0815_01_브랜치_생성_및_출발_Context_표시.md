# 브랜치 생성 및 출발 Context 표시

- 상태: 구현 완료

## 목표

대화의 특정 블록에서 새 브랜치를 만들고, 해당 브랜치가 어떤 Context를 기반으로 시작됐는지 사용자가 추적할 수 있게 한다.

## 구현 내용

### 1. 브랜치 생성 모달

- 대화 영역 헤더에 브랜치 생성 버튼을 추가했다.
- 브랜치 이름 입력과 네 가지 추천 이름을 제공한다.
- 현재 대화 블록 중 분기 지점을 선택할 수 있으며, 기본값은 마지막 블록이다.
- 화면에서 선택한 블록은 출발 Context 후보에 기본으로 포함된다.
- 생성 중 상태와 이름·분기 지점 미입력 상태에서는 생성 버튼을 비활성화한다.

### 2. 유효한 Context만 선택

- 분기 지점 뒤의 블록은 새 브랜치에 존재하지 않으므로 Context 후보에서 제외한다.
- 제출 직전에도 현재 분기 지점까지 존재하는 블록만 다시 걸러 API에 전달한다.
- 서버에서 거부할 수 있는 Context 조합을 클라이언트에서 예방한다.

### 3. 생성 후 브랜치 이동

- 브랜치 생성 API 호출 뒤 대화의 브랜치 목록을 새로 조회한다.
- 생성된 브랜치로 즉시 전환해 사용자가 현재 작업 위치를 알 수 있게 했다.
- 생성 실패는 기존 오류 상태에 저장하고 모달은 유지한다.

### 4. 출발 Context 배너

- 메인 브랜치를 제외한 브랜치에서 출발 Context가 있으면 대화 상단에 배너를 표시한다.
- 배너에는 현재 브랜치 이름, Context 개수, 각 Context의 미리보기 pill을 표시한다.
- pill을 누르면 원본 블록이 있는 브랜치로 이동하고 해당 블록까지 부드럽게 스크롤한다.
- 이동한 원본 블록은 2초 동안 강조 표시한다.

### 5. Markdown 미리보기 공통화

- Context·브랜치 목록용 `toPreview()` 함수를 분리했다.
- 코드 블록과 Markdown 기호를 제거해 한 줄 미리보기에서 원문 기호가 노출되지 않게 했다.

## 검증 범위

- 커밋 변경 내역과 상태 흐름을 기준으로 브랜치 생성·전환, Context 필터링, 원본 이동 동작을 확인했다.
- Git 기록에는 프론트엔드 빌드·린트, 브라우저 상호작용, 백엔드 브랜치 API 연동의 실행 결과가 남아 있지 않다.
- 실제 동작은 메시지 블록이 있는 대화에서 브랜치를 생성하고, Context pill을 눌러 원본 이동을 별도 확인해야 한다.

## 완료 기준

- 사용자가 분기 지점과 출발 Context를 정해 브랜치를 생성할 수 있다.
- 새 브랜치에 없는 블록은 출발 Context로 선택할 수 없다.
- 브랜치 진입 후 출발 Context와 원본 블록 위치를 확인할 수 있다.
