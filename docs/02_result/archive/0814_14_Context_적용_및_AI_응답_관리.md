## 목표

선택한 Context를 서버 기준으로 확정해 AI 답변에 적용하고, 질문 저장부터 답변 생성·저장·재생성까지의 대화 흐름을 하나의 API로 제공한다.

## 구현 항목

### 1. Context 적용 스냅샷

- 화면이 보낸 본문을 신뢰하지 않고, 서버가 선택 블록의 현재 활성 버전을 읽어 Context를 확정한다.
- 선택된 블록은 중복을 제거하고 대화 순서대로 정렬한다.
- 블록·버전·본문·순번을 Context 스냅샷으로 구성하고, 실제 사용 이력을 저장한다.
- 승인되지 않은 정제본은 활성 버전이 아니므로 Context에 포함되지 않는다.
- 브랜치에 보이지 않는 블록과 최대 30개 초과 Context를 검증해 거절한다.

### 2. Context와 일반 대화의 분리

- Context를 선택한 전송에서는 선택 Context만 모델에 전달하고 이전 대화 흐름은 제외한다.
- Context 없이 전송하면 기존 대화 흐름을 유지한다.
- 실제 호출에서 선택 Context와 최근 대화를 함께 전달했을 때 최근 대화가 선택 주제를 덮는 현상이 확인돼, 사용자가 고르지 않은 내용은 제외하는 규칙(NFR-011)을 적용했다.
- Context 지시는 블록을 선택한 경우에만 프롬프트에 포함한다. 일반 질문에서 Context 부재를 이유로 모델이 답변을 거부하는 문제를 방지한다.

### 3. 메시지 전송과 AI 답변 저장

- 한 요청 안에서 사용자 질문 저장, 적용 Context 로그 저장, AI 답변 생성, assistant 블록 저장을 순서대로 처리한다.
- 방금 보낸 질문이 이전 대화 흐름에 중복으로 포함되지 않도록, 사용자 블록 생성 전에 기존 흐름을 읽는다.
- AI 답변 생성 실패 시에도 사용자가 입력한 질문은 보존한다.
- 첫 질문이면 채팅 제목을 자동 생성한다. 제목 생성 실패는 대화 흐름을 실패시키지 않는다.

### 4. 답변 재생성

- assistant 블록만 재생성할 수 있다.
- 재생성 결과는 새 블록을 만들지 않고 기존 assistant 블록의 새 버전으로 추가한다.
- 재생성 시 해당 답변 직전의 사용자 질문과 그 이전 흐름을 사용한다.
- 기존 답변은 버전 이력에 남고, 버전 이동으로 이전 답변을 다시 활성화할 수 있다.

## 테스트 범위

- 질문·답변 저장과 메시지 순서
- 질문 중복 없이 기존 대화 흐름 전달
- 선택 Context 전달, 이전 흐름 제외, Context 없는 일반 대화 유지
- 서버 현재 활성 버전 사용, Context 순서 정렬·중복 제거·브랜치 범위 검증
- 미승인 정제본 제외
- 첫 질문 제목 생성과 제목 생성 실패 시 대화 유지
- assistant 답변 재생성, 버전 이력 보존, 이전 버전 복귀
- 다른 사용자의 메시지 전송 차단

Git 기록에는 테스트 실행 결과가 포함되지 않는다. 커밋 설명의 실제 호출 검증은 Context 입력 구성 규칙을 확인한 근거이며, 전체 통합 환경 검증과는 구분한다.

## 완료 기준

- 적용 Context가 서버의 활성 버전 기준으로 확정되고 사용 이력이 남는다.
- 선택 Context가 있을 때 선택하지 않은 이전 대화는 모델 입력에서 제외된다.
- 질문 저장, 답변 생성·저장, 제목 생성, 재생성이 일관된 버전 정책으로 동작한다.
- AI 실패와 제목 실패가 사용자 질문 또는 대화 흐름을 불필요하게 잃게 하지 않는다.
