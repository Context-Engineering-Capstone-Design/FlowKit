## 목표

사용자가 선택한 메시지 블록을 자연어 지시로 정제하고, 원본과 정제본을 비교한 뒤 승인한 결과만 새 버전으로 적용할 수 있게 한다.

## 구현 항목

### 1. 정제 작업과 기준 스냅샷

- 선택 블록과 편집 지시를 검증해 정제 작업을 생성한다.
- 실행 시점의 각 블록 활성 버전·본문·역할·순번을 `BlockRefineTarget`으로 고정한다.
- 정제가 진행되는 동안 원본 블록이 수정돼도 정제 기준과 원본·정제본 비교 기준이 바뀌지 않는다.
- 지시문은 빈값, 최대 2,000자, 한 작업당 최대 20개 블록을 검증한다.

### 2. AI 정제 결과 정합성

- 모델링 패키지에 블록별 정제를 요청한다.
- AI 결과의 블록 ID 집합이 요청 블록 ID 집합과 정확히 일치하는지 확인한다.
- 결과 누락, 다른 블록 ID, 빈 정제 결과가 있으면 저장하지 않고 정제 작업을 실패 처리한다.
- 이 검증으로 사용자가 A 블록에 대해 승인한 결과가 B 블록에 반영되는 위험을 막는다.

### 3. 정제 결과 검토와 반영

- 정제 결과를 `pending` 상태로 저장하고, 원본·정제본·상태·기준 버전을 조회한다.
- 개별 승인 시 정제 본문을 새 메시지 버전으로 추가하고 활성 포인터를 이동한다.
- 기존 원본은 버전 이력에 남으며, 되돌리기는 기존 버전 활성화로 처리한다.
- 개별 거절은 원본 활성 버전을 변경하지 않는다.

### 4. 일괄 처리와 정리

- 일괄 승인·거절을 지원한다.
- 일괄 처리에서 일부 항목이 실패해도 다른 대기 결과는 계속 처리하고 실패 항목을 분리해 반환한다.
- 패널 종료 시 남은 `pending` 결과를 `rejected`로 정리한다.
- 이미 승인된 결과는 정리 작업이 되돌리지 않는다.

### 5. 접근 권한

- 정제 작업과 결과가 현재 채팅·브랜치에 속하는지 검증한다.
- 다른 채팅의 작업은 찾을 수 없는 것으로 처리한다.
- 다른 사용자는 해당 채팅에서 정제를 실행할 수 없다.

## 테스트와 실제 API 검증

테스트는 가짜 AI를 사용해 다음을 검증한다.

- 정제 작업 생성, 블록별 pending 결과, 원본 순서 유지
- 원본 변경 전까지 정제 결과가 대화에 반영되지 않는지 확인
- 빈 지시·빈 선택·브랜치 밖 블록·AI 실패·결과 불일치 처리
- 개별·일괄 승인과 거절, 버전 이력 보존, 버전 기반 되돌리기
- 미승인 정리와 작업·사용자 접근 권한

커밋 설명에 따라 실제 Gemini 호출로 정제, 승인, 거절, 버전 이력 보존도 확인했다.

## 완료 기준

- 선택 블록의 정제 기준이 실행 시점 버전으로 고정된다.
- AI 결과가 요청 블록과 일대일로 대응할 때만 저장된다.
- 승인된 정제본만 새 활성 버전으로 반영되고 원본 이력은 보존된다.
- 거절·미승인 정리는 원본 대화를 변경하지 않는다.
