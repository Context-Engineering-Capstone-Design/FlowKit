# 학습 답변 정제 승인·거절 QA

## 목표

Transformer 학습 답변의 일부를 골라 정제 지시를 적용하고, 원문 비교와 승인·거절 흐름을 실제 브라우저에서 검증한다.

## 범위

- 답변 안의 문장 범위를 드래그해 정제 진입점을 확인
- 학습 맥락의 정제 지시를 보내고 생성 상태와 비교 화면 확인
- 정제본 승인 또는 거절 뒤 원문·버전·후속 동작 상태 확인
- 재현된 코드 오류만 수정하고 자동 테스트와 브라우저 재검증 수행

## 완료 기준

- 선택부터 정제 결과 처리까지의 사용자 화면 결과를 기록한다.
- 수정이 필요하면 코드·테스트를 별도 커밋한다.
- 결과 문서를 `docs/02_result/`로 이관한다.

## 검증 방법

- 로컬 외부 브라우저에서 Self-Attention·Multi-Head Attention 학습 내용을 사용한다.
- 운영 데이터 삭제, 권한·비밀값, 외부 결제·계정 설정은 바꾸지 않는다.

## 실행 결과

### 브라우저 흐름

- Project 안의 새 대화에서 Multi-Head Attention의 여러 헤드 역할을 묻고 학습 답변을 만들었다.
- 답변 안의 `각 헤드가 서로 다른 관계를 학습한다` 범위를 드래그하자 `채팅에 추가`, `블록 정제`, `사이드 채팅에 질문` 메뉴가 나타났다.
- `블록 정제`는 선택 범위가 속한 전체 AI 블록을 Context 편집 패널의 정제 대상으로 열었다.
- Q·K·V 변환과 헤드 결합을 연결해 달라는 지시로 정제 결과를 만들었다. 원본과 정제본 비교, 대기 상태, 개별 승인 버튼이 모두 표시됐다.
- 승인 후 정제본이 답변 `v2`로 반영됐고, 패널을 닫은 뒤 다른 탭을 거쳐 다시 열어도 같은 `v2`와 `2/2` 버전 이력이 유지됐다.
- 이어서 한 문장 요약 정제를 만들고 거절했다. `거절됨` 상태와 알림이 표시됐으며, 패널을 닫은 뒤 승인된 `v2` 본문과 버전 수가 그대로 남았다.
- 브라우저 오류 로그는 없었고, 정제 생성·승인·거절·정리 API가 모두 성공 응답을 반환했다.

### 변경 사항

- 재현된 구현 오류는 없었다. 코드 변경과 코드 커밋은 만들지 않았다.

### 검증 결과

- `npm test -- src/components/ContextPanel.test.tsx src/components/MessageBlockItem.test.tsx src/store/chatStore.test.ts`: 85개 통과.
- `.venv/bin/pytest tests/test_refine.py`: 24개 통과.

### 남은 제한 사항

- 실제 모델 실패를 만들기 위해 외부 키·공급자 설정을 바꾸지는 않았다. 실패 상태와 재시도 처리는 자동 테스트 범위에서만 확인했다.
