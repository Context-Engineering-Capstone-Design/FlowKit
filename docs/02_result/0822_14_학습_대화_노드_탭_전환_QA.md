# 학습 대화 노드·탭 전환 QA

## 결과

빠른 대화·레거시 브랜치·초안 전환에서 늦은 응답이 마지막 화면을 덮는 문제와, 탭을 닫은 뒤 키보드 초점·패널 라벨이 끊기는 문제를 수정했다.

기준 코드 커밋: `4db4908` (`fix(navigation): preserve latest view state`)

## 확인된 사항과 문제

- 화면의 `분기`는 과거의 선택 목록이 아니라 독립 대화 노드로 바뀐 현재 설계다. 레거시 Branch 선택 UI를 복구할 결함은 아니었다.
- 대화 A·B 또는 레거시 브랜치 B·C를 빠르게 전환하면 늦게 끝난 이전 상세·평가 응답이 제목, 블록, 활성 탭, 평가를 덮을 수 있었다.
- 대화 상세를 불러오는 중 새 초안·기존 초안 탭으로 이동하거나, 불러오는 배경 탭을 닫아도 늦은 응답이 이전 대화를 다시 열 수 있었다.
- 탭 닫기 뒤 다음 탭 또는 Context 편집으로 초점이 복귀하지 않거나, 사용자가 이미 다른 탭·입력창을 선택했는데 이전 비동기 작업이 초점을 다시 가져갈 수 있었다.
- 탭이 하나여서 탭 바를 숨기면 현재 `tabpanel`의 `aria-labelledby`가 존재하지 않는 탭을 가리켰다.

## 구현

- 대화·브랜치·초안 화면 전환에 공통 요청 세대를 두고, 늦은 상세·오류·평가 응답을 무시하게 했다.
- Project 새 대화 생성, 새 초안, 초안 탭, 세션 초기화, 열리는 배경 탭 닫기도 같은 화면 전환 보호를 사용하게 했다.
- 탭 닫기 뒤 다음·이전 탭, Context 탭, 현재 패널의 Context 편집 버튼 순서로 초점을 복구했다. 닫기 취소와 이후 사용자 선택은 유지한다.
- 마지막 사이드 패널 탭을 닫아 패널이 사라질 때는 메인 패널의 Context 편집 버튼으로 초점을 넘긴다.
- Context 편집을 연 채 마지막 대화 탭을 닫아도 Context 탭을 남기고, 한 탭 상태의 대화 패널에는 대화 제목을 직접 라벨로 제공했다.
- 전환·초점·패널 라벨 회귀 테스트를 추가했다.

## 검증

- 로컬 외부 브라우저에서 기존 Self-Attention 학습 대화의 우측 `분기 3` 노드로 탭 화살표 이동과 Context 편집 열기·닫기를 확인했다. 원래 선택 노드로 정상 복귀했다.
- 브라우저에서 메인 패널의 고정 Context 초점 대상을 확인했고 오류 로그는 없었다.
- 탭 닫기는 기존 운영 대화나 임시 대화를 삭제하지 않기 위해 브라우저에서 실행하지 않았고, 자동 회귀 테스트로 검증했다.
- 대상 테스트: chatStore·ChatTabBar·ChatPane 74개 통과.
- 프런트엔드 전체 테스트: 28개 파일, 201개 통과.
- 린트와 프로덕션 빌드 통과. 기존 린트 경고와 번들 크기 경고는 남아 있으며 이번 변경으로 새 오류는 없었다.

## 제한 사항

- `sendMessage`·첫 채팅 생성, 노드·사이드 채팅 생성, 재생성·스트리밍 완료의 늦은 결과는 다음 QA 범위다.
- 새 대화·노드 생성, 대화 삭제, 운영 데이터 삭제, 권한·비밀값, 결제·계정 설정은 실행하거나 변경하지 않았다.
