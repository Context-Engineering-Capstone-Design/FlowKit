# 웹 검색 학습 답변 회귀 QA

## 목표

트랜스포머 학습 질문에서 웹 검색 모드, 출처 표시, 답변 재시도 흐름을 실제 브라우저로 검증한다.

## 범위

- 웹 검색 모드를 항상 사용으로 바꾼 뒤 학습 질문 전송
- 답변 생성 상태와 출처 표시 확인
- 답변 다시 시도와 오류 표시 확인
- 재현된 코드 오류만 수정하고 관련 자동 테스트와 브라우저 재검증 수행

## 완료 기준

- 검색 사용 답변의 사용자 화면 결과를 기록한다.
- 수정이 필요하면 코드·테스트를 별도 커밋한다.
- 결과 문서를 `docs/02_result/`로 이관한다.

## 검증 방법

- 로컬 외부 브라우저와 FlashAttention·Transformer 학습 질문을 사용한다.
- 운영 설정·비밀값·사용자 데이터를 바꾸지 않는다.

## 실행 결과

### 웹 검색 학습 답변

- Project 안의 새 대화에서 웹 검색을 `항상`으로 바꾼 뒤 FlashAttention의 Self-Attention 메모리 병목 완화 과정을 질문했다.
- 첫 답변은 FlashAttention 논문 출처를, 다시 생성한 두 번째 답변은 논문과 공식 구현 저장소 출처를 각각 화면의 참고 자료로 표시했다.
- 두 답변 모두 타일링, SRAM, 온라인 Softmax와 정확한 Attention 결과 유지라는 핵심을 일관되게 설명했다.

### 발견·수정

- 긴 대화에서 대화 목차 레일이 메시지 동작 도구막대의 가장 왼쪽 버튼을 덮었다. 따라서 다시 생성된 답변의 `이전 버전`과 버전 없는 답변의 첫 `좋아요`를 마우스로 누를 수 없었다.
- 버튼 중심의 실제 hit-test가 버튼 대신 `대화 목차` nav를 반환하는 것으로 재현했다.
- 도구막대를 목차보다 앞 레이어로 올렸다. 기준 코드 커밋은 `965a855` (`fix(actions): keep message actions above outline`)이다.
- 변경 경로: `frontend/src/components/MessageBlockActions.tsx`, `frontend/src/components/MessageBlockItem.test.tsx`.

### 검증 결과

- 외부 브라우저에서 `이전 버전`과 `다음 버전` 마우스 클릭이 각각 버전 전환 API를 호출하고 `1/2`·`2/2` 화면을 왕복하는 것을 확인했다.
- 버전 없는 긴 Transformer 답변의 첫 `좋아요`도 마우스로 눌러 선택 상태와 피드백 API 호출을 확인했다.
- 목차 항목 클릭은 대화 아래쪽에서 첫 질문 위치로 정상 이동했다.
- 브라우저 오류 로그는 없었다.
- `npm test -- src/store/chatStore.test.ts src/components/MessageBlockItem.test.tsx src/components/ConversationOutline.test.tsx src/components/WebSearchToggle.test.tsx`: 89개 통과.
- `npm run lint`: 종료 코드 0. 기존 React 관련 경고만 남았다.
- `npm run build`: 통과.

### 남은 제한 사항

- 실제 모델·검색 공급자 실패를 만들기 위해 운영 설정이나 비밀값을 바꾸지는 않았다. 전송 실패 상태는 `chatStore` 자동 테스트로 확인했고, 실제 브라우저에서는 성공 재시도 흐름만 검증했다.
