## 구현 전 정책 판단

### 1. BE-AIRESP-001 — Context와 이전 대화 흐름

우선 제안은 현행 동작 유지다.

- Context를 골랐을 때는 선택하지 않은 최근 대화가 답변을 끌고 가지 않도록 이전 흐름을 제외한다.
- 기존 코드, 회귀 테스트, 0814_14 결과 문서의 실제 호출 결과가 이 정책을 전제로 한다.
- 사용자가 이 안을 확정하면 코드는 유지하고, 별도 승인을 받아 BE 기능명세 2.8의 “결합” 문구를 실제 규칙에 맞게 수정한다.
- 사용자가 “결합”을 선택하면 ai_response_service.py와 관련 테스트를 바꾸고, Context가 최근 대화에 눌리지 않는지 모델 호출 검증을 추가한다.

### 2. BE-AIRESP-003 — 레거시 답변

우선 제안은 복원 불가능한 재생성 차단이다.

- AIResponseJob이 있는 답변은 저장된 입력 스냅샷을 그대로 사용한다.
- 작업 기록이 없는 답변은 원래 질문·대화 흐름과 일부 Context·첨부를 찾을 수 있어도 당시 모델과 웹 검색 여부를 확정할 수 없다.
- 원래 조건을 알 수 없는 답변을 기본 모델·검색 끔으로 조용히 재생성하지 않는다.
- 레거시 답변에는 AI_INPUT_SNAPSHOT_NOT_FOUND를 반환하고, 기존 답변과 버전은 유지한다.
- 구현 전에 실제 DB의 작업 없는 AI 답변 수를 읽기 전용으로 확인한다. 데이터가 있으면 차단 정책의 사용자 영향을 다시 보고한다.

## 구현 결과

- API 재생성 응답에 검색 근거를 추가하고, 첫 질문 재시도 성공 시 제목 생성을 수행한다.
- 작업 스냅샷이 없는 레거시 답변은 기본 모델·검색 끔으로 재생성하지 않고 AI_INPUT_SNAPSHOT_NOT_FOUND를 반환한다.
- 출발 Context 응답과 pill에 원본 블록 역할(User·AI)을 표시한다.
- 첨부 형식·MIME·빈 파일·10 MiB 초과를 업로드 전에 검증하고, 검색어를 trim한다.
- Google·개발 로그인 401은 세션 재발급을 시도하지 않도록 분리했다.

브라우저에서 localhost:5173 로컬 로그인과 작업 화면 진입은 확인했다. 127.0.0.1:5173은 백엔드 허용 Origin과 달라 연결 오류가 재현됐다. 파일 선택을 실제 전송하는 브라우저 검증과 Context·검색·로그인 실패 화면의 직접 재현은 자동 테스트로 대체했으며, 후속 브라우저 확인 대상이다.

## 위험과 제한

- 프론트엔드의 사전 검증은 사용성 개선이며 백엔드 검증을 대체하지 않는다. 두 기준이 달라지지 않도록 테스트에 허용 형식과 크기를 고정한다.
