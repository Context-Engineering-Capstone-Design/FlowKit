# 학습 Context·사이드 대화 비동기 전환 QA

## 결과

- 기준 코드 커밋: `95fc959` (`fix: guard context and side chat async transitions`)
- Context 범위 전송 시 렌더된 Markdown 오프셋과 원문 오프셋을 구분했다. 원문 위치가 검증된 경우에만 오프셋을 전송하고, 그렇지 않으면 서버가 고유한 스니펫만 찾도록 했다.
- 같은 문구가 원문에 둘 이상이면 임의의 첫 위치를 Context로 쓰지 않고 검증 오류로 막았다.
- 생성 중인 답변을 사이드 대화·대화 노드의 기준점으로 선택하지 못하게 했다. 생성 중인 빈 답변이 자식 흐름에 고정되는 경로를 차단했다.
- 사이드 대화 생성, 분기 생성, 부모 반영, 메시지 수정·버전 조회, 탭 전환·삭제의 늦은 응답이 다른 세션·채팅·브랜치·탭 상태를 덮지 않게 했다.
- 실시간 활동 조회는 각 열린 패널에서 최신 요청만 반영하며, 사이드 대화 메시지 가져오기도 부모 브랜치와 목록 갱신 신호를 발행한다.
- AI 생성 시작 신호는 작업·메시지 커밋 뒤에 발행하도록 옮겼다.

## 제한 사항

- Markdown 서식 경계를 가로지르는 선택은 원문 위치를 정확히 계산할 수 없을 수 있다. 같은 스니펫이 원문에 여러 번 있으면 잘못된 Context 대신 검증 오류가 표시된다.
- 부모 반영 저장소/API 동작은 검증했지만, 현재 화면에는 해당 동작을 직접 실행하는 UI 진입점이 없다.
