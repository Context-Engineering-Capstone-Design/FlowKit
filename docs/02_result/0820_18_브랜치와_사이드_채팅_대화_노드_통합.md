# 0820_18 브랜치와 사이드 채팅 대화 노드 통합 결과

## 목표

기존 브랜치와 사이드 채팅을 하나의 대화 노드 트리로 통합한다. 현재 노드에서 분기하면 새 노드는 현재 노드의 자식이 아니라 **현재 노드와 같은 부모 아래의 이웃 노드**로 만든다.

```text
메인 대화
├─ 원래 흐름
└─ 사이드 대화 A
   ├─ 사이드 대화 B
   └─ 분기 대화 C     ← B에서 분기, B의 부모인 A 아래에 생성
```

## 현재 구조와 마이그레이션 범위

- `branches`는 상속 체인(`parent_branch_id`, `base_message_block_id`)과 메시지 블록 소유 관계를 가진다.
- `chats`의 사이드 채팅은 구조적 부모·루트·분기 지점 참조를 가진다.
- AI 작업, 정제 작업, Context 로그, 메시지 블록, 출발 Context도 `branch_id`를 참조한다.

따라서 브랜치 행만 사이드 채팅으로 바꾸면 안 된다. 기존 참조를 새 대화 노드와 대화 흐름 식별자로 옮기거나, 전환 기간 동안 호환 계층을 둬야 한다.

## 제안 데이터 구조

- `ConversationNode` 개념을 `chats`에 통합한다. 메인·일반 노드·Temporary 노드는 모두 같은 트리 구조를 쓴다.
- 각 노드는 `parent_chat_id`, `root_chat_id`, `forked_from_chat_id`, `forked_from_message_block_id`를 가진다.
- 분기 노드는 원본 노드의 지정 시점까지를 읽기 전용 출발 흐름으로 참조하고, 이후 메시지는 새 노드에만 저장한다.
- 노드가 참조하는 출발 흐름은 생성 시점의 메시지 버전·Context 스냅샷으로 고정한다. 부모에 나중에 추가한 메시지를 자동으로 섞지 않는다.
- Temporary는 노드 속성으로 유지하며, 깊이와 무관하게 사용자가 선택한다.

## 마이그레이션 단계

1. 새 노드·출발 흐름·노드별 메시지 소유 모델과 읽기 API를 추가한다. 기존 브랜치 API는 읽기 전용 호환 상태로 유지한다.
2. 사전 점검으로 모든 Branch·MessageBlock·AI 작업·정제 작업·Context 로그·출발 Context 참조 수를 기록한다.
3. 채팅의 Main Branch를 루트 노드로 연결하고, 각 Child Branch를 새 대화 노드로 만든다. 부모 Branch 관계는 새 노드의 부모 관계와 분기 지점으로 변환한다.
4. 각 기존 참조의 `branch_id`를 새 노드의 흐름 식별자로 이전한다. 이전 전후 행 수·소유자·메시지 순서·버전 ID를 비교한다.
5. 새 API·화면을 노드 트리 기준으로 전환한다. 이전 API는 일정 기간 읽기 호환만 제공한다.
6. 실제 데이터 복사 전 백업을 만들고, 스테이징 복원·전환·되돌리기 리허설을 수행한다. 검증 뒤에만 Branch 테이블·호환 코드를 제거한다.

- [ ] 스테이징 데이터 전환·롤백 리허설은 사용자 지시로 생략했다.

## 확정 결정사항

1. **분기 출발 흐름**: 생성 시점의 스냅샷으로 고정한다.
2. **분기 노드 위치**: 현재 노드의 부모 아래에 만든다. 예를 들어 `메인 → A → B`에서 B를 분기하면 새 노드의 부모는 A다. 메인에서 분기하면 메인이 부모다.
3. **기존 `branchId` API·링크**: 한 릴리스 동안 읽기 호환을 둔다.
4. **기존 Branch 데이터**: 백업 뒤 한 릴리스 동안 보관한다.
5. **삭제 규칙**: 명시적 전체 삭제 확인 뒤 하위 노드도 함께 삭제한다. 자동 승격은 하지 않는다.
6. **일반 노드의 자동 참고**: 생성 시점 스냅샷만 참고한다.
7. **노드 이름**: `분기 N`으로 자동 생성하고 이후 이름 변경을 허용한다.
8. **전환 방식**: 지금 점검 시간에 일괄 전환한다. 구·신 구조 병행은 하지 않는다.

## 구현 결과

**기준 커밋:** `e03adc7`

- `chats`에 출발 노드·메시지·기존 Branch 식별자를 추가하고, Alembic `a82020nodes`가 기존 Child Branch를 대화 노드로 전환한다.
- `POST /api/chats/{chatId}/nodes`가 지정 지점까지의 메시지를 새 노드의 Main 흐름으로 복제한다. `메인 → A → B`에서 B를 분기하면 새 노드는 A 아래에 놓인다.
- 기존 Branch 행과 `branch_id` 참조를 새 노드의 Main 흐름으로 유지해 AI 작업·정제 작업·Context 로그의 소유 관계를 보존한다.
- 좌측 대화 구조와 AI 응답의 분기 동작은 통합 대화 노드 API를 사용한다. 하위 노드 삭제와 Temporary 노드 수명도 Chat 트리 기준으로 처리한다.
