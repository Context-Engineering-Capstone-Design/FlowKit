# 0819_09 기능명세 대조 미구현 조사

- 상태: 조사 완료 (후속 마일스톤 계획 전 단계)
- 기준 커밋: `8c432dacbc36067115d8fec1e837c8c9a4277946`
- 참고: 조사 시점 작업 트리에 커밋되지 않은 변경이 다수 있었다. 그중 `MessageBlockActions.tsx`, `MessageEditForm.tsx`, `frontend/src/lib/authExpiration.ts` 등은 `0819_06`·`0819_07` 계획 문서가 다루는 파일과 겹친다. 즉 두 계획 문서는 아직 "구현 전"으로 표시되어 있지만 실제 코드는 상당 부분 만들어져 커밋 대기 중인 상태였다. 이 조사는 커밋 여부와 무관하게 디스크에 있는 코드 기준으로 확인했다.

## 목표

`기획 문서/AI기능명세서`, `BE기능명세서`, `FE기능명세서`에 적힌 기능을 실제 코드와 하나씩 대조해서, 명세에는 있지만 코드가 없거나(미구현), 코드는 있지만 명세와 다르게 동작하는 항목을 찾아 정리한다. 이 문서 자체는 구현 계획이 아니라 다음 마일스톤들을 만들기 위한 밑조사 결과다.

## 범위

- AI 파트: `modeling/`, `backend/app/services/`의 AI 응답·정제·제목 생성·입력 보조 관련 코드
- BE 파트: `backend/app/` 전체 (라우터·서비스·모델·스키마)
- FE 파트: `frontend/src/` 전체 (컴포넌트·스토어·API·훅)
- 이미 있는 계획 문서(`docs/01_plan/0819_06`, `0819_07`)와 결과 문서(`docs/02_result/0819_01~08`)를 먼저 읽고, 이미 알려진 항목과 새로 발견한 항목을 구분했다.

## 조사 방법

명세 문서별로 기능 ID 단위(예: AI-ANSWER-004, BE-BRANCH-004, FE-CTXEDIT-004)로 다음을 확인했다.

1. 코드에 해당 기능이 있는지
2. 있다면 명세가 요구하는 입출력·예외 처리·상태 유지 규칙과 실제 동작이 같은지
3. 상태를 "미구현" / "부분 구현" / "명세와 다르게 동작" / "구현됨"으로 분류하고, "구현됨"은 이 문서에 싣지 않았다

세 파트를 각각 별도로 조사했기 때문에, 한 문제가 FE·BE 양쪽에 걸쳐 있으면 두 절에 나눠 적었다.

## AI 파트

### 사전 확인 — 이미 해결된 것으로 보이는 과거 기록

`기획 문서/AI기능명세서/충돌사항/코드베이스_충돌_정리.md`가 지적했던 "답변 재생성이 Context를 빼고 대화 흐름을 새로 계산한다"(AI-ANSWER-004)는 문제는 `backend/app/services/ai_response_service.py`의 `regenerate` 함수(53~66행)에서 이미 고쳐져 있다. 최초 생성 시점의 입력 조건(`input_snapshot`)을 그대로 재사용한다. 이 충돌 문서는 더 이상 코드와 맞지 않으므로 정리(삭제) 대상으로 보인다. **사용자 확인 후 처리 필요.**

또한 같은 문서가 "코드가 아직 없다"고 전제했던 모델 선택(AI-CORE-001·002), 웹 검색(AI-SEARCH-001·002), 첨부 입력(AI-ATTACH-001~003)은 실제로는 `modeling/models.py`, `modeling/llm.py`, `modeling/attachments.py`, `modeling/chains/answer.py`에 이미 구현되어 있었다. 아래 두 건만 예외로 문제가 남아 있다.

### [AI-SEARCH-002] 검색 근거 전달 — 부분 구현

- 명세: 응답에 검색 근거(제목·주소)가 있으면 답변 본문과 함께 돌려준다.
- 코드: [`backend/app/services/ai_response_service.py`](../../backend/app/services/ai_response_service.py)의 `regenerate`(61행)와 `_legacy_regenerate`(128행)가 검색 근거(`search_sources`)를 그냥 버린다. `RegenerateResponse` 스키마에도 이 필드가 없다.
- 영향: 웹 검색으로 만든 답을 다시 생성하면, 다시 검색을 해도 그 근거가 사라진다. 최초 생성과 실패 재시도는 근거를 정상적으로 돌려주는데 재생성만 빠져 있어 동작이 기능마다 다르다.
- 우선순위: 중

### [AI-TITLE-001] 첫 질문 기반 제목 생성 — 명세와 다르게 동작

- 명세: 첫 메시지이면서 채팅 제목이 아직 기본값일 때 제목을 자동으로 만든다.
- 코드: `retry_failed_job`(같은 파일 68~80행)이 제목 생성 함수를 아예 부르지 않고 `title_generated`를 항상 `False`로 고정한다.
- 영향: 첫 질문에 대한 답 생성이 한 번 실패했다가 "다시 시도"로 성공하는 흔한 상황에서, 조건을 만족해도 제목이 만들어지지 않아 채팅 제목이 "새 대화"로 영구히 남는다. 관련 테스트(`test_failed_job_can_retry_without_duplicate_question`)도 이 값을 검증하지 않아 회귀로 걸러지지 않는다.
- 우선순위: 중

### [AI-ANSWER-003] 빈 응답 오류 처리 위치 — 해결됨

- 명세: 답변 생성 모델링 함수 자체가 빈 응답을 오류로 처리해야 한다.
- 조치: `modeling/chains/answer.py`의 `generate_answer`가 빈 응답이면 `EmptyAnswerError`를 직접 raise하도록 고쳤다(커밋 `63eb60d`). 백엔드 `_classify_error`도 이 예외를 기존 `AI_RESPONSE_EMPTY` 코드로 분류하도록 맞췄다. `modeling/tests/test_chains.py`에 `test_generate_answer_rejects_empty_response`를 추가했다.
- 우선순위: 하 (해결)

### [AI-REFINE-004] 정제 결과 개수/빈 본문 검사 위치 — 해결됨

- 명세: 정제 결과 개수 불일치와 빈 본문 모두 모델링 함수 책임이다.
- 조치: `modeling/chains/refine.py`의 `refine_blocks`가 빈 본문이면 `EmptyRefineResultError`를 직접 raise하도록 고쳤다(커밋 `63eb60d`). 개수 불일치는 기존 `zip(..., strict=True)`가 이미 막고 있었다. `test_refine_rejects_empty_result`로 검증했다.
- 우선순위: 하 (해결)

## BE 파트

### [BE-AIRESP-003] 과거(레거시) AI 응답 재생성 시 조건 유실 — 명세와 다르게 동작
