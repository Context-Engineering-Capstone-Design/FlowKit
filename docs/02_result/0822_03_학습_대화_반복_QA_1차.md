# 학습 대화 반복 QA 1차

## 목표

배포와 로컬 환경에서 학습 주제 대화의 로그인·초기 진입·채팅 생성 흐름을 비교하고, 재현 가능한 오류를 수정한다.

## 범위

- Google 로그인과 초기 작업 화면 진입
- 학습 대화용 채팅 생성과 새로고침 후 상태 유지
- 배포(Vercel·Render)와 로컬(`localhost:5173`)의 화면·API 오류 비교

## 완료 기준

- 각 환경의 실행 결과와 오류를 기록한다.
- 수정한 오류는 관련 자동 테스트와 브라우저 재검증을 통과한다.
- 운영 데이터·권한·비밀값·외부 계정 설정은 변경하지 않는다.

## 검증 방법

- 외부 브라우저에서 배포와 로컬 화면을 확인한다.
- 필요한 경우 브라우저 콘솔과 읽기 전용 API 상태를 대조한다.
- 수정 시 영향 범위의 프론트엔드·백엔드 테스트를 실행한다.

## 구현 결과

- 기준 코드 커밋: `f704d91`
- 새로고침 때 목록 응답에 같은 채팅 ID가 반복되더라도 첫 항목만 유지하도록 처리했다. 사이드바의 React key 충돌을 막는다.
- 로컬에서 개발 로그인 후 Self-Attention 학습 질문을 전송하고, 새로고침 뒤 생성된 대화 제목이 목록에 유지되는 것을 확인했다.
- 배포 Render `/health`는 `200 {"status":"ok"}`였다. Vercel은 Render 절전 해제 뒤 로그인 화면까지 진입했다.

## 검증 결과

- `frontend`: `npm test -- --run src/store/chatStore.test.ts` — 46개 통과
- `frontend`: `npm run lint` — 기존 경고만 있고 실패 없음
- `frontend`: `npm run build` — 통과
- 외부 브라우저: 로컬 새로고침 뒤 새 React key 오류 없음

## 남은 제한 사항

- 배포 Google 로그인은 Google Cloud OAuth의 `redirect_uri_mismatch`로 완료하지 못했다. 외부 OAuth 설정 변경이 필요한 항목이라 수정하지 않았다.
- 로컬 AI 답변 성공 경로는 사용자 OpenAI API 키가 없어 검증하지 못했다. 실패 상태 표시는 확인했다.
