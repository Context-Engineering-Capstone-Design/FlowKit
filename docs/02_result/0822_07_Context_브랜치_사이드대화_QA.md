# Context·브랜치·사이드 대화 QA

## 목표

학습 대화의 메시지에서 Context 드래그 범위 선택, 편집 진입, 브랜치와 사이드 대화 생성을 검증한다.

## 범위

- 메시지 텍스트 드래그 후 Context 태그 생성
- Context 편집 패널 열기와 태그 제거
- 메시지 기준 브랜치·사이드 대화 생성

## 완료 기준

- 드래그 범위만 Context로 추가된다.
- 생성한 브랜치·사이드 대화가 올바른 대화 계열에 보인다.
- 재현 오류는 수정·자동 테스트·브라우저 재검증을 거친다.

## 검증 방법

- 로컬 외부 브라우저와 학습 대화 메시지를 사용한다.
- 실제 AI 답변이 필요한 단계는 기존 테스트 대화 또는 실패 상태의 사용자 메시지로 대체한다.

## 구현 결과

- 기준 코드 커밋: `9aacbdb`
- 우측 사이드 패널에서 분기·사이드 대화를 만들 때 메인 대화 구조도 즉시 다시 불러오도록 수정했다.
- 우측 패널에서 생성한 자식 노드가 새로고침 전 좌측 대화 구조에 누락되던 문제를 해결했다.

## 검증 결과

- 굵은 Markdown을 포함한 Self-Attention 답변 범위를 드래그해 Context 태그로 추가하고, 후속 학습 질문의 AI 답변까지 정상 생성했다.
- 강조된 원문 범위를 클릭해 Context 태그가 제거되는 것을 확인했다.
- 메시지 기준 분기와 사이드 대화를 생성하고, 중첩 사이드 대화에서 다시 분기하는 흐름을 확인했다.
- 새로고침 전에는 중첩 노드가 좌측 대화 구조에 늦게 나타났으나, 수정 뒤 새 사이드 노드가 즉시 나타나는 것을 확인했다.
- `frontend`: `npm test -- --run src/store/chatStore.test.ts` — 47개 통과
- `frontend`: `npm run lint` — 기존 경고만 있고 실패 없음
- `frontend`: `npm run build` — 통과

## 남은 제한 사항

- 입력창 인라인 태그의 X 버튼은 자동화 클릭으로 제거 상태를 확인하지 못했다. 강조된 원문 클릭으로의 제거는 확인했다.
- 승인 전 정제 결과에서 Context 범위를 전송하는 경로와 레거시 CHILD 브랜치의 분기 경로는 별도 QA가 필요하다.
