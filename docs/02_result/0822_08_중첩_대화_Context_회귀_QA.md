# 중첩 대화·Context 회귀 QA

## 목표

학습 대화에서 중첩 사이드 대화의 분기 앵커와 Context 편집 경로를 실제 화면으로 검증한다.

## 범위

- 중첩 사이드 대화에서 만든 분기가 원래 메시지 위치에 표시되는지 확인
- 빠른 대화 전환 뒤 우측 패널 내용이 현재 대화와 일치하는지 확인
- Context 편집 패널에서 인용 범위 태그의 표시·제거 흐름 확인
- 재현된 코드 오류만 수정하고 관련 자동 테스트와 브라우저 재검증 수행

## 완료 기준

- 검증 결과와 재현 조건을 기록한다.
- 수정이 필요하면 코드·테스트를 별도 커밋한다.
- 결과 문서를 `docs/02_result/`로 이관한다.

## 검증 방법

- 로컬 외부 브라우저에서 트랜스포머 학습 대화를 사용한다.
- 기존 QA 데이터는 삭제하지 않고, 필요한 경우 새 학습 질문으로 추가한다.

## 구현 결과

- 기준 코드 커밋: `821304d`, `e63d7d0`, `85de368`
- 중첩 사이드 대화에서 만든 분기는 `forkedFromChatId`와 `forkedFromMessageBlockId`를 기준으로 원본 메시지에 연결하도록 수정했다.
- Context 편집 탭에서 메시지를 수정할 때 기존 인용 범위 태그를 표시하고 제거 동작을 연결했다.
- 늦게 끝난 이전 대화 구조 요청이 현재 분기나 최신 목록을 덮지 않도록 store별 요청 순서를 확인한다.

## 검증 결과

- 로컬 외부 브라우저에서 `새 사이드 채팅`의 `Softmax 온도` 학습 질문에 만든 `분기 4`가 처음에는 보이지 않다가, 수정 뒤 원본 질문 위치에 표시되는 것을 확인했다.
- 표시된 `분기 4` 앵커를 누르면 해당 우측 대화 패널로 전환되는 것을 확인했다.
- 브라우저 오류 로그에 새 오류가 없는 것을 확인했다.
- `frontend`: `npm test -- --run src/store/chatStore.test.ts` — 50개 통과
- `frontend`: `npm test -- --run src/components/ContextPanel.test.tsx src/store/chatStore.test.ts` — 54개 통과
- `frontend`: `npm run lint` — 기존 경고만 있고 실패 없음
- `frontend`: `npm run build` — 통과

## 남은 제한 사항

- 외부 브라우저 자동화에서는 드래그한 범위를 정제 탭으로 보내는 동작을 이 세션에서 다시 재현하지 못했다. Context 편집의 인용 태그 표시·제거는 컴포넌트 회귀 테스트로 검증했다.
- 일반 신규 UI에는 같은 채팅 안에서 legacy 브랜치를 빠르게 바꾸는 선택 화면이 없다. 해당 경쟁 상태는 지연 응답을 만든 store 회귀 테스트로 검증했다.
