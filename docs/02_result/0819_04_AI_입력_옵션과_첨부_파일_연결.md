## 현재 상태와 문제

- `modeling.available_models`와 모델 선택 검증은 구현돼 있다.
- `modeling.generate_answer`는 모델, 검색, 이미지·문서 첨부를 받을 수 있다.
- 백엔드 메시지 요청은 질문과 Context ID만 받는다.
- 검색 근거가 모델링 결과로 와도 백엔드에서 버린다.
- 첨부 DB 모델, 파일 저장소, 업로드 API가 없다.
- 입력창에는 첨부·검색·모델 UI가 없고 전송 실패 시 입력 본문도 복원되지 않는다.

## 확정 구현 방식

### 모델 목록

- 모델 목록의 원본은 `modeling.config.MODELS` 한곳만 사용한다.
- 백엔드는 `modeling.available_models()`를 API 형식으로 변환한다.
- FE에 모델 목록을 중복 상수로 두지 않는다.
- 목록 조회가 실패했을 때만 마지막으로 확인된 기본 모델 표시값을 사용하되, 실제 전송은 서버 검증을 다시 거친다.

### 웹 검색

- FE는 `webSearchEnabled`만 전달한다.
- 백엔드는 선택 모델의 검색 지원 여부를 확인한 뒤 모델링에 전달한다.
- 지원하지 않는 모델이면 자동으로 기본 모델로 바꾸지 않고 `WEB_SEARCH_NOT_SUPPORTED`를 반환한다.
- 검색 근거는 `SearchSource(title, url)` 목록으로 응답에 포함한다.
- 별도 검색 서비스나 검색 결과 화면은 만들지 않는다.

### 첨부 저장

- 파일 바이트를 DB에 저장하지 않는다.
- 파일 메타데이터와 상태는 DB에, 원본은 저장소에 둔다.
- 저장소 접근은 인터페이스로 분리한다.
- 로컬 개발 기본 구현은 `ATTACHMENT_STORAGE_DIR` 아래 파일 시스템을 사용한다.
- 배포 저장소는 환경별 구현으로 교체할 수 있게 경로 생성·읽기·삭제 함수만 서비스에 노출한다.
- 첨부가 메시지에 연결된 뒤에는 원본을 수정하지 않는다. 재생성에서 같은 입력을 쓰기 위해 보존한다.

### 기본 제한

명세에 정확한 수치가 없으므로 다음 값을 코드 상수와 환경 설정으로 분리한다. 실제 값은 구현 전 사용자 확인이 필요하다.

- 한 파일 최대 크기: 제안 10MB
- 한 메시지 최대 첨부 수: 제안 5개
- 허용 이미지: PNG, JPEG, WebP
- 허용 문서: PDF, TXT, Markdown
- 임시 첨부 만료: 제안 24시간

서버가 최종 기준이며 FE는 서버와 같은 안내값을 사용한다.

- 사용자 메시지에만 첨부 연결을 허용한다.
- 다른 사용자·채팅의 첨부 연결을 거절한다.

## API 계약

### 모델 목록

`GET /api/models`

응답 항목:

- `modelId`
- `displayName`
- `provider`
- `supportsWebSearch`
- `supportsAttachment`
- `isDefault`
- `isAvailable`

### 첨부 업로드

`POST /api/chats/{chatId}/attachments`

- `multipart/form-data`의 단일 파일을 받는다.
- 여러 파일은 FE가 파일별 요청으로 보내 각 항목의 진행·실패 상태를 독립 처리한다.
- 성공 시 `attachmentId`, 파일명, MIME type, 크기, 상태를 반환한다.
- 이미지 미리보기는 FE의 로컬 Object URL을 우선 사용한다. 인증 없는 공개 파일 URL은 만들지 않는다.

### 첨부 제거

`DELETE /api/chats/{chatId}/attachments/{attachmentId}`

- `temporary` 상태만 즉시 제거한다.
- 이미 메시지에 연결된 첨부는 `ATTACHMENT_ALREADY_USED`로 거절한다.
- 파일 삭제 실패 시 DB 상태를 성공으로 바꾸지 않는다.

### 메시지 전송 확장

`POST /api/chats/{chatId}/branches/{branchId}/messages`

추가 요청 필드:

```json
{
  "selectedModelId": "gemini-model-id",
  "webSearchEnabled": true,
  "attachmentIds": ["uuid"]
}
```

처리 순서:

1. 채팅·브랜치 소유권 검증
2. 모델 선택값과 검색·첨부 지원 여부 검증
3. 첨부 소유권·채팅·임시 상태 검증
4. 사용자 메시지 블록 생성
5. 첨부를 사용자 메시지에 연결하고 `attached`로 변경
6. 저장소에서 바이트를 읽어 모델링 `Attachment`로 변환
7. 사용자 키·모델·검색·첨부를 답변 생성에 전달
8. 답변과 검색 근거 반환

응답 추가 필드:

- `selectedModel`
- `webSearchEnabled`
- `attachments`
- `searchSources`

## FE 상태 구조

입력 초안 상태는 `ChatArea` 지역 상태가 아니라 채팅 상태 저장소에 둔다. 전송 실패와 채팅·브랜치 이동 규칙을 한곳에서 처리하기 위해서다.

필요 상태:

- `draftText`
- `selectedModelId`
- `webSearchEnabled`
- `attachments[]`
- 각 첨부의 `localId`, `attachmentId`, `status`, `error`
- `isModelListLoading`

초기화 규칙:

- 전송 성공: 본문·첨부 비움, 모델·검색 선택은 유지
- 전송 실패: 본문·첨부 유지
- 새 채팅·다른 채팅·브랜치 전환: 미전송 초안이 있으면 확인 후 이동
- 로그아웃: 모든 초안과 로컬 Object URL 정리

## 화면 동작

### 첨부

- 첨부 버튼에서 `사진 업로드`, `파일 업로드`를 선택한다.
- 파일마다 독립적으로 업로드 중·완료·실패·재시도 상태를 표시한다.
- 제거하면 화면에서 먼저 숨기되 서버 삭제 실패는 정보 알림으로 남긴다.
- 이미지 Object URL은 제거·전송·화면 종료 때 해제한다.
- 업로드 중인 파일이 있으면 메시지 전송을 막는다.

### 웹 검색

- 토글 상태를 색과 텍스트로 구분한다.
- 현재 모델이 검색을 지원하지 않으면 비활성화하고 이유를 표시한다.
- 모델 변경으로 검색이 불가능해지면 토글을 끄고 안내한다.

### 모델 선택

- 서버 목록을 열어 이름, Provider, 기능 지원 여부, 기본 모델을 표시한다.
- 사용할 수 없는 모델은 선택할 수 없게 한다.
- 서버가 선택값을 거절하면 기본 모델로 조용히 바꾸지 않고 사용자가 다시 고르게 한다.

- `GET /api/models`, 첨부 업로드·삭제 API와 로컬 파일 저장소를 추가했다.
- 허용 형식은 PNG·JPEG·WebP·PDF·TXT·Markdown이며, 기본 제한은 10MB·메시지당 5개·임시 24시간이다. 모두 환경변수로 변경할 수 있다.
- 메시지 전송에서 모델·검색·첨부를 검증하고, 첨부 연결과 사용자 메시지 저장을 함께 처리한다. 모델링 결과의 검색 근거도 응답에 보존한다.
- 입력창에 모델 선택, 검색 토글, 첨부 메뉴·진행 상태·재시도·제거를 추가했다. 전송 성공 때만 초안을 비우며, 채팅·브랜치 이동 시 확인하고 로그아웃 시 Object URL을 해제한다.

## 남은 제한 사항

- 실제 Gemini 검색과 이미지·PDF·텍스트 파일의 브라우저 E2E 검증은 사용자 API 키와 실행 서버가 필요해 수행하지 않았다.
- 배포 환경에서는 `ATTACHMENT_STORAGE_DIR` 구현을 객체 저장소 어댑터로 교체해야 한다.
