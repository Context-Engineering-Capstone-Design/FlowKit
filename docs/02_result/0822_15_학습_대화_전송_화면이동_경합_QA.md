# 학습 대화 전송·화면 이동 경합 QA 결과

## 목표와 범위

Transformer 학습 대화에서 전송·첫 채팅 생성·첫 첨부가 진행되는 동안 다른 대화·초안 탭으로 이동할 때, 늦은 응답이 현재 화면의 제목·블록·입력 상태를 바꾸지 않는지 검증했다.

## 구현 결과

- 전환 요청 번호와 실제 화면 변경 번호를 분리했다. 다른 대화 조회가 실패해도 원래 화면의 전송은 계속 완료된다.
- `chatId + branchId`별 전송 순번과 진행 상태를 두었다. 다른 대화로 갔다가 같은 노드로 돌아오면 이전 전송 결과만 합치고, 그 뒤 새로 쓴 입력과 Context는 유지한다.
- 같은 대화를 다시 선택하면 대기 중인 다른 대화 조회를 취소한다. 늦은 조회도 이미 끝난 전송 결과를 이전 블록·제목으로 덮지 못한다.
- 첫 메시지 전송과 첫 파일 첨부가 같은 초안에서 동시에 시작되면 채팅 생성 요청을 하나로 합친다. 파일이 업로드 중이면 전송을 막고 안내한다.
- 재진입 조회에 이미 들어온 사용자·답변 블록은 중복하지 않는다. 진행 중인 답변 텍스트는 스트림이 이어서 갱신할 수 있도록 보존한다.
- 스트림 텍스트·출처·완료 처리는 시작한 `chatId + branchId`가 현재 열려 있을 때만 적용한다.

## 재현·검증

- 수정 전 지연 응답 자동 테스트로 다음 5개 문제를 재현했다.
  - A 전송 완료가 B 화면의 제목·입력·블록을 덮음
  - B 열기 실패 뒤 A 전송 결과가 사라짐
  - A를 다시 열어도 이전 전송 결과를 버림
  - 첫 채팅 생성 완료가 B 화면을 강제로 바꿈
  - 첫 첨부 생성 완료가 B 화면에 파일 상태를 섞음
- 추가로 같은 대화 늦은 조회, 같은 대화 재선택으로 다른 열기 취소, 첫 전송·첫 첨부 동시 시작, 같은 블록 ID의 다른 노드 스트림을 지연 응답으로 확인했다.
- `npm test -- --run src/store/chatStore.test.ts`: 70건 통과.
- `npm test -- --run`: 28개 파일, 215건 통과.
- `npm run lint`: 오류 없음. 기존 React effect/ref 경고 12건은 이번 변경 범위 밖이다.
- `npm run build`: 통과. 기존 번들 500 kB 초과 경고만 남는다.
- 외부 브라우저의 `http://localhost:5173/`에서 `트랜스포머 학습 QA` 프로젝트, 새 대화 입력, 우측 `분기 3`의 Self-Attention 대화를 읽기 전용으로 확인했다. 실제 전송·첨부·탭 닫기는 운영 데이터 보호를 위해 실행하지 않았다.

## 남은 제한 사항

- 기존 대화에서 파일 업로드 중 다른 탭으로 이동하면 업로드는 완료되어도 해당 임시 첨부를 배경 탭에 보존하지 않는다. 첨부 취소·정리 정책 QA가 필요하다.
- `regenerate`, `retryAiResponseJob`, `cancelGeneration`은 이번 전송 경합 보호 범위에 포함하지 않았다. 다음 QA에서 대화·노드 이동 중 늦은 응답을 검증한다.
- 노드·사이드 채팅 생성 자체의 지연 응답과 전환 경합은 별도 범위로 남긴다.
