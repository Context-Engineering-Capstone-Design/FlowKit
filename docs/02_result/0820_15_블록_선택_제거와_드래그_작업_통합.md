# 0820_15 블록 선택 제거와 드래그 작업 통합

## 목표

체크박스 기반 메시지 블록 선택을 제거하고, 드래그 범위 선택을 Context·정제·사이드 채팅의 유일한 선택 방식으로 만든다.

## 범위

- `selectedBlockIds`와 선택 블록 목록, Context 패널의 선택 기반 동작을 제거한다.
- 드래그 작업 토글에 `블록 정제`를 추가한다. 범위가 속한 메시지 블록 하나를 정제 대상으로 연다.
- 브랜치 생성은 헤더의 일반 생성만 남기고, 블록별 분기·선택 Context 전달을 없앤다.
- 사이드 채팅의 선택 블록 기반 부모 반영 UI를 제거한다. 드래그 범위 Context 전달만 남긴다.

## 기획 문서와의 차이

사용자가 2026-08-20에 확정한 화면 방향에 맞춰 메시지 블록 선택, 선택 블록 Context, 선택 블록 정제·브랜치 생성 요구를 관련 기획 문서에도 반영한다.

## 완료 기준

- [x] 화면에 체크박스·선택된 블록 패널이 없다.
- [x] 드래그 토글에서 Context 추가·사이드 채팅 질문·블록 정제를 실행할 수 있다.
- [x] 일반 브랜치 생성에 선택 블록 Context가 전달되지 않는다.
- [x] 관련 테스트와 타입 검사·린트·빌드가 통과한다.

## 검증 방법

- 관련 컴포넌트·스토어 테스트를 갱신한다.
- `cd frontend && npx vitest run`
- `cd frontend && npx tsc --noEmit && npm run lint && npm run build`

## QA 후속 확인 (2026-08-21)

`0820_19` QA에서 처음 실제 Chrome으로 확인했다. 코드 변경 없음.

- 메시지 블록에 체크박스·"선택된 블록" 패널이 없음을 확인했다.
- 드래그 토글의 "블록 정제"를 클릭하면 그 범위가 속한 메시지 블록 전체가 우측 Context 패널의 정제 모드로 열리고, "AI 정제 지시" 입력란과 "블록별로 정제하기" 버튼이 뜬다(범위만 잘려 정제되지 않음을 확인).
- 메시지별 "여기서 브랜치 생성" 버튼으로 분기를 만들면 Context 블록 체크 목록 없이 바로 생성된다. 다만 이 QA에서는 별도의 "헤더" 위치 브랜치 생성 버튼은 찾지 못했다 — 메시지별 버튼이 이 문서가 말하는 "헤더의 일반 생성"에 해당하는 것으로 보이나, 정확한 위치는 재확인이 필요하다.
- 사이드 채팅 화면의 체크박스 제거 여부는 이번에 확인하지 못했다.
