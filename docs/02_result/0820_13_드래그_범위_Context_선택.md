# 0820_13 드래그 범위 Context 선택

- 상태: 구현 완료

## 목표

기존 메시지 블록 단위 선택을 한 메시지 안의 드래그 범위 선택으로 바꾼다. 사용자는 고른 범위를 하단 채팅 패널의 태그로 모아 다음 질문의 Context로 쓰거나, 빈 사이드 채팅 패널에서 질문을 시작할 수 있다.

## 선택 규칙

- 드래그 선택은 한 메시지 안에서만 가능하다. 여러 메시지를 가로지르는 드래그는 허용하지 않는다.
- 일반 본문, 코드 블록, 표, 인용문을 선택할 수 있다. 첨부 미리보기는 선택할 수 없다.
- 한 메시지 안에서 본문·코드 블록·표·인용문의 경계를 걸치는 범위도 선택할 수 있다.
- 빈 영역을 클릭하면 현재 드래그 범위를 확정한다.
- 겹치는 선택 범위는 허용하고, 각각 별도 태그로 유지한다.
- 선택 범위 수와 전체 글자 수 제한은 두지 않는다.

## 저장 기준

선택 범위마다 다음을 저장한다.

- 메시지 ID
- 메시지 버전 ID
- 선택 당시 본문 스냅샷
- 원문 메시지가 나중에 수정돼도 선택 당시 스냅샷을 Context로 사용한다.
- 태그 호버 시에도 현재 원문이 아니라 선택 당시 스냅샷 기준으로 해당 범위를 강조한다.

## 하단 채팅 패널

- 확정된 선택 범위는 하단 채팅 패널에 태그로 표시한다.
- 태그에는 선택 전체 대신 앞 5~10자 이하의 짧은 미리보기만 보여준다.
- 태그에 호버하면 선택 원문 스냅샷의 해당 범위를 하이라이트한다. 기존의 어둡게 눌린 선택 표시는 대체한다.
- 각 태그 오른쪽 `X` 버튼으로 해당 선택 범위를 제거할 수 있다.
- 태그가 붙은 상태에서 다음 메시지를 전송하면 모든 태그 범위를 해당 요청의 Context로 자동 포함한다.
- 전송 뒤 태그는 다음 요청에 재사용되지 않도록 비운다.

## 선택 뒤 작업

- `채팅 패널에 추가`: 선택 범위 태그를 현재 하단 채팅 패널에 추가한다.
- `사이드 채팅으로 질문`: 선택 범위 태그가 붙은 빈 사이드 채팅 패널을 프론트엔드에서 즉시 연다.

## 지연 생성 사이드 채팅

- `사이드 채팅으로 질문`을 누른 시점에는 백엔드에 새 대화를 만들지 않는다.
- 사용자가 빈 사이드 채팅 패널에서 태그를 포함한 첫 메시지를 전송할 때만 백엔드에 새 사이드 채팅을 생성한다.
- 첫 전송 전 패널을 닫으면 서버에 대화·메시지·첨부 기록을 남기지 않는다.

- [x] A2. 선택 영역 클릭 해제와 빈 영역 클릭 확정 동작을 만든다.

- [x] B1. 하단 채팅 패널에 미리보기 태그와 `X` 제거 버튼을 표시한다.
- [x] B2. 태그 호버 시 스냅샷 기준 하이라이트를 표시한다.
- [x] B3. 전송 시 모든 태그 범위를 Context로 전달하고, 전송 뒤 태그를 비운다.

### 마일스톤 C · 지연 생성 사이드 채팅

- [x] C1. 선택 범위 태그를 포함한 빈 사이드 채팅 패널을 로컬 상태로 연다.
- [x] C2. 첫 메시지 전송 때만 사이드 채팅과 첫 메시지를 서버에 생성한다.
- [x] C3. 첫 전송 전 닫힌 패널은 서버 기록 없이 제거한다.

### 마일스톤 D · 검증

- [x] D1. 한 메시지 안의 일반 본문·코드·표·인용문과 그 경계 선택을 프론트엔드 테스트로 검증한다.
- [x] D2. 중복·겹침 선택, 클릭 해제, 빈 영역 확정, 태그 `X` 제거를 검증한다.
- [x] D3. 선택 당시 스냅샷이 원문 수정 뒤에도 Context와 하이라이트에 유지되는지 검증한다.
- [x] D4. 태그를 포함한 전송에만 Context가 전달되고, 전송 뒤 태그가 비워지는지 검증한다.
- [x] D5. 사이드 채팅 패널 생성만으로는 서버 기록이 생기지 않고, 첫 전송에서만 생성되는지 검증한다.

## 완료 기준

- 사용자가 한 메시지 안에서 원하는 범위를 드래그해 Context 태그로 추가·제거할 수 있다.
- 여러 형식의 경계를 걸치는 선택, 겹치는 선택, 원문 수정 뒤 스냅샷 강조가 유지된다.
- 다음 메시지에는 태그 범위가 자동 Context로 포함되고, 그 뒤 태그가 비워진다.
- 빈 사이드 채팅 패널은 첫 메시지 전송 전까지 서버에 저장되지 않는다.

### 완료 항목

- **A**: 메시지 렌더링 컨테이너에 `data-selectable-root`를 붙이고, `window.getSelection()`으로 읽은 드래그 범위를 문서 순서 텍스트 오프셋으로 환산하는 유틸(`frontend/src/lib/textRangeSelection.ts`)을 만들었다. 오프셋은 DOM 트리 전체(코드·표·인용문 포함)를 순회해 계산하므로 형식 경계를 걸친 선택도 그대로 동작한다. 드래그가 끝나면(`mouseup`) 선택 위치 옆에 `채팅에 추가`·`사이드 채팅에 질문` 작업 토글(`SelectionActionToggle`)을 띄운다 — 이 토글이 "선택 뒤 작업" 두 가지를 실행하는 유일한 통로다(하단 채팅 패널에는 별도 진입 버튼을 두지 않는다). 빈 영역을 클릭하면(문서 `mousedown`이 토글 밖을 때리면) 토글을 닫는다. 확정된 태그는 렌더링된 마크다운 트리에 `<mark>`로 겹침까지 지원해 얹는 rehype 플러그인(`frontend/src/lib/rehypeHighlightRanges.ts`)으로 표시하고, 그 `<mark>`를 다시 클릭하면 태그를 지운다.
- **B**: 태그는 `chatStore`의 새 상태 `contextRangeTags`로 관리하며, 기존 체크박스 기반 `selectedBlockIds`/정제/브랜치/사이드 채팅 반영 흐름은 그대로 둔 채 "다음 질문 Context"용으로만 별도로 추가했다(사용자 확인: 기존 흐름 대체가 아니라 신규 추가). 하단 채팅 패널(`ChatArea.tsx`의 `Composer`)에 짧은 미리보기 태그·`X` 제거 버튼·호버 시 스냅샷 강조 팝업을 추가했다. 전송(`sendMessage`)은 태그를 `{blockId, versionId, snippetText}`로 변환해 함께 보내고, 성공하면 태그를 비운다.
- **C**: "사이드 채팅에 질문"은 기존 임시 탭(draft tab) 패턴을 재사용해, `chatId: null`이고 `draftSideChatAnchor`(부모 채팅·브랜치·지점 블록)를 든 로컬 탭만 연다 — 이 시점에는 백엔드 호출이 전혀 없다. 첫 메시지 전송에서 `sendMessage`가 활성 탭에 `draftSideChatAnchor`가 있으면 기존 `sideChatApi.createSideChat`으로 사이드 채팅을 만든 뒤 이어서 메시지를 보낸다. 전송 전 탭을 닫으면 기존 `closeTab`이 그대로 처리해 서버 기록이 없다.
- **백엔드 확장(사용자 확인: 스니펫 단위 Context를 위해 API를 새로 확장)**: `SendMessageRequest`에 `contextRanges`(블록 ID·버전 ID·스니펫 텍스트) 필드를 추가했다. `context_service.build_range_snapshot`이 각 스니펫이 그 버전 본문의 실제 부분 문자열인지 검증한 뒤(위조 방지) `ContextItem`으로 변환한다 — `AppliedContextItem.content`가 이미 자유 텍스트라 스키마 변경 없이 기존 Context 파이프라인(로그 저장·AI 입력 구성)을 그대로 탄다. 버전은 블록의 현재 버전이 아니라 요청이 지정한 특정 버전을 찾아 검증하므로, 원문이 수정된 뒤에도 태그가 고정한 예전 버전의 스니펫이 그대로 Context로 쓰인다(D3).

- 답변 본문을 드래그하면 "채팅에 추가"/"블록 정제"/"사이드 채팅에 질문" 3개 토글이 뜨고, "채팅에 추가"를 누르면 입력창에 미리보기 태그가 붙고 원문이 하이라이트된다. 태그의 X로 제거하면 하이라이트도 함께 사라진다(D2 관련 확인).
- 이 환경은 OpenAI 연결이 안 돼 D3(스냅샷 유지)·D4(전송 반영)·D5(사이드 채팅 첫 전송에서만 생성)의 전송 이후 동작은 실제 화면으로 확인하지 못했다.
- 코드 블록·표·인용문 경계를 걸치는 선택(D1)은 이번에 시도하지 않았다.
- **표·인용문 경계 선택은 별도 테스트 없음**: 코드 블록 경계는 직접 테스트했지만, 표·인용문 경계는 별도 케이스를 추가하지 않았다. 오프셋 계산과 하이라이트 모두 요소 종류를 가리지 않는 방식이라 동작은 같을 것으로 보이지만, 실제로 확인하지는 않았다.
- **겹치는 태그를 한 번에 클릭하면 모두 제거**: 여러 태그가 겹치는 구간을 클릭하면 그 구간에 걸린 태그를 모두 지운다. 어떤 태그를 지울지 고르는 별도 UI는 없다.
- **동일 문구가 메시지 안에 여러 번 나오면 첫 번째 위치 기준**: 선택한 글자와 똑같은 문구가 앞쪽에 또 있으면, 오프셋은 그 앞쪽 위치를 기준으로 잡힐 수 있다(구현 방식상 드문 예외 상황).
- **기존 블록 체크박스 선택과 공존**: 사용자 확인대로 기존 `선택된 블록`(정제·브랜치·사이드 채팅 반영용) 체크박스 흐름은 손대지 않았다. 두 선택 방식을 동시에 쓰면 한 메시지 전송에 둘 다 Context로 포함될 수 있다 — 계획에 없는 조합이라 별도로 막지 않았다.
