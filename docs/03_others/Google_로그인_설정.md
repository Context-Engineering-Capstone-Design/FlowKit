# Google 로그인 설정

FlowKit은 Google 계정으로만 로그인한다. 동작하려면 Google에서 발급받는 **클라이언트 ID**가 필요하다. 무료이고 신용카드도 필요 없다.

한 번만 만들어서 팀원끼리 같은 값을 쓰면 된다.

## 어떻게 동작하나

1. 사용자가 로그인 화면에서 Google 버튼을 누른다
2. 구글이 로그인 창을 띄우고, 성공하면 **ID 토큰**(로그인했다는 증명서)을 브라우저에 준다
3. 프론트가 그 토큰을 백엔드로 보낸다
4. 백엔드가 구글의 공개 키로 **진짜 구글이 발급한 게 맞는지** 확인한다
5. 확인되면 FlowKit 자체 토큰을 발급하고 로그인이 끝난다

브라우저가 보낸 말을 그냥 믿지 않고 4번에서 서버가 다시 확인하는 것이 핵심이다. 그래서 클라이언트 ID를 프론트와 백엔드 **양쪽에** 넣어야 한다.

---

## 1. 클라이언트 ID 만들기

### 1-1. 프로젝트 만들기

[Google Cloud Console](https://console.cloud.google.com/)에 접속해 구글 계정으로 로그인한다.

상단의 프로젝트 선택 메뉴에서 **새 프로젝트**를 누르고 이름을 `FlowKit`으로 지정해 만든다. 만든 뒤 그 프로젝트가 선택되어 있는지 확인한다.

### 1-2. 동의 화면 설정

사용자가 로그인할 때 "FlowKit이 내 정보에 접근하려 합니다"라고 보여줄 화면을 먼저 만들어야 한다. 이걸 건너뛰면 클라이언트 ID를 만들 수 없다.

왼쪽 메뉴에서 **API 및 서비스 → OAuth 동의 화면**으로 간다.

- User Type: **외부** 선택 후 만들기
- 앱 이름: `FlowKit`
- 사용자 지원 이메일: 본인 이메일
- 개발자 연락처 정보: 본인 이메일
- 나머지는 비워두고 저장 후 계속

범위(Scope) 단계에서는 아무것도 추가하지 않아도 된다. 기본으로 이메일·이름·프로필 사진을 받는다.

**테스트 사용자** 단계에서 팀원 4명의 구글 계정을 모두 추가한다. 여기 없는 계정은 로그인이 막힌다. 나중에 베타 테스터를 받을 때도 여기에 추가하면 된다.

### 1-3. 클라이언트 ID 발급

**API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**로 간다.

- 애플리케이션 유형: **웹 애플리케이션**
- 이름: `FlowKit Web`

**승인된 JavaScript 원본**에 아래를 추가한다. 여기 없는 주소에서는 로그인 창이 아예 안 뜬다.

```
http://localhost:5173
http://127.0.0.1:5173
```

**승인된 리디렉션 URI는 비워둔다.** FlowKit은 페이지를 이동하지 않고 브라우저 안에서 토큰을 받는 방식이라 필요 없다.

만들기를 누르면 `숫자-문자열.apps.googleusercontent.com` 형태의 클라이언트 ID가 나온다. 이 값을 복사한다. 함께 나오는 **클라이언트 보안 비밀번호는 쓰지 않는다.**

---

## 2. 값 넣기

같은 클라이언트 ID를 두 곳에 넣는다. 서로 다르면 백엔드가 토큰을 거부한다.

**frontend/.env**

```
VITE_GOOGLE_CLIENT_ID=여기에_붙여넣기.apps.googleusercontent.com
```

**backend/.env**

```
GOOGLE_CLIENT_ID=여기에_붙여넣기.apps.googleusercontent.com
```

두 파일 모두 git에 올라가지 않으므로, 팀원 각자 자기 컴퓨터에서 채워야 한다. 값은 비밀번호가 아니라서 팀 채팅으로 공유해도 된다.

## 3. 확인

값을 넣은 뒤 **양쪽 서버를 모두 다시 시작한다.** 설정은 시작할 때 한 번만 읽는다.

```bash
# 백엔드
cd backend && source .venv/bin/activate
uvicorn app.main:app --reload --port 8000

# 프론트엔드
cd frontend && npm run dev
```

`http://localhost:5173`에 접속해 구글 버튼이 보이면 성공이다. 눌러서 로그인하면 3단 화면으로 넘어간다.

---

## 문제가 생기면

**버튼이 안 보이고 "클라이언트 ID가 없다"고 나올 때**
`frontend/.env`에 값이 있는지 확인하고 프론트 서버를 다시 시작한다. Vite는 시작할 때만 `.env`를 읽는다.

**버튼은 보이는데 눌러도 아무 일이 없을 때**
브라우저 개발자 도구 콘솔에 `origin is not allowed` 같은 메시지가 있는지 본다. 1-3의 승인된 JavaScript 원본에 접속 주소가 정확히 들어 있어야 한다. `localhost`와 `127.0.0.1`은 다른 주소로 취급되니 둘 다 넣는다.

**로그인 창은 뜨는데 "액세스 차단됨"이 나올 때**
1-2의 테스트 사용자에 그 계정이 없다. 계정을 추가하면 된다.

**INVALID_GOOGLE_ID_TOKEN 오류가 뜰 때**
프론트와 백엔드의 클라이언트 ID가 다르거나, 백엔드 `.env`가 비어 있다. 두 값을 비교하고 백엔드를 다시 시작한다.

---

## 배포할 때

지금 설정은 로컬 개발용이다. 실제 주소로 배포하면 다음을 추가해야 한다.

- 승인된 JavaScript 원본에 배포 주소 추가 (예: `https://flowkit.vercel.app`)
- 테스트 사용자를 넘어 일반 사용자를 받으려면 OAuth 동의 화면에서 **게시**로 전환. 이때 구글 검토가 필요할 수 있다.
