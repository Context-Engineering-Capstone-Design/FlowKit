# Cut-Off 로컬 서버 실행 안내

대상 저장소: `/Users/lyugeonho/Documents/Cut-Off`

Cut-Off은 웹 프론트엔드, React Native 앱, Supabase 백엔드, AI 파이프라인 관리 화면과 워커가 분리되어 있다. 필요한 서버만 각각 별도 터미널에서 실행한다.

## 실행 전 공통 준비

각 Node.js 프로젝트에서는 처음 한 번만 의존성을 설치한다.

```bash
npm install
```

비밀값과 API 키는 저장소에 커밋하지 않는다. 프로젝트별 `.env`, `.env.local`, `.env.collect.local` 파일에만 넣는다.

## 1. 웹 프론트엔드

```bash
cd /Users/lyugeonho/Documents/Cut-Off/front-end
npm run dev
```

터미널에 표시되는 주소를 브라우저에서 연다. Vite 기본 주소는 보통 `http://localhost:5173`이다.

## 2. 모바일 프론트엔드

```bash
cd /Users/lyugeonho/Documents/Cut-Off/front-end-RN
npm start
```

Expo 개발 서버가 열린 뒤 터미널에서 다음 키를 사용한다.

| 키 | 동작 |
| --- | --- |
| `i` | iOS 시뮬레이터 실행 |
| `a` | Android 에뮬레이터 실행 |

실기기 실행에는 Expo Go 또는 개발 빌드가 필요하다.

## 3. 백엔드: 로컬 Supabase

```bash
cd /Users/lyugeonho/Documents/Cut-Off/back-end/v1
supabase start
supabase functions serve
```

주요 로컬 주소:

| 서비스 | 주소 |
| --- | --- |
| Supabase API | `http://127.0.0.1:54321` |
| Supabase Studio | `http://127.0.0.1:54323` |

OAuth, 외부 API, Edge Function을 정상 실행하려면 백엔드 `.env`에 필요한 값이 있어야 한다.

`supabase db reset`은 로컬 DB를 초기화하므로, 데이터 보존이 필요한 경우 실행하지 않는다.

### 문제 해결: Docker API에 연결하지 못함

다음 오류는 Supabase 문제가 아니라 Docker Desktop이 실행되지 않았거나 Docker 엔진이 아직 준비되지 않았다는 뜻이다.

```text
failed to connect to the docker API ... connect: no such file or directory
```

Supabase 로컬 서비스는 Docker 컨테이너로 실행되므로 Docker Desktop을 먼저 시작한다.

```bash
open -a Docker
```

Docker Desktop 화면에서 엔진 실행이 완료될 때까지 기다린 뒤 연결을 확인한다.

```bash
docker info
```

서버 정보가 정상적으로 나오면 Cut-Off 백엔드 폴더에서 다시 실행한다.

```bash
cd /Users/lyugeonho/Documents/Cut-Off/back-end/v1
supabase start
supabase functions serve
```

Docker Desktop이 실행 중인데도 같은 오류가 나면 현재 Docker 연결 대상을 확인한다.

```bash
docker context show
docker context ls
```

목록에 `desktop-linux`가 있고 다른 대상이 선택되어 있다면 다음 명령으로 변경한 뒤 `docker info`를 다시 확인한다.

```bash
docker context use desktop-linux
```

Docker 엔진이 꺼진 상태에서는 `supabase start --debug`를 실행해도 해결되지 않는다. 먼저 `docker info`가 성공해야 한다.

## 4. AI 파이프라인 관리자 화면

```bash
cd /Users/lyugeonho/Documents/Cut-Off/AI-Pipeline/Frontend
npm run dev
```

브라우저에서 `http://localhost:3000`을 연다.

관리자 화면은 최소한 아래 환경 변수를 사용한다.

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
SUPABASE_SERVICE_ROLE_KEY=
ADMIN_SECRET=
```

동일 폴더에서 `npm run dev`를 두 번 실행하면 Next.js의 `.next` 산출물이 충돌할 수 있다. 이 저장소는 이를 막는 실행 가드를 포함하므로, 이미 실행 중인 서버를 사용하거나 먼저 종료한 뒤 재실행한다.

## 5. AI 수집 워커

아래 명령은 수집을 실제로 트리거하며, 연결된 Supabase의 `raw_videos`와 파이프라인 로그에 기록할 수 있다. 관리자 화면 확인만 필요하다면 실행하지 않는다.

```bash
cd /Users/lyugeonho/Documents/Cut-Off/AI-Pipeline/AI-pipeline
bash scripts/run-collect-local.sh
```

사전 준비 파일은 `AI-pipeline/.env.collect.local`이다. 최소한 Supabase URL·서비스 키, 워커 시크릿, 필요한 외부 AI/API 키가 있어야 한다.

## 권장 실행 순서

1. 로컬 데이터와 Edge Function까지 확인해야 하면 Supabase를 먼저 실행한다.
2. 웹 또는 RN 앱을 실행한다.
3. AI 관리 화면을 열 때는 관리자 환경 변수를 확인한다.
4. 실제 신규 영상 수집이 필요한 경우에만 수집 워커를 실행한다.
