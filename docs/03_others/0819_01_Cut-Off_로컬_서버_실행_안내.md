# Cut-Off 로컬 서버 실행 안내

대상 저장소: `/Users/lyugeonho/Documents/Cut-Off`

Cut-Off은 웹 프론트엔드, React Native 앱, Supabase 백엔드, AI 파이프라인 관리 화면과 워커가 분리되어 있다. 필요한 서버만 각각 별도 터미널에서 실행한다.

## 실행 전 공통 준비

각 Node.js 프로젝트에서는 처음 한 번만 의존성을 설치한다.

```bash
npm install
```

비밀값과 API 키는 저장소에 커밋하지 않는다. 프로젝트별 `.env`, `.env.local`, `.env.collect.local` 파일에만 넣는다.

## 3. 백엔드: 로컬 Supabase

현재 `back-end/v1`의 로컬 마이그레이션만으로는 새 로컬 DB를 완성할 수 없다. 아래 명령에서 `articles` 테이블 누락 오류가 나면 반복 실행하지 말고 이 절의 문제 해결 내용을 확인한다.

```bash
cd /Users/lyugeonho/Documents/Cut-Off/back-end/v1
supabase start
supabase functions serve
```

주요 로컬 주소:

| 서비스 | 주소 |
| --- | --- |
| Supabase API | `http://127.0.0.1:54321` |
| Supabase Studio | `http://127.0.0.1:54323` |

OAuth, 외부 API, Edge Function을 정상 실행하려면 백엔드 `.env`에 필요한 값이 있어야 한다.

`supabase db reset`은 로컬 DB를 초기화하므로, 데이터 보존이 필요한 경우 실행하지 않는다.

### 문제 해결: Docker API에 연결하지 못함

다음 오류는 Supabase 문제가 아니라 Docker Desktop이 실행되지 않았거나 Docker 엔진이 아직 준비되지 않았다는 뜻이다.

```text
failed to connect to the docker API ... connect: no such file or directory
```

Supabase 로컬 서비스는 Docker 컨테이너로 실행되므로 Docker Desktop을 먼저 시작한다.

```bash
open -a Docker
```

Docker Desktop 화면에서 엔진 실행이 완료될 때까지 기다린 뒤 연결을 확인한다.

```bash
docker info
```

서버 정보가 정상적으로 나오면 Cut-Off 백엔드 폴더에서 다시 실행한다.

```bash
cd /Users/lyugeonho/Documents/Cut-Off/back-end/v1
supabase start
supabase functions serve
```

Docker Desktop이 실행 중인데도 같은 오류가 나면 현재 Docker 연결 대상을 확인한다.

```bash
docker context show
docker context ls
```

목록에 `desktop-linux`가 있고 다른 대상이 선택되어 있다면 다음 명령으로 변경한 뒤 `docker info`를 다시 확인한다.

```bash
docker context use desktop-linux
```

Docker 엔진이 꺼진 상태에서는 `supabase start --debug`를 실행해도 해결되지 않는다. 먼저 `docker info`가 성공해야 한다.

### 현재 차단 이슈: `public.articles` 테이블 누락

다음 오류는 Docker 문제가 아니라 로컬 마이그레이션 구성이 완전하지 않아 발생한다.

```text
ERROR: relation "public.articles" does not exist (SQLSTATE 42P01)
```

확인된 구조는 다음과 같다.

- `back-end/v1/supabase/migrations`에는 서비스 API용 타임스탬프 마이그레이션 28개만 있다.
- `20240101000004_article_video_sync.sql`은 이미 `articles` 테이블이 있다고 가정하고 `ALTER TABLE public.articles`를 실행한다.
- `articles` 테이블은 `AI-Pipeline/AI-pipeline/supabase/migrations/001_initial_schema.sql`에서 생성된다.
- AI 파이프라인 쪽 통합 경로에는 숫자형 101개와 타임스탬프형 28개, 총 129개 마이그레이션이 있다.

따라서 `back-end/v1`에서 `supabase start`를 다시 실행해도 같은 위치에서 실패한다. `--debug`는 상세 로그만 늘리며 누락된 테이블을 만들지 않는다.

하지 말아야 할 조치:

- 오류가 난 `20240101000004_article_video_sync.sql`을 임의로 삭제하거나 이름을 바꾸지 않는다.
- 이미 적용된 원격 마이그레이션 내용을 직접 수정하지 않는다.
- `supabase migration repair --status reverted`를 실행하지 않는다.
- 원격 또는 보존이 필요한 DB에 `supabase db reset`을 실행하지 않는다.

필요한 영구 조치는 백엔드·AI 파이프라인 담당 범위다. 로컬 Supabase가 하나의 통합 마이그레이션 집합을 읽도록 `v1`의 마이그레이션 구성을 보완하거나, 통합 경로에서 백엔드 Edge Function까지 실행할 수 있도록 프로젝트 설정을 통일해야 한다.

이 조치가 반영되기 전에는 다음 중 하나를 선택한다.

1. 프론트엔드가 원격 개발 Supabase를 사용하도록 환경 변수를 설정한다.
2. 백엔드 담당자에게 로컬 통합 마이그레이션 구성을 요청한다.

현재 상태에서는 `back-end/v1`의 `supabase start` 성공을 전제로 다음 단계로 진행하지 않는다.

## 4. AI 파이프라인 관리자 화면

```bash
cd /Users/lyugeonho/Documents/Cut-Off/AI-Pipeline/Frontend
npm run dev
```

브라우저에서 `http://localhost:3000`을 연다.

관리자 화면은 최소한 아래 환경 변수를 사용한다.

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
SUPABASE_SERVICE_ROLE_KEY=
ADMIN_SECRET=
```

동일 폴더에서 `npm run dev`를 두 번 실행하면 Next.js의 `.next` 산출물이 충돌할 수 있다. 이 저장소는 이를 막는 실행 가드를 포함하므로, 이미 실행 중인 서버를 사용하거나 먼저 종료한 뒤 재실행한다.

## 권장 실행 순서

1. 로컬 데이터와 Edge Function까지 확인해야 하면 Supabase를 먼저 실행한다.
2. 웹 또는 RN 앱을 실행한다.
3. AI 관리 화면을 열 때는 관리자 환경 변수를 확인한다.
4. 실제 신규 영상 수집이 필요한 경우에만 수집 워커를 실행한다.
