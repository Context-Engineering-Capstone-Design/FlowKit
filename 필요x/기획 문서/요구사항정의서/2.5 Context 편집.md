## 2.5 Context 편집 요구사항

### REQ-022 · Context 편집 패널 열기/닫기

사용자는 우측 Context 편집 패널을 열거나 닫을 수 있어야 한다.

**입력**
Context 패널 버튼 또는 닫기 버튼 클릭

**결과**
패널 표시 상태 전환

**수용 기준**
버튼 클릭 시 우측 패널이 표시되거나 숨겨져야 한다.

**우선순위**
상

---

### REQ-023 · 선택된 블록 목록 확인

사용자는 우측 패널에서 선택한 블록 목록을 확인할 수 있어야 한다.

**입력**
메시지 블록 선택

**결과**
선택된 블록 목록 표시

**수용 기준**
선택된 각 블록은 역할 구분과 미리보기 텍스트 형태로 표시되어야 한다.

**우선순위**
상

---

### REQ-025 · 자연어 AI 편집 지시 입력

사용자는 선택된 블록을 어떻게 정리할지 자연어로 입력할 수 있어야 한다.

**입력**
편집 지시 입력창에 텍스트 입력

**결과**
지시문 입력

**수용 기준**
사용자가 입력한 지시문은 블록별 정제 실행 시 반영되어야 한다.

**우선순위**
상
> 2026-08-20 변경: 선택 블록 목록과 선택 블록 Context 편집은 폐기한다. Context는 메시지 내부 드래그 범위 태그로만 만들며, 정제 화면은 드래그 범위가 속한 단일 블록을 대상으로 연다.
> 2026-08-20 변경: REQ-024(빠른 편집 지시 선택)는 제거한다. 편집 지시는 자연어 입력(REQ-025)만 사용한다.

---

### REQ-072 · 전송된 Context 스니펫 대화 내 영구 표시

사용자는 드래그 범위 Context 태그를 붙여 보낸 메시지를 채팅 내역에서 다시 열어도, 그 메시지가 어떤 부분을 인용했는지 확인할 수 있어야 한다.

**입력**
드래그 범위 태그가 붙은 상태로 메시지 전송

**결과**
전송된 사용자 메시지 말풍선에 인용한 스니펫이 읽기 전용 태그로 함께 표시된다.

**수용 기준**
전송 직후는 물론, 대화를 새로고침하거나 다시 열어도 해당 사용자 메시지에 인용 스니펫 태그가 그대로 남아 있어야 한다.

**우선순위**
중
> 2026-08-21 추가: 기존에는 태그가 입력창에서만 보이다 전송 후 사라졌다(REQ-025 하단 변경 이력의 "드래그 범위 태그" 참고, 0820_13). 전송 뒤 다음 요청에 재사용되지 않도록 입력창 태그를 비우는 동작은 그대로 두되, 채팅 내역에는 별도로 영구 표시한다.
> 2026-08-21 변경: 전송 전 입력창 태그는 입력 상자 위가 아니라 질문 글 사이에 칩으로 표시한다. 전송 본문에는 넣지 않는다.
