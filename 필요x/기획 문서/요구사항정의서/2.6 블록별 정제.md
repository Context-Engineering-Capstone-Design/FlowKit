## 2.6 블록별 정제 요구사항

### REQ-028 · 선택 메시지 블록 개별 정제

사용자는 선택한 각 메시지 블록을 블록 단위로 AI 정제할 수 있어야 한다.

**입력**
메시지 블록 선택, 편집 지시 입력, 블록별 정제 실행

**결과**
블록별 정제 결과 목록 생성

**수용 기준**
선택된 N개 블록에 대해 N개의 정제 결과가 생성되어야 하며, 각 결과는 대응하는 원본 blockId를 가져야 한다.

**우선순위**
상

---

### REQ-029 · 블록별 원본/정제본 비교

사용자는 각 블록의 원본 내용과 정제 결과를 비교할 수 있어야 한다.

**입력**
블록별 정제 완료

**결과**
원본/정제본 비교 UI 표시

**수용 기준**
각 블록별로 원본 내용과 정제 결과가 함께 표시되어야 한다.

**우선순위**
상

---

### REQ-030 · 정제본 인라인 표시

사용자는 블록별 정제 결과를 원래 채팅 블록 위치에서 바로 확인할 수 있어야 한다.

**입력**
블록별 정제 완료

**결과**
채팅 블록 본문에 정제본 표시

**수용 기준**
정제 대상 메시지 블록의 본문 영역에 정제본이 표시되어야 한다.

**우선순위**
상

---

### REQ-031 · 원본/정제본 토글

사용자는 각 블록에서 원본과 정제본을 전환해 비교할 수 있어야 한다.

**입력**
정제 또는 원본 토글 클릭

**결과**
표시 내용 전환

**수용 기준**
`정제` 클릭 시 정제본, `원본` 클릭 시 기존 원본 내용이 표시되어야 한다.

**우선순위**
상

---

### REQ-032 · 블록별 정제 상태 관리

사용자는 각 정제 결과의 상태를 확인할 수 있어야 한다.

**입력**
정제 결과 생성

**결과**
상태 표시

**수용 기준**
각 정제 결과는 pending, approved, rejected 상태 중 하나를 표시해야 한다.

**우선순위**
상

---

### REQ-033 · 블록별 정제 결과 승인 및 즉시 적용

사용자는 승인 버튼 클릭 즉시 해당 블록의 정제본이 중앙 패널에 반영되어야 한다.

**입력**
승인 버튼 클릭

**결과**
정제본 즉시 원본 블록에 적용

**수용 기준**
pending 상태의 정제 결과만 승인 가능하며, 승인 클릭 시 별도 적용 버튼 없이 정제본이 새 버전으로 저장·활성화되어야 한다. 승인 후에는 정제 승인 취소 UI를 제공하지 않는다.

**우선순위**
상

---

### REQ-034 · 정제 승인 후 버전 복구 연계

정제 결과가 승인되면 해당 정제본은 메시지 블록의 새 버전으로 저장된다. MVP에서는 별도의 정제 승인 취소 UI를 제공하지 않는다.

**입력**
메시지 블록 버전 이동 또는 활성 버전 변경

**결과**
이전 버전 활성화

**수용 기준**
승인 이후 이전 내용으로 되돌리고 싶은 경우, 사용자는 메시지 블록 버전 목록 조회 및 활성 버전 변경(REQ-020, REQ-021)을 통해 이전 버전을 다시 활성화할 수 있어야 한다. 버전 이력은 삭제하지 않는다.

**우선순위**
하

---

### REQ-035 · 블록별 정제 결과 거절

사용자는 각 정제 결과를 원본에 반영하지 않도록 거절할 수 있어야 한다.

**입력**
거절 버튼 클릭

**결과**
거절 상태 반영

**수용 기준**
pending 상태의 정제 결과만 거절 가능하며, 거절된 정제 결과는 원본 블록의 현재 활성 버전을 변경하지 않아야 한다.

**우선순위**
상

---

### REQ-036 · 인라인 승인/거절

사용자는 각 블록의 인라인 툴바에서 pending 상태의 정제 결과를 바로 승인 또는 거절할 수 있어야 한다.

**입력**
인라인 승인/거절 클릭

**결과**
정제본 즉시 적용 또는 거절 상태 반영

**수용 기준**
인라인 승인 클릭 시 즉시 정제본이 적용되고, 인라인 버튼 상태와 우측 패널의 상태가 동기화되어야 한다. 승인 완료 후 인라인 승인/거절 버튼은 제거되며, 승인 버튼 재클릭으로 승인을 취소할 수 없다.

**우선순위**
상

---

### REQ-037 · 전체 승인

사용자는 pending 상태의 블록별 정제 결과를 한 번에 모두 승인 및 적용할 수 있어야 한다.

**입력**
전체 승인 버튼 클릭

**결과**
전체 블록 즉시 적용 및 카드 닫힘

**수용 기준**
pending 상태의 모든 정제 결과가 즉시 정제본으로 적용되고, 블록 항목이 순차 애니메이션으로 사라진 뒤 정제 카드 전체가 닫혀야 한다.

**우선순위**
중

---

### REQ-038 · 전체 거절

사용자는 pending 상태의 블록별 정제 결과를 한 번에 모두 거절할 수 있어야 한다.

**입력**
전체 거절 버튼 클릭

**결과**
전체 거절 상태 반영

**수용 기준**
pending 상태의 모든 정제 결과가 rejected로 변경되어야 하며, 메시지 블록의 현재 활성 버전은 변경하지 않아야 한다. 전체 거절 버튼은 pending 항목이 없을 경우 숨겨져야 한다.

**우선순위**
중

---

### REQ-039 · 승인된 항목 패널 애니메이션 제거

승인이 완료된 항목은 우측 패널에서 애니메이션과 함께 즉시 제거되어야 한다.

**입력**
승인 완료

**결과**
패널 내 해당 항목 슬라이드 아웃

**수용 기준**
승인된 블록이 오른쪽으로 밀리며 접혀 사라져야 하며, 마지막 항목 제거 후 정제 카드 전체가 페이드 아웃되어야 한다.

**우선순위**
상

---

### REQ-040 · 승인 후 인라인 툴바 제거

승인된 블록은 인라인 툴바(정제/원본 토글, 승인/거절 버튼)가 제거되어야 한다.

**입력**
승인 완료

**결과**
인라인 툴바 제거

**수용 기준**
승인된 블록의 본문 영역에서 정제 툴바가 사라지고 정제본만 표시되어야 한다.

**우선순위**
상

---

### REQ-041 · 원본 버전 이력 보존

정제본이 적용되더라도 기존 원본 내용은 삭제되지 않아야 한다.

**입력**
정제본 원본 적용

**결과**
기존 내용 버전 이력 저장

**수용 기준**
적용 전 원본 내용은 버전 이력에 보존되어야 한다.

**우선순위**
상

---

### REQ-042 · 정제본 새 버전 추가

승인된 정제본은 해당 블록의 새 버전으로 저장되어야 한다.

**입력**
승인본 적용

**결과**
새 버전 추가

**수용 기준**
정제본이 버전 목록에 추가되고 현재 버전으로 설정되어야 한다.

**우선순위**
상

---

### REQ-043 · 미승인 블록 원본 복원

미승인(대기·거절) 상태의 블록은 정제 프리뷰 세션이 종료되어도 원본 내용을 유지해야 한다.

**입력**
전체 승인 후 패널 닫힘 등

**결과**
미승인 블록 원본 복원

**수용 기준**
승인되지 않은 블록은 정제본이 아닌 원본 내용이 표시되어야 한다.

**우선순위**
상
