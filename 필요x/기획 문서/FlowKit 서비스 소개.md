아래 글은 팀원들에게 그대로 공유해도 되는 형태로 정리한 **서비스 기능 소개글**입니다.

# FlowKit 기능 소개: Block-based Context Editing & Branching Chatbot

## 1. 서비스 한 줄 소개

**FlowKit은 AI 챗봇의 이전 대화 맥락을 사용자가 직접 선택·편집·분기할 수 있게 해주는 Context 관리형 챗봇 서비스입니다.**

일반 챗봇은 이전 대화 전체를 자동으로 기억하고 다음 답변에 반영합니다. 하지만 사용자는 AI의 긴 답변을 모두 읽지 않았을 수도 있고, 일부 내용은 원하지 않았을 수도 있습니다. FlowKit은 이 문제를 해결하기 위해 대화를 **Block 단위**로 나누고, 사용자가 필요한 블록만 선택해 다음 대화의 Context로 사용할 수 있게 합니다.

---

## 2. 해결하려는 문제

기존 챗봇은 사용자가 질문하면 답변을 최대한 풍부하게 생성하는 경향이 있습니다. 예를 들어 사용자가 “파이프라이닝에서 구조적 해저드가 뭐야?”라고 물으면, AI는 구조적 해저드뿐 아니라 데이터 해저드, 제어 해저드, 캐시 구조, 해결 방식까지 길게 설명할 수 있습니다.

이때 문제가 생깁니다.

사용자는 전체 답변 중 일부만 읽었는데, 챗봇은 이전 답변 전체를 사용자가 이해했다고 가정합니다. 그 결과 읽지 않은 내용, 원하지 않은 내용, 불필요한 설명까지 이후 대화의 맥락에 포함됩니다.

FlowKit은 이 문제를 **Context 편집 기능**과 **선택형 브랜치 기능**으로 해결합니다.

---

## 3. 핵심 기능 요약

| 기능               | 설명                                            |
| ---------------- | --------------------------------------------- |
| 대화 Block 선택      | 사용자 질문과 AI 응답을 각각 블록으로 나누고 필요한 블록만 선택         |
| Context 편집 패널    | 선택한 블록을 우측 패널에서 확인하고 편집                       |
| AI 편집 지시         | “핵심만 요약”, “초보자용으로”, “표로 정리” 등 자연어로 Context 정제 |
| 정제된 Context 미리보기 | AI가 재구성한 Context를 다음 질문 전에 확인                 |
| Context 적용       | 정제된 Context만 기반으로 다음 질문 진행                    |
| 선택형 브랜치 생성       | 전체 대화가 아니라 선택한 Context만 기반으로 새 대화 흐름 생성       |
| 이전 대화 수정         | 기존 메시지 블록을 직접 수정하거나 수정본 기반 브랜치 생성             |
| 답변 재생성 및 버전 관리   | AI 응답을 다시 생성하고 버전처럼 비교 가능                     |

## 4. 주요 기능 상세 설명

## 4.1 대화 Block 선택 기능

FlowKit에서는 대화가 하나의 긴 로그가 아니라 여러 개의 **Message Block**으로 구성됩니다.

예시는 다음과 같습니다.

```text
[Block 1] 사용자 질문
[Block 2] AI 응답
[Block 3] 사용자 후속 질문
[Block 4] AI 후속 응답
```

각 블록에는 체크박스가 있으며, 사용자는 다음 대화에 반영하고 싶은 블록만 선택할 수 있습니다. 현재 UI 초안에서도 메시지 블록에 마우스를 올리면 체크박스가 나타나고, 선택된 블록은 Context 편집 패널에 추가되는 구조로 구현되어 있습니다. 

이 기능의 목적은 명확합니다.

> AI가 자동으로 모든 대화를 기억하는 것이 아니라, 사용자가 필요한 대화만 골라 기억하게 만드는 것

---

## 4.2 Context 편집 패널

오른쪽에는 **Context 편집 패널**이 있습니다.

이 패널은 사용자가 선택한 블록을 모아서 보여주고, 해당 블록을 AI에게 다시 정리시키는 공간입니다. 현재 UI 초안에는 선택된 블록 목록, AI 편집 지시 입력창, 정제된 Context 미리보기 영역이 포함되어 있습니다. 

주요 구성은 다음과 같습니다.

```text
선택된 블록
AI 편집 지시 입력창
정제된 Context 미리보기
Context 적용 버튼
브랜치 생성 버튼
```

즉, 단순히 대화를 보는 공간이 아니라 **다음 AI 응답에 들어갈 맥락을 가공하는 작업 공간**입니다.

---

## 4.3 AI 기반 Context 편집 기능

사용자는 선택한 블록에 대해 자연어로 편집 지시를 내릴 수 있습니다.

예를 들면 다음과 같습니다.

```text
핵심만 3줄로 요약해줘.
불필요한 내용은 제거해줘.
초보자도 이해할 수 있게 쉽게 바꿔줘.
시험 대비용으로 정리해줘.
표 형식으로 정리해줘.
발표 대본 스타일로 바꿔줘.
```

사용자는 위와 같은 지시를 AI 편집 지시 입력창에 직접 적어 블록을 정제합니다.

이 기능은 단순한 요약 기능이 아닙니다.

핵심은 다음과 같습니다.

> AI 답변 자체를 고치는 것이 아니라, 이후 대화에 반영될 Context를 AI와 함께 재구성하는 기능

---

## 4.4 정제된 Context 미리보기

AI가 선택된 블록을 정리하면, 사용자는 바로 다음 질문으로 넘어가지 않고 먼저 **정제된 Context Preview**를 확인할 수 있습니다.

예를 들어 기존 AI 응답이 길었다면, 사용자는 다음처럼 정제된 형태를 확인합니다.

```text
구조적 해저드는 여러 명령어가 동시에 같은 하드웨어 자원을 사용하려 할 때 발생한다.
대표적으로 IF 단계와 MEM 단계가 같은 메모리에 접근할 때 충돌이 생긴다.
이를 해결하기 위해 I-Cache와 D-Cache를 분리한다.
```

이 미리보기 기능이 중요한 이유는, 사용자가 **AI가 다음 질문에서 무엇을 기억할지** 확인할 수 있기 때문입니다.

---

## 4.5 Context 적용 기능

정제된 Context가 마음에 들면 사용자는 **“이 Context로 질문하기”** 버튼을 누릅니다.

그러면 입력창 위에 현재 적용 중인 Context가 표시됩니다. 현재 UI 초안에서도 사용자가 Context를 적용하면 `선택된 블록 Context`, `시험 대비 Context`, `초보자용 Context`, `핵심 요약 Context`, `표 정리 Context` 같은 이름으로 입력창 위에 표시되도록 설계되어 있습니다. 

이 상태에서 사용자가 다음 질문을 하면, AI는 이전 대화 전체가 아니라 **선택·편집된 Context 중심으로 답변**합니다.

---

## 4.6 선택형 브랜치 생성 기능

FlowKit의 브랜치 기능은 일반적인 대화 분기와 다릅니다.

일반 브랜치는 특정 시점까지의 대화 전체를 가져와서 새 흐름을 만듭니다. 하지만 FlowKit은 사용자가 선택한 블록 또는 정제된 Context만 기반으로 새 브랜치를 만들 수 있습니다.

예를 들어 메인 대화에서 다음 블록만 선택할 수 있습니다.

```text
[AI] 파이프라이닝 전체 개요
[AI] 구조적 해저드 상세
[AI] 데이터 해저드 상세
```

그리고 이 세 개만 기반으로 “구조적 해저드 중심 브랜치”를 생성합니다. 실제 UI 초안에서도 브랜치 생성 시 선택된 Context 블록을 기반으로 요약 블록을 만들고, 브랜치 목적과 포함된 Context를 표시하는 구조가 포함되어 있습니다. 

이 기능의 핵심은 다음입니다.

> 시간순 대화 분기가 아니라, 의미 있는 Context 기준으로 대화를 분기한다.

---

## 4.7 이전 대화 수정 기능

FlowKit은 이전 메시지 블록을 수정할 수 있습니다.

사용자는 AI 응답이 너무 길거나 방향이 맞지 않을 때 해당 블록을 수정 모드로 바꿔 직접 고칠 수 있습니다. 현재 UI 초안에는 블록 수정 시 텍스트 영역이 열리고, 사용자가 수정한 뒤 저장하거나 수정본 기반으로 브랜치를 만들 수 있는 구조가 포함되어 있습니다. 

적용 방식은 다음과 같습니다.

```text
현재 블록 수정
수정본 저장
수정본 기반 브랜치 생성
원본 대화 보존
```

이 기능은 대화 흐름이 잘못되었을 때 전체 대화를 새로 시작하지 않고, 특정 지점만 고쳐서 이어갈 수 있게 해줍니다.

---

## 4.8 답변 재생성 및 버전 관리

FlowKit은 AI 응답을 재생성하고, 이전 버전과 새 버전을 관리할 수 있습니다.

현재 UI 초안에는 특정 블록을 다시 생성하면 새로운 응답 버전이 추가되고, 사용자가 버전 이동 UI를 통해 이전/다음 버전을 확인할 수 있는 구조가 포함되어 있습니다. 

이 기능은 다음 상황에서 유용합니다.

```text
AI 답변이 너무 길 때
다른 관점의 답변이 필요할 때
이전 답변과 새 답변을 비교하고 싶을 때
가장 적절한 답변만 Context로 남기고 싶을 때
```

---

## 4.9 좌측 사이드바: 대화·브랜치 관리

좌측 사이드바는 전체 작업 공간을 관리하는 영역입니다.

현재 UI 초안에서는 서비스명 `FlowKit`, 새 채팅 버튼, 검색창, 최근 대화 목록, 현재 대화의 브랜치 목록이 포함되어 있습니다. 

사이드바의 역할은 다음과 같습니다.

```text
최근 대화 확인
새 채팅 생성
대화 검색
브랜치 전환
현재 작업 흐름 파악
```

Google AI Studio처럼 실험형 대화 작업을 여러 갈래로 관리할 수 있게 하는 구조입니다.

---

## 5. 예시 사용 흐름

사용자는 다음과 같이 FlowKit을 사용할 수 있습니다.

```text
1. 사용자가 질문한다.
   “파이프라이닝에서 구조적 해저드가 뭐야?”

2. AI가 긴 답변을 생성한다.

3. 사용자는 필요한 AI 응답 블록만 선택한다.

4. 우측 Context 편집 패널에서 지시한다.
   “구조적 해저드 부분만 남기고, 초보자용으로 쉽게 정리해줘.”

5. AI가 정제된 Context를 생성한다.

6. 사용자는 미리보기를 확인한다.

7. “이 Context로 질문하기”를 누른다.

8. 이후 질문은 선택·정제된 Context만 기반으로 이어진다.

9. 필요하면 이 Context를 기반으로 새 브랜치를 만든다.
```

## 6. 우리 서비스의 차별점

FlowKit의 차별점은 단순한 챗봇 기능이 아니라 **Context 제어 기능**에 있습니다.

| 구분       | 일반 챗봇        | FlowKit          |
| -------- | ------------ | ---------------- |
| 이전 대화 처리 | 전체 대화를 자동 반영 | 사용자가 필요한 블록만 선택  |
| 긴 응답 처리  | 그대로 누적       | AI로 요약·삭제·재작성    |
| 대화 분기    | 특정 시점 기준 분기  | 선택 Context 기준 분기 |
| 사용자 제어권  | 낮음           | 높음               |
| 핵심 가치    | 답변 생성        | 맥락 관리와 대화 흐름 제어  |

FlowKit은 “AI가 무엇을 답할지”뿐만 아니라, **AI가 무엇을 기억하고 무엇을 잊어야 하는지**를 사용자가 관리할 수 있게 하는 서비스입니다.

## 7. 팀원별로 이해해야 할 포인트

### 기획 담당

이 서비스의 핵심 문제는 **읽지 않은 AI 응답이 이후 Context에 반영되는 문제**입니다. 기능 기획은 “대화 편집”이 아니라 “Context 편집”이라는 관점에서 잡아야 합니다.

### UI/UX 담당

핵심 화면은 3단 구조입니다.

```text
좌측: 대화/브랜치 목록
중앙: 메시지 블록 기반 채팅
우측: Context 편집 패널
```

사용자가 복잡한 기능을 어렵게 느끼지 않도록, 블록 선택과 자연어 편집 지시 중심으로 설계해야 합니다.

### 프론트엔드 담당

우선 구현할 핵심 인터랙션은 다음입니다.

```text
메시지 블록 선택
선택 블록 우측 패널 반영
AI 편집 지시 입력
정제 Context 미리보기 표시
Context 적용 상태 표시
브랜치 생성 및 좌측 목록 반영
블록 수정 및 버전 관리
```

### 백엔드/AI 담당

핵심은 대화 전체를 그대로 모델에 넣는 것이 아니라, 사용자가 선택한 블록과 정제된 Context만 모델 입력으로 구성하는 것입니다.

즉, 모델 호출 전 단계에서 다음 구조가 필요합니다.

```text
선택된 Message Block
→ AI 편집 지시
→ 정제된 Context
→ 최종 프롬프트 구성
→ 모델 응답 생성
```

## 8. MVP에서 우선 구현할 기능

캡스톤 프로젝트 기준으로는 아래 기능을 우선 구현하면 됩니다.

```text
1. 기본 채팅 화면
2. 메시지 Block 선택 기능
3. 우측 Context 편집 패널
4. AI 편집 지시 입력
5. 정제된 Context 미리보기
6. Context 적용 상태 표시
7. 선택 Context 기반 브랜치 생성
8. 이전 메시지 수정 기능
```

고급 기능인 브랜치 비교, 협업 기능, 외부 문서 연동, 그래프형 시각화는 후순위로 두어도 됩니다.

## 9. 발표용 핵심 문장

> FlowKit은 AI 챗봇이 이전 대화 전체를 무조건 기억하는 문제를 해결하기 위해, 사용자가 필요한 대화 블록만 선택하고 AI로 정제하여 다음 대화의 Context로 사용할 수 있게 하는 서비스입니다.

> 기존 챗봇이 답변 생성에 집중했다면, FlowKit은 대화의 맥락을 사용자가 직접 관리할 수 있게 하는 Context Editing Interface입니다.

> FlowKit의 브랜치는 단순히 특정 시점에서 대화를 다시 시작하는 기능이 아니라, 사용자가 선택한 Context만 기반으로 새로운 대화 흐름을 만드는 선택형 브랜치 기능입니다.
