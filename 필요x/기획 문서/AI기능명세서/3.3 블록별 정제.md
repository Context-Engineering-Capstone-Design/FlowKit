## 3.3 블록별 정제

**FE/BE/AI 책임 기준:** 정제 대상 블록과 기준 버전을 고르는 것은 BE-REFINE-001이, 결과 저장과 승인·거절은 BE-REFINE-003 이후가 맡는다. AI 모델링 파트는 넘겨받은 블록 본문을 편집 지시대로 다시 쓴 결과만 돌려준다.

### AI-REFINE-001 · 편집 지시 확인

정제를 시작하기 전에 편집 지시가 쓸 수 있는 값인지 본다.

**도메인**
BlockRefine

**관련 요구사항**
REQ-025, REQ-028

**관련 BE 기능**
BE-CTXEDIT-002, BE-REFINE-002

**관련 화면**
AI 편집 지시 입력창, 블록별로 정제하기 버튼

**입력**
`instructionText`

**처리**
지시가 비어 있거나 공백뿐이면 모델을 부르지 않고 바로 오류를 낸다. 앞뒤 공백을 없앤 값을 이후 단계에서 쓴다.

**출력**
정리된 편집 지시

**DB 영향**
없음

**상태 변화**
없음

**권한**
없음

**오류**
지시문 없음

**우선순위**
상

**비고**
길이 제한과 금지 문자열 검사는 BE-CTXEDIT-002 책임이다. 여기서는 빈값만 막는다.

---

### AI-REFINE-002 · 블록별 개별 정제 실행

선택된 블록을 하나씩 따로 모델에 보내 정제한다.

**도메인**
BlockRefine

**관련 요구사항**
REQ-028

**관련 BE 기능**
BE-REFINE-002

**관련 화면**
블록별로 정제하기 버튼

**입력**
`apiKey`, `refineTargets(blockId, role, content)`, `instructionText`, `selectedModelId` 선택값

**처리**
대상이 없으면 모델을 부르지 않고 빈 목록을 돌려준다. 대상이 있으면 블록마다 편집 지시와 블록 본문 하나씩을 담은 요청을 만들어 동시에 호출한다. 여러 블록을 한 요청에 묶지 않는다.

**출력**
`aiRefineResults(blockId, refinedContent)`

**DB 영향**
없음

**상태 변화**
없음

**권한**
없음

**오류**
지시문 없음, 모델 호출 실패, 응답 시간 초과

**우선순위**
상

**비고**
여러 블록을 한 번에 보내고 결과를 나눠 받으면 응답에서 블록 경계를 다시 갈라야 한다. 이때 순서가 밀리거나 하나가 빠지면 엉뚱한 블록에 다른 내용이 반영되고, 사용자는 A 블록을 승인했는데 B 내용이 들어가도 알아채기 어렵다. 블록마다 따로 부르면 이 문제가 생기지 않는다. 호출 수는 늘지만 동시에 처리하므로 체감 속도 차이는 크지 않다.

### AI-REFINE-003 · 정제 프롬프트 기준

정제 결과가 원문에 없는 내용을 만들어내지 않도록 지시 문안을 정한다.

**도메인**
BlockRefine

**관련 요구사항**
REQ-028, REQ-029

**관련 BE 기능**
BE-REFINE-002

**관련 화면**
정제 결과 패널, 인라인 정제본 표시

**입력**
`instructionText`, 블록 역할, 블록 본문

**처리**
시스템 지시에 다음을 담는다. 원문에 없는 사실을 새로 넣지 말고 정리·요약·재구성만 할 것, 지시가 요약이면 짧게·표로 정리하라면 표로·쉽게 바꾸라면 쉬운 말로 쓸 것, 원문의 언어를 유지할 것, 머리말이나 설명 없이 결과 본문만 낼 것, 원문이 이미 지시를 만족하면 거의 그대로 두어도 될 것. 사용자에게 보내는 부분에는 편집 지시와 원문을 역할 표시와 함께 나눠 넣는다.

**출력**
모델에 넣을 메시지

**DB 영향**
없음

**상태 변화**
없음

**권한**
없음

**오류**
없음

**우선순위**
상

**비고**
역할 표시는 `user`를 "사용자 질문", `assistant`를 "AI 답변"으로 바꿔 넣는다. 원문이 질문인지 답변인지에 따라 정리 방식이 달라지기 때문이다.

---

### AI-REFINE-004 · 정제 결과와 원본 블록 대응 보장

정제 결과가 요청한 블록과 정확히 짝지어 돌아가게 한다.

**도메인**
BlockRefine

**관련 요구사항**
REQ-028, NFR-016

**관련 BE 기능**
BE-REFINE-002, BE-REFINE-003

**관련 화면**
인라인 정제본 표시, 원본/정제본 토글

**입력**
`refineTargets`, 모델 응답 목록

**처리**
요청한 대상과 돌아온 결과를 순서대로 짝지어 각 결과에 원본 `blockId`를 붙인다. 개수가 다르면 오류를 낸다. 결과 본문의 앞뒤 공백을 없앤다.

**출력**
`aiRefineResults(blockId, refinedContent)`

**DB 영향**
없음

**상태 변화**
없음

**권한**
없음

**오류**
결과 개수 불일치, 결과 본문 없음

**우선순위**
상

**비고**
백엔드도 BE-REFINE-003에서 요청한 블록과 결과가 일대일로 맞는지 다시 확인한다. 양쪽에서 검사해 잘못된 내용이 원본에 반영되는 일을 막는다.
> 2026-08-20 변경: 드래그 범위가 속한 단일 블록만 정제 대상으로 모델에 전달한다. 드래그 범위 자체가 정제 범위를 자르지는 않는다.
