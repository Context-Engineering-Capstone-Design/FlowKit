---

### 2. 신규 서비스 방향: FlowKit

05월 07일에는 새로운 서비스 시안 및 제안서를 공유하였다. 신규 서비스인 **FlowKit**은 기존 챗봇의 대화 맥락 관리 문제를 해결하는 서비스이다.

기존 챗봇은 사용자의 질문에 대해 풍부한 답변을 생성하지만, 사용자가 답변 전체를 읽거나 이해하지 않았더라도 이후 대화에서는 이전 응답 전체를 맥락으로 사용한다. 이로 인해 사용자가 원하지 않거나 읽지 않은 정보까지 대화 흐름에 포함되는 문제가 발생한다.

FlowKit은 이를 해결하기 위해 사용자가 필요한 Context만 선택하고, 수정하며, 해당 Context를 기반으로 새로운 대화 흐름을 만들 수 있도록 한다.

---

### 3. 핵심 기능

FlowKit의 핵심 기능은 다음과 같다.

1. **블록 단위 Context 선택**
    - 사용자 질문과 AI 응답을 각각 블록 단위로 나눈다.
    - 사용자는 필요한 블록만 선택할 수 있다.
2. **Context 편집 및 정제**
    - 선택한 블록은 우측 패널에서 편집할 수 있다.
    - “핵심만 요약” 등 자연어 명령을 통해 AI를 활용한 Context 정제가 가능하다.
3. **선택형 Branch 기능**
    - 전체 대화가 아니라 선택한 Context 블록을 기반으로 새로운 대화 흐름을 생성할 수 있다.
    - 이를 통해 불필요한 정보가 이후 대화에 포함되는 것을 줄일 수 있다.

### 4. UI 시안 및 서비스 구현 방향 논의

05월 07일 공유된 UI 시안에 대해 팀원들이 의견을 나누었다. 전체적인 UI 완성도는 긍정적으로 평가되었다. 다만 상위 문서에서 참조한 Context를 하위 문서에서 어떻게 접근할지에 대한 추가 논의가 필요하다. 이때 Context를 복사해서 사용할지, 원본을 참조하는 방식으로 구현할지 결정해야 한다.

또한 프로젝트의 성격상 인공지능 모델 자체의 기술적 고도화는 어렵다는 우려가 있다. 하지만, 모델 쪽의 고도화에 집중하기보다는 

모델 성능 개선, 벤치마크 데이터셋 구축, 실험 설계보다는 **Context를 다루는 UX와 서비스 구조 설계**, 서비스 구현, 사용자 편의성 개선에 집중하기로 하였다. (제출 및 통과에 의의를 두기로 하였다.)

### 7. 설계 문서 정리

1학기 동안 작성할 주요 설계 문서에 대해 다음과 같이 정의한다.

- **요구사항정의서**: 유저 관점에서 제공되어야 하는 서비스 요구사항을 표 형태로 정리한 문서
- **기능 명세서**: 요구사항을 구현하기 위해 각 파트가 기술적으로 어떤 기능을 개발해야 하는지 정리한 문서
- **세부 설계서**: 기능 명세서보다 더 구체적인 구조와 형태를 다루는 문서
    
    예: 컴포넌트 구상도, DB 설계서, API 명세서, 모델 아키텍처 설계도 등
    

교수님과의 대면 면담을 통해 위 문서들을 지속적으로 보완하고, 방학 전까지 확정하는 것을 목표로 한다.

### 8. 교수님 피드백 반영 및 AS-IS / TO-BE 정리

04월 01일 교수님 피드백을 반영하여 서비스의 AS-IS와 TO-BE를 명확히 정리하였다.

- **AS-IS**: AI가 작성한 응답을 수정 없이 그대로 대화 맥락에 포함해야 함
- **TO-BE**: 사용자 또는 AI가 응답을 수정·정제할 수 있고, 특정 Context를 기반으로 Branch할 수 있음

이를 통해 FlowKit은 단순히 챗봇 답변을 생성하는 서비스가 아니라, 사용자가 대화 맥락을 직접 관리하고 필요한 흐름만 선택적으로 확장할 수 있는 서비스로 방향성을 정리하였다.
