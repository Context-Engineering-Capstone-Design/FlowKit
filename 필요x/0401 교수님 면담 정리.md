# 0401 교수님 면담 QNA 정리

## Q1. AS-IS / TO-BE는 어떻게 정리했는가?

A. **AS-IS**: 기존 챗봇에서는 AI가 작성한 이전 응답이 수정 없이 그대로 이후 대화의 Context에 포함됩니다. 그 결과 읽지 않은 내용, 원하지 않은 내용이 이후 대화의 맥락에 포함됩니다.

**TO-BE**: FlowKit에서는 사용자가 AI 응답 중 필요한 Context를 직접 선택하고, 직접 또는 AI를 활용해 수정·정제한 뒤, 특정 Context를 기반으로 새로운 Branch를 생성할 수 있도록 합니다.

## Q2. FlowKit은 Context를 보여 주고 관리하는 서비스인가, 잘못된 Context를 자동 교정하는 서비스인가?

A. 저희는 FlowKit을 모델이 생성한 잘못된 Context를 자동으로 교정하는 연구 중심 서비스보다는, 사용자가 대화 중 필요한 Context를 직접 선택하고 관리할 수 있는 서비스로 정의했습니다. 즉, 인간 개입이 적극적으로 이루어지는 Context 관리 UX에 초점을 두고자 합니다.

## Q3. 정제된 Context의 성능을 수치적으로 증명하는 것이 핵심인가, 서비스적 측면이 핵심인가?

A. 벤치마크 데이터셋 구축이나 모델 성능 비교 실험을 핵심 목표로 두기보다는, Context 선택·편집·Branch 기능을 통해 사용자가 대화 흐름을 더 명확하게 제어할 수 있도록 하는 서비스적 측면에 집중하기로 했습니다.

## Q4. Context Engineering 관련 연구와 평가는 어떻게 반영할 예정인가?

A. 별도의 벤치마크 실험 설계를 프로젝트의 중심으로 두지는 않지만, Context Engineering 관련 논문과 평가 metric은 조사하여 서비스 설계의 참고 근거로 활용할 예정입니다. 해당 조사는 창현 님이 담당하기로 했습니다.

**TOBE** : "우리가 원하는 서비스는 무엇인가?", "어떻게 개선되어야 하는가?"
